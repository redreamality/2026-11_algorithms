第 12 课 · 堆与优先队列

堆是一棵“父亲总比孩子小”的二叉树，所以最小值永远在顶上。它其实就存在一个普通数组里。

开始前要会：Python —— // 与 %（算父亲孩子的下标）、魔法方法（__len__、__bool__）、lambda 与 key=、解包、异常约定（IndexError）、生成器（merge 是生成器）；前面的课 —— 第 10 课 · 二叉树、第 8 课 · 归并排序（merge 的思路）

实战里怎么写：标准库 heapq

业务代码里没人手写堆，Python 标准库 heapq 直接把普通 list 当堆用。按场景选：

场景用什么代价
任务调度、“谁最急谁先做”heapq.heappush / heappop，存 (优先级, 序号, 任务)push / pop O(log n)，看堆顶 O(1)

一层一层从左往右排满（完全二叉树），所以不需要指针，下标就能算出亲戚：

父亲   (i - 1) // 2
左孩子 2*i + 1
右孩子 2*i + 2

注意：堆只管父子，不管兄弟。上面的 3 和 2 谁在左都行，所以堆不是排好序的数组。

push：放到末尾，往上浮

def _sift_up(heap, index):
    while index > 0:
        parent = (index - 1) // 2
        if heap[index] >= heap[parent]:     # 不比父亲小，停
            return
        heap[index], heap[parent] = heap[parent], heap[index]
        index = parent

heap.append(item)

pop：拿走堆顶，末尾补上来，往下沉

def pop(heap):
    if not heap:
        raise IndexError("pop from an empty priority queue")
    last = heap.pop()
    if not heap:                  # 刚才那个就是唯一的元素
        return last
    top = heap[0]
    heap[0] = last                # 末尾的挪到堆顶
    _sift_down(heap, 0)           # 和较小的孩子比，比它大就交换，一路往下
    return top

树高是 log n，上浮下沉最多走一条从根到叶的路，所以都是 O(log n)。

复杂度

操作时间
peek 看最小值O(1)
push / popO(log n)
heapify 把乱序数组变成堆O(n)
堆排序O(n log n)

heapify 为什么是 O(n)：从最后一个有孩子的节点 n//2 - 1 往前，逐个下沉。一半节点是叶子，根本不动；越靠下的节点越多，但要沉的距离越短，加起来不到 2n。

堆排序：先 heapify，再 pop n 次，拿出来的就是从小到大。教科书上的原地版本用最大堆，每次把堆顶换到数组末尾。

优先队列就是“谁最小谁先出”的队列，堆是它最常见的实现。Python 里是 heapq，第 16 课的 Dijkstra 就靠它。

动手玩

建议依次试试：push 一个 0，看它一路浮到顶；点 pop，看末尾的数怎么沉下去；点 heapify 乱序数组 看建堆；最后点 堆排序。

最容易错的地方

  • 下沉时要和较小的孩子换，换成较大的那个，堆就坏了。
  • 节点可能只有左孩子：先检查右孩子下标有没有越界。
  • 只剩一个元素时 pop：别把它先挪到堆顶再删掉。
  • 空堆 pop 或 peek 抛 IndexError。

自测

1. 下标 5 的父亲和孩子是谁？ 父亲 (5-1)//2 = 2，孩子 11 和 12。
2. 一个个 push 建堆是 O(n log n)，heapify 为什么更快？ push 是上浮，越靠下的节点越多、浮得越远；heapify 是下沉，多数节点在底层，几乎不用动。
3. 想找最大的 k 个数，用最小堆还是最大堆？ 最小堆，大小保持 k：新数比堆顶大就替换堆顶。堆顶就是“目前第 k 大”，总共 O(n log k)。
