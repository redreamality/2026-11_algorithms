第 43 课 · 区间 DP

区间 DP 的表格里，每一格代表一段连续的区间。大区间的答案由它里面的小区间拼出来，所以按区间长度从短到长填表。

开始前要会：Python —— 推导式（二维表）、itertools.accumulate、math.inf、functools.cache、f-string；前面的课 —— 第 19 课 · DP（一）记忆化、第 27 课 · 前缀和（O(1) 求区间总和）、第 37 课 · 一维 DP（四步法）、第 38 课 · 二维 DP（最长回文子串按长度填表）。

第 38 课的最长回文子串已经见过一次“区间”类的表：is_palindrome[i][j] 看的是子串 text[i..j]，而且必须按长度从短到长填。这一课把这种写法单独拿出来讲透。笔试第 3 题常考它，因为它的遍历顺序和前面的 DP 都不一样，写错一点就全错。

先定义几个词

  • 区间 i..j：数组里下标从 i 到 j 的这一段，两端都含，要求 i ≤ j。
  • 区间长度：length = j - i + 1。长度为 1 的区间只有一个元素（i == j）。
  • 分割点 k：把区间 i..j 切成左右两块 i..k 和 k+1..j，k 可以取 i 到 j - 1。长度为 L 的区间一共有 L - 1 个分割点。
  • 区间 DP：状态 dp[i][j] 定义成“区间 i..j 的最优结果”，转移时只用到比它短的区间。表只用到对角线（i == j）和它右上方的一半，左下方 i > j 的格子没有意义。

区间 DP 的四步法（第 37 课）里，前三步因题而异，第 4 步几乎总是同一个写法：

for length in range(2, n + 1):          # 区间长度从短到长（长度 1 是初始值）
    for i in range(n - length + 1):     # 左端点
        j = i + length - 1              # 右端点
        dp[i][j] = 用更短的区间算出来

为什么不能像网格题那样一行行从上往下填？因为 dp[i][j] 要用 dp[k + 1][j]，它在下面的行，从上往下填时还没算。按长度填就没有这个问题：所有更短的区间在上一轮外层循环里都已经填好了。

实战里怎么写：functools.cache 写 best(i, j)

业务里碰到“只能动相邻的东西”的最优化，基本都是区间 DP：

场景区间代表什么最后一步
合并相邻的日志分段 / 视频切片，每次合并要重写合出来的整块第 i 段到第 j 段左边一块和右边一块合并
矩阵连乘 A×B×C×D 怎么加括号乘法最少（numpy 的 numpy.linalg.multi_dot 内部就这么算）第 i 个到第 j 个矩阵左边的乘积乘右边的乘积
最少插入几个字符，把字符串补成回文子串 text[i..j]两端配对，或者在一端补一个字符

真实代码里不写表格，而是把“区间 i..j 的最优值”直接写成递归函数，让 functools.cache（第 19 课）记住算过的区间。区间只有 n² 个，n 到几百都很快：

from functools import cache
from itertools import accumulate

def min_rewrite_cost(segment_sizes):            # 合并相邻分段，最少重写多少 MB
    prefix_total = list(accumulate(segment_sizes, initial=0))

    @cache
    def rewrite_cost(i, j):                     # 把第 i..j 段合成一个文件的最少代价
        if i == j:
            return 0
        range_total = prefix_total[j + 1] - prefix_total[i]
        return min(rewrite_cost(i, k) + rewrite_cost(k + 1, j) for k in range(i, j)) + range_total

    return rewrite_cost(0, len(segment_sizes) - 1)

min_rewrite_cost([300, 400, 200, 400])    # 2600

题 1：石子合并（本课主线）

题意：一排 n 堆石子，piles[i] 是第 i 堆的石子数。每次只能把相邻的两堆合成一堆，这一次的代价是新堆的石子数。合到只剩一堆，最少总代价是多少？

例子：piles = [3, 4, 2, 4]。

3424← 先合 3 + 4（代价 7），再合 2 + 4（代价 6）
76← 最后合 7 + 6（代价 13）。总代价 7 + 6 + 13 = 26，这是最少的

贪心为什么不对：直觉是“每次合最小的相邻两堆”。这里相邻两堆的和是 7、6、6，贪心先合 4 + 2 = 6，剩下 [3, 6, 4]；再合 3 + 6 = 9，剩下 [9, 4]；最后 13。总代价 6 + 9 + 13 = 28，比 26 多。问题在于：4 + 2 合出来的 6 后来又被合了两次，它的石子被重复计了很多遍。眼前最便宜的一步，不一定让后面也便宜。

暴力做法为什么慢：把每种合并顺序都试一遍。第一步有 n - 1 对相邻的可以选，第二步有 n - 2 对……一共 (n - 1)! 种顺序，n = 20 时已经超过 1017。

关键观察：不管前面怎么合，最后一次合并一定是把“左边一块”和“右边一块”合在一起。左边那块是由第 0 堆到第 k 堆合成的，右边是第 k + 1 堆到第 n - 1 堆，k 就是分割点。

  • 左右两块在最后一步之前互不影响：左边怎么合，跟右边无关。所以左边应该用“把 0..k 合成一堆”的最优方案，右边同理。
  • 最后一次合并的代价是两块的石子数之和，也就是整个区间的石子总数，跟 k 选哪个无关。
  • “把 0..k 合成一堆”和原题是同一类问题，只是区间更短。于是问题变成：对每个区间 i..j，求合成一堆的最少代价。

套四步法：

  1. 状态：merge_cost[i][j] = 把第 i 堆到第 j 堆（两端都含）合成一堆的最少代价。
  2. 转移：枚举分割点 k（i ≤ k < j）， 
    merge_cost[i][j] = min(merge_cost[i][k] + merge_cost[k + 1][j] for k in range(i, j)) + range_total(i, j)
    其中 range_total(i, j) 是第 i 堆到第 j 堆的石子总数，用前缀和 O(1) 求出：prefix_total[j + 1] - prefix_total[i]（第 27 课）。
  3. 初始值：merge_cost[i][i] = 0，一堆不用合。
  4. 遍历顺序：按区间长度从 2 到 n。答案在右上角 merge_cost[0][n - 1]。
from itertools import accumulate

def merge_stones_min_cost(piles):
    n = len(piles)
    if n <= 1:
        return 0
    prefix_total = list(accumulate(piles, initial=0))
    merge_cost = [[0] * n for _ in range(n)]            # 长度 1 的区间是 0，正好是初始值
    for length in range(2, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            range_total = prefix_total[j + 1] - prefix_total[i]
            merge_cost[i][j] = min(merge_cost[i][k] + merge_cost[k + 1][j] for k in range(i, j)) + range_total
    return merge_cost[0][n - 1]

merge_stones_min_cost([3, 4, 2, 4])    # 26

为什么对：任何一种合并方案都有最后一步，最后一步一定对应某个分割点 k；对每个 k，左右两块用的都是各自的最优方案（换成更差的只会更贵）。把所有 k 都比较一遍，最优方案不会被漏掉。

复杂度：区间有 n(n + 1) / 2 个，每个区间枚举不超过 n 个分割点，所以 O(n³) 时间、O(n²) 空间。n = 200 时约 130 万次，Python 一秒内跑完；n 到 1000 就要换思路了（笔试里这类题的 n 一般给到几百）。

要方案不只要代价：填表时顺手记下每个区间最好的分割点 best_split[i][j]，最后从 0..n-1 开始按分割点递归拆开，就得到 ((3, 4), (2, 4))。骨架里的选做题 merge_plan 就是这个。

题 2：最长回文子序列（LeetCode 516）

题意：从字符串 text 里按原来的顺序挑出一些字符（可以不连续，这叫子序列，第 20 课讲过），组成一个回文串（正着读和反着读一样）。最长能有多长？

例子：text = "bbbab"，挑出第 0、1、2、4 个字符 "bbbb"，返回 4。"cbbd" 返回 2（"bb"）。

和第 38 课的最长回文子串比：子串必须连续，所以两端不相同时整段直接不是回文；子序列可以跳过字符，两端不相同时还可以扔掉一端继续找。

暴力做法为什么慢：长度为 n 的串有 2n 个子序列，每个再花 O(n) 判断是不是回文。

关键观察：只看区间 text[i..j] 的两个端点：

  • 两端相同（text[i] == text[j]）：把它们配成一对，放在回文的最外层，里面放 text[i+1..j-1] 的最长回文子序列。长度 + 2。
  • 两端不同：它们不可能同时出现在答案的最外层，所以至少有一端用不上。扔掉左端，问题变成 text[i+1..j]；扔掉右端，变成 text[i..j-1]。取大的。

这次的转移不是枚举分割点，而是去掉一端或两端。用到的区间仍然比 i..j 短，所以照样按长度填。

套四步法：

  1. 状态：longest[i][j] = text[i..j] 里最长回文子序列的长度。
  2. 转移：两端相同时 longest[i][j] = longest[i + 1][j - 1] + 2；不同时 longest[i][j] = max(longest[i + 1][j], longest[i][j - 1])。
  3. 初始值：longest[i][i] = 1，单个字符本身就是回文。长度为 2 且两端相同时，中间是空串，longest[i + 1][j - 1] 落在 i > j 的那一半里，那一半填 0 就正好对。
  4. 遍历顺序：按区间长度从 2 到 n。答案在 longest[0][n - 1]。
def longest_palindromic_subsequence(text):
    n = len(text)
    if n == 0:
        return 0
    longest = [[0] * n for _ in range(n)]          # i > j 的格子保持 0，代表空串
    for i in range(n):
        longest[i][i] = 1
    for length in range(2, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            if text[i] == text[j]:
                longest[i][j] = longest[i + 1][j - 1] + 2
            else:
                longest[i][j] = max(longest[i + 1][j], longest[i][j - 1])
    return longest[0][n - 1]

longest_palindromic_subsequence("bbbab")    # 4

为什么对：设最优的回文子序列是 P。如果 text[i] 和 text[j] 都在 P 里，它们一定分别是 P 的第一个和最后一个字符，所以必须相同，这是第一种情况；否则至少一端不在 P 里，P 完全落在 i+1..j 或 i..j-1 里，第二种情况取了两者的最大值。

复杂度：O(n²) 时间和空间，每格 O(1)。

用上它：最少插入几次变成回文（LeetCode 1312）。最长回文子序列里的字符不用动，其余每个字符都要在对称的位置补一个，所以答案是 len(text) - longest_palindromic_subsequence(text)。"mbadm" 的最长回文子序列是 "mam"（长度 3），答案 5 - 3 = 2。

选做：戳气球（LeetCode 312）

题意：一排气球上写着数字。戳破一个气球能得到“左邻 × 自己 × 右邻”枚硬币，左邻、右邻指的是还没戳破的相邻气球，越界时当成 1。全部戳完，最多拿多少？[3, 1, 5, 8] 的答案是 167。

难点：如果枚举“第一个戳哪个”，戳完以后左右两边的气球变成了邻居，两边不再独立，拆不成两个小区间。

反过来想：在两端各补一个 1，枚举区间里最后一个被戳破的气球 last。它最后才戳，所以在它之前，左右两边各自被戳光，互不影响；它被戳的那一刻，左右邻正好是区间两端外面的那两个气球。这样又变回了“分割点”的形状，和石子合并一样按长度填。骨架里有完整的提示（max_coins_bursting_balloons）。

区间 DP 的一个通用技巧就在这里：想不通“第一步”时，换成想“最后一步”。最后一步把区间分成互不影响的两半，才能用上更短区间的结果。

怎么认出这类题

  • 题目里有“相邻的才能合并 / 相乘 / 消除”，问最少代价或最大收益：枚举分割点的区间 DP。
  • 输入是一个字符串，问“回文”“两端”：去掉一端或两端的区间 DP。
  • 数据范围 n ≤ 几百（O(n³) 能过），或者 n ≤ 几千（O(n²) 能过）。
  • 想按“第一步做什么”递归时发现两边会互相影响：试试“最后一步做什么”。

LeetCode 1000 · 合并石头的最低成本

题意：n 堆石头排成一排，第 i 堆有 stones[i] 块。每次操作把恰好 k 堆相邻的石头合并成一堆，成本是这 k 堆的石头总数。返回把所有石头合并成一堆的最低成本；做不到就返回 -1。（k = 2 时就是 正文题 1。）

例子：输入 stones = [3, 2, 4, 1]，k = 2，输出 20。先合并 [3, 2] 成本 5，得到 [5, 4, 1]；再合并 [4, 1] 成本 5，得到 [5, 5]；最后合并成本 10，共 20。另外，stones = [3, 2, 4, 1]、k = 3 时输出 -1：合并一次剩 2 堆，就再也凑不出 3 堆。

数据范围：n ≤ 30，2 ≤ k ≤ 30，stones[i] ≤ 100。

LeetCode 1312 · 让字符串成为回文串的最少插入次数

题意：给定字符串 s，每次操作可以在任意位置插入任意一个字符。返回让 s 成为回文串的最少操作次数。

例子：输入 s = "zzazz"，输出 0，它本身就是回文串。输入 s = "mbadm"，输出 2，可以变成 "mbdadbm" 或 "mdbabdm"。

数据范围：n ≤ 500，s 只含小写字母。

LeetCode 312 · 戳气球

题意：n 个气球，第 i 个上写着 nums[i]；戳破气球 i 得到 nums[i - 1] × nums[i] × nums[i + 1] 枚硬币（左右邻指还没戳破的相邻气球，越界当成 1），返回戳破所有气球能得到的最多硬币数，n ≤ 300。完整讲解见 正文「选做：戳气球」。

LeetCode 1039 · 多边形三角剖分的最低得分

题意：一个凸 n 边形，values[i] 是按顺时针顺序第 i 个顶点的值。把它剖分成 n − 2 个三角形（三角形的顶点都是多边形的顶点），每个三角形的值是三个顶点值的乘积，剖分的得分是所有三角形的值之和。返回所有剖分方式中的最低得分。

例子：输入 values = [3, 7, 4, 5]，输出 144。四边形只有两种剖分：沿对角线 7–5 切，得分 3 × 7 × 5 + 4 × 5 × 7 = 245；沿对角线 3–4 切，得分 3 × 7 × 4 + 3 × 4 × 5 = 144。

数据范围：3 ≤ n ≤ 50，values[i] ≤ 100。

LeetCode 375 · 猜数字大小 II

题意：对方从 1 到 n 中选一个数，你来猜。每猜错一次数 x，就要付 x 元，并被告知要猜的数比 x 大还是小；钱付不起就输了。返回无论对方选哪个数都能保证赢所需的最少现金。

例子：输入 n = 10，输出 16（最优策略先猜 7，最坏情况下总共付 16 元）。小一点的例子：n = 1 输出 0；n = 2 输出 1：先猜 1，猜错付 1 元，就知道答案是 2。

数据范围：n ≤ 200。

最容易错的地方

  • 按行从上往下填：dp[k + 1][j] 在下面的行，还没算。外层必须是区间长度。
  • 分割点范围写错：k 从 i 到 j - 1，右半块是 k + 1..j。写成 range(i, j + 1) 会出现空的右半块。
  • 区间总和每次重新求和：sum(piles[i:j + 1]) 又是 O(n)，总复杂度变成 O(n⁴)。用前缀和。
  • 最长回文子序列长度为 2 时：longest[i + 1][j - 1] 是 i > j 的格子，要保证它是 0，不要填成别的初始值。
  • 空列表、只有一个元素时直接返回，别让 merge_cost[0][n - 1] 越界。

自测

1. 石子合并里，为什么最后一次合并的代价和分割点 k 无关？ 最后一次合并把左右两块合成整个区间，新堆的石子数就是整个区间 i..j 的石子总数。不管从哪里切开，总数都一样。所以转移里 range_total 放在 min 外面。
2. 区间 DP 为什么外层循环区间长度，而不是外层循环 i？ dp[i][j] 用到的是更短的区间，例如 dp[k + 1][j]，它的左端点 k + 1 比 i 大，在表里更靠下。外层按 i 从小到大时，这些格子还没算。按长度从短到长时，所有更短的区间都在之前的轮次里填好了。（另一种等价写法是 i 从 n - 1 倒着循环到 0、j 从 i + 1 往右循环。）
3. 最长回文子序列两端不相同时，为什么不用再看 longest[i + 1][j - 1]？ 因为 longest[i + 1][j] 和 longest[i][j - 1] 都包含了区间 i+1..j-1，它们一定 ≥ longest[i + 1][j - 1]。“两端都扔掉”的情况已经被“扔掉一端”覆盖了。
