第 11 课 · 二叉搜索树

二叉搜索树（BST）只多一条规则：左边都比我小，右边都比我大。于是每比一次就能扔掉一半，像在树上做二分查找。

问题直觉 核心定义与不变量 通用操作模板 题目与动画 应用场景 易错点与练习

开始前要会：Python —— 继承 MutableMapping（白送的方法）、sortedcontainers、异常约定（KeyError）、生成器（yield）、setdefault、@classmethod；前面的课 —— 第 10 课 · 二叉树、第 6 课 · 二分查找（bisect）、第 5 课 · 递归（删除用递归写）

问题直觉：怎样在动态数据里保持有序

数组适合二分查找，却不适合频繁插入；哈希表适合查找，却不提供顺序。BST 把“查找路径”和“有序结构”放进同一棵树，关键是每个子树都继续满足同一条规则。

核心定义与不变量：左小右大

长什么样

5

1479

规则对每个节点都成立，管的是整棵子树，不只是直接的孩子：8 在 5 的右边，所以 8 的左子树里也不能出现 4（虽然 4 < 8，但它比 5 小）。中序遍历（左 → 根 → 右）的结果正好从小到大：1 3 4 5 7 8 9。

通用操作模板：查找、插入、删除

查找和插入：小往左，大往右

手写版做成一个和 dict 用法一样的 TreeMap：每个节点存 key 和 value，按 key 排。tree[key] 的实现就是从根往下走：

def __getitem__(self, key):
    node = self.root
    while node is not None:
        if key == node.key:
            return node.value
        node = node.left if key < node.key else node.right
    raise KeyError(key)          # 和 dict 一样，找不到就抛 KeyError

prices = TreeMap({1999: "鼠标", 4599: "键盘"})
prices[4599]                     # '键盘'
4599 in prices                   # True：MutableMapping 用 __getitem__ 自动实现了 in

tree[key] = value 是同一条路：碰到相同的 key 就只改值；一直走到 None，新节点就挂在那个空位上。最小键一路往左走到底，最大键一路往右。走的步数不超过树高 h，所以都是 O(h)。

floor（不超过 x 的最大键）也是一条路走到底：当前键 ≤ x，它就是一个候选，记下来再往右找更大的；否则往左。区间查询则是带剪枝的中序遍历：当前键已经 ≤ 下界，左子树就不用进了。这两个操作是哈希表做不到的。

删除：分三种情况

要删的节点怎么办
没有孩子直接删，父亲那边改成 None
一个孩子让孩子顶上来，接替它的位置
两个孩子找后继（右子树里最小的值），把值复制过来，再删掉后继原来的节点

为什么用后继？它比左边所有值都大、比右边其余值都小，放在这个位置规则不会被破坏。后继没有左孩子，所以删它只会落到前两种情况。

复杂度：全看树高

操作树比较平衡（h ≈ log n）退化成链表（h = n）
查找 / 插入 / 删除O(log n)O(n)
中序输出全部O(n)O(n)

按 1、2、3…… 的顺序插入，每个值都只能挂在最右边，树就变成一条链。红黑树、AVL 这类平衡树会在插入删除时自动调整，保证 h = O(log n)（选修课再讲）。

应用场景：有序索引与区间查询

业务代码里几乎没人手写 BST。Python 没有内置的有序字典（dict 只记插入顺序，不按大小排），实际按场景二选一：

场景用什么代价
数据基本不变，只查询排好序的 list + 标准库 bisect（第 6 课）查 O(log n)，插入要挪元素 O(n)
边查边改第三方库 sortedcontainers 的 SortedDict / SortedList增删查都约 O(log n)
from bisect import bisect_right
from sortedcontainers import SortedDict

# 配置变更历史（按时间排好序）：某一时刻生效的是哪个版本？= 找“<= 该时刻的最后一条”
times = [changed_at for changed_at, _ in history]
index = bisect_right(times, moment) - 1
version = history[index][1] if index >= 0 else None

# 商品按价格建索引，随时上下架，按价格区间筛选
by_price = SortedDict()                 # 价格（分） -> 商品名
by_price[1999] = "鼠标"
by_price[4599] = "键盘"
del by_price[1999]
list(by_price.irange(2000, 9000))       # 区间里的价格，只走范围内的部分
by_price.peekitem(0)                    # 最便宜的 (价格, 商品)

题目与动画

建议依次试试：值设成 2 点 insert 看它走哪条路；把值设成 1、8、5 分别点 remove，看三种删除情况（5 有两个孩子，注意后继 6 怎么上去）；最后点 有序插入 1～7，看树怎么退化成链表。

易错点与练习

  • 删的是根，而且根只有一个孩子：要改的是 self.root，不是哪个父亲的指针。
  • 两个孩子的情况，复制完后继的值，忘了删掉后继原来的节点，树里就出现两个一样的值。
  • 键已存在时 tree[key] = value 只改值，size 不能加一；删一个不存在的键要抛 KeyError，size 不能减一。
  • 两个孩子的情况，键和值都要从后继搬过来，只搬键会让 tree[6] 拿到 5 的值。

练习

补全 dsa/bst.py 里的 TreeMap。它继承 collections.abc.MutableMapping：你只写 __setitem__、__getitem__、__delitem__、__iter__，get、pop、in、items()、== 这些都是 Python 自动送的，写完就能像 dict 一样直接用。

建议顺序：__setitem__ → __iter__（用 yield 写中序）→ __getitem__ → min_key / max_key → floor_key / ceiling_key → items_between → height → __delitem__。__delitem__ 用递归写最省事：“在这棵子树里删掉 key，返回删完后的新子树根”。

自测

1. 怎么用 BST 给一组数排序？要多久？ 全部插入，再中序遍历。平均 O(n log n)；要是输入本来就有序，树退化成链表，变成 O(n²)。
2. 两个孩子的情况，能用前驱（左子树里最大的值）代替后继吗？ 可以。前驱比左边其余值都大、比右边所有值都小，一样不破坏规则。两种都对，本课测试约定用后继。
3. 已经有哈希表 O(1) 查找了，为什么还要 BST？ BST 里的值是有序的：最小值、最大值、按顺序输出、找“比 x 大的最小值”、取一段区间都很方便，哈希表做不到。所以 Python 里要“边改边保持有序”，用的是 SortedDict 而不是 dict。
