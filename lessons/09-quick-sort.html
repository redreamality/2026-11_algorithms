第 9 课 · 快速排序

挑一个基准，比它小的放左边，比它大的放右边，基准就站到了最终位置。再对左右两边各做一遍。

实战里怎么写：排序、中位数、前 k 名都有现成的

Python 的 sorted() 是 Timsort，不是快排。快排的“分区”思想解决的那些问题，标准库都备好了：

场景用什么代价
排序sorted() / list.sort()O(n log n)，稳定
中位数、P95 延迟statistics.median / statistics.quantiles内部会排序，O(n log n)
前 k 名（k 远小于 n）heapq.nlargest(k, ...) / nsmallestO(n log k)

完整可运行的版本在 examples/quick_sort_in_practice.py（uv run examples/quick_sort_in_practice.py）。下面看快排和 quickselect 本身。

核心是“分区”（partition）

像体育课排队：老师指定一个同学当基准，矮的站他左边，高的站他右边。站完之后，他的位置就定了，不用再动。

213 4 9865 ← 左边都 < 4，右边都 ≥ 4

左右两边内部还是乱的，没关系，递归下去分别排就行。和归并排序反过来：归并是“先递归，再合并”，快排是“先分区，再递归”，最后什么都不用合并。

Lomuto 分区：两个指针

def partition(items, low, high):
    pivot = items[high]                  # 拿最后一个当基准
    boundary = low                       # items[low..boundary-1] 是“小于区”
    for scan in range(low, high):        # scan 从左往右扫
        if items[scan] < pivot:
            items[boundary], items[scan] = items[scan], items[boundary]   # 小的换进小于区
            boundary += 1
    items[boundary], items[high] = items[high], items[boundary]          # 基准放到小于区后面
    return boundary

记住 boundary 的含义：它左边全是比基准小的。scan 每遇到一个小的，就把它换到 boundary 的位置，boundary 往右挪一格。（下面的动画里 boundary 标作 i，scan 标作 j。）

复杂度：看基准选得好不好

快速排序归并排序（上一课）
平均O(n log n)O(n log n)
最坏O(n²)O(n log n)
额外空间O(log n)，原地，只用递归栈O(n)
稳定否是

基准每次都把数组分成差不多的两半，就是 log n 层，和归并一样。可如果总拿最后一个当基准，而数组已经有序，每次只分出“n-1 个 + 0 个”，就退化成 O(n²)。办法很简单：随机挑一个和 a[hi] 交换再分区，坏情况几乎碰不到（例外：大量相同元素时 Lomuto 仍会退化，这里不展开）。

动手玩

先点 partition 一步步看 i、j 怎么走（橙色是正在比的，蓝色是“小于区”，红框是基准）。再点 quick_sort 看整个递归过程，绿色是已经站到最终位置的。试试输入 1 2 3 4 5 6，数一数比较次数有多少。

最容易错的三个地方

  • 区间是 items[low..high] 两端都包含。递归时是 (low, pivot_index - 1) 和 (pivot_index + 1, high)，基准不要再带进去，否则可能死循环。
  • 递归出口是 low >= high（0 或 1 个元素），不是 low == high：基准在边上时会出现 low > high。
  • 不稳定：交换会把相等的元素“跳着”换过去，相对顺序就乱了。需要稳定就用 sorted()。
  • 带 key 时对 (key, 原下标) 排序：原下标各不相同，比较永远不会落到元素本身（元素可能根本不能比大小）。

练习

补全 dsa/quick_sort.py。建议顺序：partition → quick_sort（记得随机基准；再加上和 list.sort 一样的 key=、reverse=）→ select（第 k 小：分区后只往一边走，不改输入，用来算中位数和 P95）。

uv run pytest tests/test_quick_sort.py

自测

1. 为什么快排不需要合并这一步？ 分区之后，左边所有元素都小于右边所有元素。两边各自排好，整个数组自然就有序了。
2. quickselect（练习里的 select）为什么平均是 O(n) 而不是 O(n log n)？ 每次分区后只往一边走，处理的长度大约是 n、n/2、n/4……加起来约 2n。快排要两边都走，所以每层都是 n。
3. 快排最坏 O(n²)，为什么实际中还常用它？ 随机基准让最坏情况几乎不出现；它原地排序，不用 O(n) 额外空间，访问内存也连续，常数很小。
