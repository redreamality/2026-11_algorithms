第 22 课 · 选修 · Trie（字典树）

Trie 把单词一个字母一个节点地挂在树上，开头相同的词共用同一段路。查一个词只要顺着字母往下走，走几步只看词有多长，和存了多少词无关。

开始前要会：Python —— setdefault 与 get、魔法方法（__contains__ / __len__ / __iter__ / __delitem__ / __repr__）、生成器、Iterable / Iterator 标注与引号前向引用；前面的课 —— 第 4 课 · 哈希表（每个节点的孩子就是一个 dict）、第 10 课 · 二叉树（顺着引用往下走）、第 13 课 · DFS（深度优先遍历子树，递归 + yield）、第 6 课 · bisect（实战里的对比方案）、第 12 课 · 堆（complete 的提示用 heapq.nsmallest）。

先定义 核心结构 操作模板 应用场景 看动画 练习与自测

先定义：节点、结束标记和前缀

Trie 的状态是“当前走到哪个节点”。每条边代表一个字符；节点的 count 表示有多少个单词在这里结束，因此“走得到”只说明它是前缀，不能直接说明它是完整单词。

实战里怎么写：多数时候用不着 Trie

Python 标准库里没有 Trie。实际项目里按场景选：

场景用什么代价
判断字符串是不是某几个前缀开头str.startswith（可以传 tuple）O(前缀总长)
词表不大，列出某前缀下所有词排好序的 list + bisectO(log n + 结果数)；插入新词 O(n)
按热度补全collections.Counter + 排序O(n)，每次都要扫一遍
词表大、补全请求多、边改边查手写 Trie（本课）O(L + 子树大小)，但每个节点一个 dict，占内存
from bisect import bisect_left

def words_with_prefix(sorted_words, prefix):
    """以 prefix 开头的词在排好序的列表里是连续的一段。"""
    start = bisect_left(sorted_words, prefix)
    result = []
    for word in sorted_words[start:]:
        if not word.startswith(prefix):
            break
        result.append(word)
    return result

path.startswith(("/admin", "/internal"))       # 一次查多个前缀
words_with_prefix(sorted(commands), "co")      # ['commit', 'config']

完整可运行的版本在 examples/trie_in_practice.py（uv run examples/trie_in_practice.py）。Trie 的优势是：查前缀只看前缀多长，和词表多大无关，而且天然按字母序组织好了。

核心结构：共享前缀的树

存了 car、cat、dog 三个词（绿 = 有单词在这里结束）：

        (根)
       /    \
      c      d
      |      |
      a      o
     / \     |
    r✓  t✓   g✓
class TrieNode:
    def __init__(self):
        self.children = {}    # 字符 → 下一个节点
        self.count = 0        # 有几次单词在这里结束；0 表示不是单词结尾

car 和 cat 共用 c → a。结束标记很关键：走得到 ca，不代表 ca 是一个词。这里用 count（被搜索了几次）代替 True / False，自动补全时正好拿它排热度。

操作模板：先走到节点，再做不同事情

def _walk(self, text):
    """沿着 text 的字母往下走，走不通返回 None。"""
    node = self.root
    for character in text:
        node = node.children.get(character)
        if node is None:
            return None
    return node

def add(self, word, times=1):
    node = self.root
    for character in word:
        node = node.children.setdefault(character, TrieNode())   # 没路就新建
    if node.count == 0:
        self._size += 1                                           # 第一次出现的新词
    node.count += times

def __contains__(self, word):                                     # word in trie
    node = self._walk(word)
    return node is not None and node.count > 0

（setdefault(character, TrieNode()) 是预备课讲过的写法：键已经在就原样返回对应的值，不在就先把新节点存进去、再返回它，一行完成“有路就走、没路就建”。）

列出某前缀下的所有词：先 _walk(prefix) 走到前缀节点，再用生成器深度优先走它的子树，孩子按字母顺序走，产出的词自然是字典序。

复杂度（L = 单词长度）

操作Trie对比：set 存所有词
插入 / 查整词O(L)O(L)（算哈希也要读完整个词）
有没有以 p 开头的词O(L)O(n·L)，只能一个个比
列出所有以 p 开头的词O(L + 子树大小)O(n·L)

一句话：和前缀有关的问题（自动补全、拼写提示、敏感词过滤）就想 Trie。代价是每个节点一个 dict，比较占内存。

应用场景：把 Trie 和简单方案比较

上面的实战表格放在这里回看：词表小或只做偶尔查询时，startswith、排序列表加 bisect 更直接；词表大、补全请求多且需要边改边查时，Trie 才值得承担额外内存。

动手玩

建议依次试试：插入 cart，看它只新建了一个节点；用 前缀列词 查 ca，看先沿高亮的路走到前缀，再把下面的子树走一遍；最后 search 一下 ca，看为什么它是 False。

最容易错的三个地方

  • 前缀不等于单词：in 走完之后一定要看 count > 0。
  • 一个词是另一个词的前缀（ca 和 car）：两个节点都可能是结束点，结束点不一定是叶子。
  • 列词时，前缀节点自己可能就是一个词，别漏了它。

练习

补全 dsa/trie.py，做出一个搜索框自动补全：word in trie、len(trie)、for word in trie、del trie[word] 都要能用，另外有 starts_with（生成器）和按热度排序的 complete。

建议顺序：add → __contains__ / count / has_prefix（共用一个“沿前缀走到底”的小函数）→ starts_with（走到前缀节点后递归 yield，孩子按字母排序）→ complete → __delitem__（要把不再通向任何单词的节点剪掉）。

自测

1. 存了 100 万个词，查 “apple” 要走几步？ 5 步，一个字母一步。和存了多少个词无关。
2. 为什么不能只靠“走到底没断路”判断单词存在？ 存了 car 之后，ca 也走得到，可它只是前缀。要看最后那个节点的 count 是否大于 0（动画里叫 search，就是本课的 in）。
3. del trie[word] 只把 count 改成 0，会有什么问题？ in 没问题，但不再通向任何单词的节点还挂在树上：浪费内存，has_prefix 也会误报（删掉唯一的 car 后，has_prefix("ca") 仍是 True）。要修就从下往上，把“没孩子也不是结束点”的节点剪掉。
