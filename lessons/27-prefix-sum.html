第 27 课 · 前缀和与哈希计数

前缀和 = 提前算好“从开头到每个位置的累计和”，之后任意一段的和都只要做一次减法。再配上哈希表记录“见过哪些前缀和、各几次”，就能在一次遍历里数出和为 k 的子数组有多少个。

开始前要会：Python —— itertools.accumulate、dict 的 get、Counter、% 对负数的行为、类与 __init__、类型标注；前面的课 —— 第 4 课 · 哈希表（dict 查找 O(1) 的原因）、第 6 课 · 二分查找（实战里的 bisect_right）、第 26 课 · 滑动窗口（它什么时候失效，本课多次对比）。

实战里怎么写：先看真实代码里的前缀和

前缀和就是“累计值”，业务里很常见：累计销售额、账户余额曲线、报表里的区间合计、按比例分流。标准库已经备好了工具：

场景用什么代价
算累计值（余额曲线、累计销量）itertools.accumulate(values)O(n)
反复查“第 a 天到第 b 天的总和”accumulate(values, initial=0) 算好前缀和，每次查一次减法预处理 O(n)，每次查询 O(1)
按权重随机抽样（抽奖、灰度发布按比例分流）random.choices(items, weights=...)（按权重挑一个，权重越大越容易被挑中）；自己写就是权重前缀和 + bisect每抽一次 O(log n)
统计每个值出现几次collections.Counter（就是本课的“哈希计数”）O(n)
from bisect import bisect_right
from itertools import accumulate

class SalesReport:
    def __init__(self, daily_sales: list[int]) -> None:
        self._prefix_sum = list(accumulate(daily_sales, initial=0))   # 开头补一个 0

    def total(self, first_day: int, last_day: int) -> int:
        return self._prefix_sum[last_day + 1] - self._prefix_sum[first_day]

class WeightedPicker:
    """灰度发布：权重 [90, 10] 表示 90% 流量走旧版、10% 走新版。"""
    def __init__(self, choices: list[str], weights: list[int]) -> None:
        self._choices = choices
        self._cumulative_weights = list(accumulate(weights))       # [90, 100]

    def pick(self, rng) -> str:
        ticket = rng.random() * self._cumulative_weights[-1]       # [0, 100) 里随机一个点
        return self._choices[bisect_right(self._cumulative_weights, ticket)]   # 落在哪一段

完整可运行的版本在 examples/prefix_sum_in_practice.py（uv run examples/prefix_sum_in_practice.py）。两个小注：accumulate 预备课讲过（见预备课），这里的 initial=0 表示累加前先放一个初始值 0，正好补出前缀和开头那个 0；WeightedPicker.pick 里的 rng.random() 返回一个 [0, 1) 之间的小数，乘以总权重就相当于“在 [0, 总权重) 里随机取一个点”。下面的练习里不许用 accumulate，要自己写循环累加，把“为什么多一格”“为什么一次减法就够”想清楚。

前缀和数组

给数组 numbers，定义一个比它多一格的数组 prefix_sum：

  • prefix_sum[0] = 0，表示一个数都不取时的和。
  • prefix_sum[i] = numbers[0] + numbers[1] + ... + numbers[i - 1]，也就是前 i 个数的和。
  • 递推着算：prefix_sum[i + 1] = prefix_sum[i] + numbers[i]，一遍 O(n) 就算完。
下标0123456 numbers-203-52-1 prefix_sum0-2-21-4-2-3

想求下标 left 到 right（两端都包含）这一段的和，就是“前 right + 1 个数的和”减去“前 left 个数的和”，中间这一段正好剩下来：

numbers[left] + ... + numbers[right] = prefix_sum[right + 1] - prefix_sum[left]

上图中，下标 2 到 5（蓝色）的和 = prefix_sum[6] - prefix_sum[2] = -3 - (-2) = -1。验算：3 - 5 + 2 - 1 = -1。

为什么要多一格：如果 prefix_sum[i] 定义成“包含 numbers[i] 在内的和”，求从下标 0 开始的段时就要写 prefix_sum[right] - prefix_sum[-1]，下标 -1 不存在，只能特判。多放一个 0 在最前面，所有区间都用同一个公式，不用特判。

前缀和配哈希表：把“找一段”变成“找一个数”

有了前缀和，“某一段的和等于 k”就可以改写成“两个前缀和的差等于 k”：

prefix_sum[right + 1] - prefix_sum[left] == k
等价于  prefix_sum[left] == prefix_sum[right + 1] - k

这样一来，当我们从左往右走到某个位置、算出当前的前缀和时，问题就变成：前面出现过的前缀和里，有几个等于“当前前缀和 - k”？ 这是一个“查找某个值出现过几次”的问题，用 dict 记录每个值出现的次数，查一次是 O(1)。这个思路和经典的“两数之和”完全一样，所以本课也一起讲两数之和。

怎么认出这类题

  • 要反复求某一段（连续区间）的和，或者说“多次查询”。→ 先算前缀和，每次查询 O(1)。
  • 要数和恰好等于 k 的连续子数组有几个，尤其是数组里有负数或 0（这时滑动窗口不能用）。→ 前缀和 + 哈希计数。
  • 条件可以改写成“两段前缀和的某种关系”：差等于 k、差能被 k 整除（余数相同）、0 和 1 个数相等（把 0 看成 -1，就变成和为 0）。→ 前缀和 + 哈希表。
  • 在无序数组里找两个数满足某个和或差。→ 哈希表记录见过的数（两数之和模板）。
  • 二维矩阵里反复求子矩形的和。→ 二维前缀和，道理相同。

第 1 题：区域和检索（前缀和）

题意：给一个数组 numbers，之后会有很多次查询，每次给出 left 和 right，要返回 numbers[left] 到 numbers[right]（两端都包含）的和。数组本身不会被修改。

例子：numbers = [-2, 0, 3, -5, 2, -1]。sum_range(0, 2) 返回 -2 + 0 + 3 = 1；sum_range(2, 5) 返回 3 - 5 + 2 - 1 = -1。

暴力做法为什么慢：每次查询都从 left 加到 right，一次 O(n)。如果有 q 次查询，总共 O(q · n)。查询次数很多时，同样的加法被重复做了无数遍。

关键观察：数组不变，所以“前 i 个数的和”也不会变，可以在构造时一次性算好。之后每次查询都是两个前缀和相减。

class RangeSumQuery:
    def __init__(self, numbers):
        self.prefix_sum = [0]
        for number in numbers:
            self.prefix_sum.append(self.prefix_sum[-1] + number)

    def sum_range(self, left, right):
        return self.prefix_sum[right + 1] - self.prefix_sum[left]

为什么是对的：prefix_sum[right + 1] 是 numbers[0] 到 numbers[right] 的和，prefix_sum[left] 是 numbers[0] 到 numbers[left - 1] 的和。前者减后者，开头那一段 numbers[0..left - 1] 正好抵消，剩下的就是 numbers[left..right]。

复杂度：构造 O(n)，每次查询 O(1)，额外空间 O(n)。这是典型的“用空间换时间”：多存一个数组，换来每次查询从 O(n) 变成 O(1)。

第 2 题：两数之和（哈希表）

题意：数组 numbers 没有排序，找两个不同位置的数，使它们的和等于 target，返回两个下标。题目保证恰好有一个答案。

例子：numbers = [2, 7, 11, 15]，target = 9，返回 [0, 1]。numbers = [3, 3]，target = 6，返回 [0, 1]（同一个值出现两次，可以用两次，但不能把同一个位置用两次）。

暴力做法为什么慢：两层循环试所有的对，O(n²)。上一课的对撞指针要求有序，先排序会把下标打乱，还得另外记原下标，也不是最直接的办法。

关键观察：走到下标 i 时，我们想知道的其实只有一件事：“target - numbers[i] 这个数，前面出现过没有？出现在哪？”这是一个查找问题，用 dict 就是 O(1)。

index_by_value = {}                      # 已经看过的数 → 它的下标
for i, number in enumerate(numbers):
    partner = target - number
    if partner in index_by_value:        # 先查
        return [index_by_value[partner], i]
    index_by_value[number] = i           # 再记

为什么“先查后记”：如果先把 numbers[i] 记进去再查，当 number 正好是 target 的一半时（例如 target = 6，number = 3），会查到它自己，把同一个位置用了两次。先查后记，dict 里只有 i 之前的数，就不会和自己配对。

为什么是对的：设答案是下标 a < b。走到 b 时，a 已经被记进 dict，target - numbers[b] 正好是 numbers[a]，一定能查到。

复杂度：一遍循环，每次查和记都是 O(1)，时间 O(n)；dict 最多存 n 个数，空间 O(n)。

第 3 题：和为 K 的子数组（前缀和 + 哈希计数）

题意：给数组 numbers（可以有负数和 0）和整数 k，数一数有多少个连续子数组的和恰好等于 k。

例子：numbers = [1, 1, 1]，k = 2，答案是 2：下标 0～1 的 [1, 1] 和下标 1～2 的 [1, 1]，内容一样但位置不同，算两个。numbers = [1, 2, 3]，k = 3，答案是 2：[1, 2] 和 [3]。

暴力做法为什么慢：枚举起点和终点，用前缀和 O(1) 算每一段的和，也还有 O(n²) 段要看。

为什么不能用上一课的滑动窗口：数组里可能有负数。窗口里的和已经等于 k 了，再往右加一个负数，和变小，可能后面又凑回 k。“和太大就收缩、太小就扩张”的判断失效了。

关键观察：前面推过，“以当前位置结尾、和为 k 的子数组”的个数，就等于“前面出现过的前缀和里，值为 prefix_sum - k 的个数”。每个这样的前缀和对应一个起点：从那个位置之后开始，一直到当前位置，这一段的和就是 k。所以把两数之和里的“记下标”换成“记次数”就行了：

count_by_prefix_sum = {0: 1}             # 空前缀：和为 0，出现 1 次
prefix_sum = 0
subarray_count = 0
for number in numbers:
    prefix_sum += number
    subarray_count += count_by_prefix_sum.get(prefix_sum - k, 0)   # 先查
    count_by_prefix_sum[prefix_sum] = count_by_prefix_sum.get(prefix_sum, 0) + 1   # 再记
return subarray_count

用 numbers = [1, 2, 3]，k = 3 走一遍：

numberprefix_sum要找 prefix_sum - k查之前的 count_by_prefix_sum找到几个对应的子数组

合计 2 个。

为什么一开始要放 {0: 1}：它代表“一个数都还没取”时的前缀和 0。没有它，从下标 0 开始的子数组（例如上表第二行的 [1, 2]）就数不到。

为什么“先查后记”：如果先把当前 prefix_sum 记进去再查，当 k = 0 时会查到它自己，相当于数了一个长度为 0 的空子数组。

复杂度：一遍循环，时间 O(n)；dict 最多存 n + 1 个不同的前缀和，空间 O(n)。

动手玩

两个按钮。区域和查询演示前缀和数组怎么一格格算出来，然后用一次减法回答 sum_range(2, 5)。和为 K 的子数组用一个带负数的例子 [3, 4, 7, 2, -3, 1, 4, 2]、k = 7：每一步先查 prefix_sum - k 在 dict 里出现过几次，再把当前前缀和记进去。找到的子数组会用绿色标出来。

最容易错的地方

  • 前缀和数组没有多一格，区间公式写成 prefix_sum[right] - prefix_sum[left - 1]，left = 0 时变成 prefix_sum[-1]，在 Python 里不会报错，而是悄悄取到最后一个元素，结果错得很隐蔽。
  • 和为 K 的子数组忘了初始化 {0: 1}，漏掉从开头开始的子数组。
  • 先记后查。两数之和会让一个数和自己配对；和为 K 的子数组在 k = 0 时会多数。
  • dict 里存的是“出现次数”还是“下标”要想清楚：数个数存次数（560），要返回位置存下标（1），要最长存最早出现的下标（525）。
  • 看到“和为 k 的子数组”就用滑动窗口。只有全是正数时窗口才成立，有负数或 0 就要用前缀和。

自测

1. 两数之和用了 O(n) 空间换 O(n) 时间。如果数组已经有序，有没有更省空间的做法？ 有。用第 25 课的对撞指针，时间 O(n)，额外空间 O(1)。无序时如果先排序再用对撞指针，时间是 O(n log n)，而且要另外保存原下标。
2. 和为 K 的子数组，如果题目改成“和能被 K 整除的子数组有几个”（LeetCode 974），要改哪里？ 两段前缀和的差能被 K 整除，等价于两者除以 K 的余数相同。所以 dict 改成按“前缀和除以 K 的余数”计数，每走一步查“当前余数之前出现过几次”。注意 Python 的 % 对负数也返回非负余数（见预备课），正好合用；其他语言要自己把负余数调成正的。
3. 如果数组会被频繁修改，前缀和还好用吗？ 不好用。改一个数，它后面所有的前缀和都要跟着改，一次修改是 O(n)。频繁修改加查询的场景要用树状数组或线段树，修改和查询都是 O(log n)——这两个结构超出了本课程的范围，知道有专门的工具就行。
