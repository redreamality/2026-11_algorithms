第 2 课 · 链表

链表的每个节点只记两样东西：自己的值和下一个是谁。像寻宝游戏，每张纸条告诉你下一张在哪。

先理解核心对象模板与不变量应用场景练习与自测

开始前要会：Python —— 生成器、yield 与 next(迭代器, 默认值)、itertools.islice、魔法方法（__iter__、__contains__、__eq__）、类型标注 Node | None 与引号前向引用、多重赋值（交换）、异常约定（IndexError、ValueError）；前面的课 —— 第 0 课 · 复杂度、第 1 课 · 动态数组（拿来对比）。

先理解：为什么需要“指向下一个”

数组适合按下标访问；如果更常见的是在已知位置增删，连续搬动元素就很贵。链表把“下一个位置”存进节点，让连接关系成为核心。

应用场景：没人写 LinkedList 类，但“指向下一个”的对象到处都是

业务代码里几乎没人专门写一个链表类。但“每个对象记着上一个 / 下一个是谁”的结构很常见，最典型的是版本历史：git 的每次提交只记“我的上一次提交是谁”（parent），一个分支就是指向最新提交的名字，整条历史就是一条单链表。

场景怎么做代价
新提交一次新建节点，parent 指向旧的最新提交，分支名挪到新节点O(1)，就是链表的头部插入
开新分支新分支直接指向当前提交，不复制历史O(1)，两个分支共用同一段尾巴
看历史（git log）沿着 parent 一路往回走，用生成器逐个产出走几步花几步，可以随时停
撤销最近一次提交分支名挪回 parentO(1)
class Commit:
    def __init__(self, message, parent=None):
        self.message = message
        self.parent = parent                # 上一次提交；第一次提交没有，是 None


def history(commit):
    """从某次提交往回走，逐个产出提交说明。"""
    while commit is not None:
        yield commit.message
        commit = commit.parent


main = None
for message in ["初始化", "加登录页", "修复样式"]:
    main = Commit(message, main)            # 头部插入：O(1)
feature = Commit("加支付", main)            # 新分支：挂在 main 后面，历史一个都没复制
print(list(history(feature)))               # ['加支付', '修复样式', '加登录页', '初始化']

完整可运行的版本在 examples/linked_list_in_practice.py（uv run examples/linked_list_in_practice.py），还会找两个分支“从哪里分叉的”。

下面看链表为什么能把头部增删做到 O(1)。

核心对象：节点、head 与 tail

长什么样

head → 1→2→3→ None（tail 指向 3） 
class Node:
    def __init__(self, value, next=None):
        self.value = value
        self.next = next

节点不用排在一起，散落在内存的任何地方都行，靠 next 串起来。

和数组比一比

操作数组链表
按下标取第 i 个O(1)O(n)，只能从头一个个数
头部插入 / 删除O(n)O(1)
尾部插入均摊 O(1)O(1)（前提是记着 tail）

一句话：数组擅长随机访问，链表擅长在已知位置增删。

模板与不变量：改指针前先保存连接

头部插入：两步，顺序不能反

0→1→2→None 
def appendleft(self, value):
    new_node = Node(value, self.head)   # ① 新节点先指向旧的头
    self.head = new_node                # ② 再把 head 挪到新节点
    if self.tail is None:               # 原来是空链表：新节点既是头也是尾
        self.tail = new_node
    self._size += 1

如果先挪 head，旧的头就找不到了。改指针之前，先想清楚谁会因此“失联”。

删除：要找的是“前一个”

单链表只能往后走。要删掉 2，得站在 1 上，让 1 跳过 2：

1⤼23 prev.next = prev.next.next

小技巧：哨兵节点。在 head 前面放一个假节点 dummy，这样删头节点和删中间节点就是同一种写法，不用单独判断。

反转：三个指针一起往前走

def reverse(self):
    previous_node, current_node = None, self.head
    while current_node is not None:
        next_node = current_node.next      # 先记住后面
        current_node.next = previous_node  # 掉头
        previous_node = current_node       # 两个指针一起前进
        current_node = next_node
    self.head, self.tail = self.tail, self.head

别忘了最后一行：反转之后 head 和 tail 要互换。

动手玩

建议依次试试：reverse（用“上一步 / 下一步”慢慢看三个指针怎么走）；把值设成 4 再点 remove，看删掉尾巴时 tail 怎么退回；连点 pop_front 直到链表变空。

最容易错的三个地方

  • 链表变空的时候，head 和 tail 都要变回 None。
  • 删掉的正好是尾巴，tail 要退回到前一个节点。
  • 只有一个节点时，head 和 tail 是同一个节点。

测试会专门检查这三种情况。

练习与自测

练习

补全 dsa/linked_list.py 里的 LinkedList。方法名照搬标准库队列 deque 的叫法（第 3 课会讲，到时候你会觉得眼熟）：append、appendleft、popleft、remove、reverse，再加上 len()、for、in。动画里的 push_front / push_back / pop_front 分别对应 appendleft / append / popleft。异常和标准库一致：空链表 popleft 抛 IndexError，remove 找不到抛 ValueError。

建议顺序：appendleft → __iter__（用 yield）→ append → popleft → __contains__ → remove → reverse。

自测

1. 为什么链表取第 i 个是 O(n)？ 节点不连续，没法算地址，只能从 head 开始沿着 next 走 i 步。
2. 有 tail 指针，为什么删尾巴在单链表上还是 O(n)？ 删掉尾巴以后，tail 要指向倒数第二个节点，可单链表没法往回走，只能从头找。双向链表就能做到 O(1)。
3. 两个分支共用同一段历史（实战例子里的 main 和 feature），为什么不用担心改了一个影响另一个？ 提交一旦建好就不再修改，新提交只是新建一个节点挂在前面，分支名挪过去。旧节点的 parent 从来不变，所以共用的那段尾巴对谁都一样。只有原地改指针（比如 reverse）才会影响所有共用它的人。
