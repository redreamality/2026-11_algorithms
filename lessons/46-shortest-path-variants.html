第 46 课 · 最短路变种

第 13 课的 BFS 和第 16 课的 Dijkstra 之外，还有三个常用的最短路算法：边权只有 0 和 1 时用 0-1 BFS（deque 头插尾插，O(V + E)）；要任意两点之间的最短路、点又不多时用 Floyd-Warshall（三重循环，O(n³)）；有负权边时用 Bellman-Ford（所有边松弛 V − 1 轮）。

开始前要会：Python —— dict 的 get 与 setdefault、math.inf、推导式（嵌套的 dict 推导式建表）、解包；前面的课 —— 第 3 课 · 栈与队列（deque 的 appendleft）、第 13 课 · 图的表示与 BFS（邻接矩阵、V 和 E）、第 16 课 · Dijkstra（松弛、过期记录）、第 19 课 · 动态规划（Floyd 是一张 DP 表）、第 35 课 · 网格搜索（网格是隐式的图）。

主线例子：收费站

五座城 A～E 之间有六条双向的路。有的路上有收费站，过一次记 1；有的路免费，记 0。边上的数字就是边权（第 16 课：边上的代价）。

A–B：1A–C：0C–B：0 B–D：1C–E：1D–E：0

这一课围绕这张图问三个问题，每个问题对应一个算法：

  1. 从 A 出发，到每座城最少过几次收费站？边权只有 0 和 1 → 0-1 BFS。
  2. 做一张表，写出任意两座城之间最少过几次收费站？→ Floyd-Warshall。
  3. 如果有一条路反过来给补贴（边权是负数），怎么办？→ Bellman-Ford。

先说两个词。单源最短路：从一个起点出发，求它到所有点的最短距离，第 16 课的 Dijkstra 就是单源的。全源最短路：求每一对点之间的最短距离，结果是一张 V × V 的表（V 是点数，E 是边数，和第 13 课一样）。

下面是“最少过几次收费站”的完整写法，和第 16 课的 Dijkstra 只差两处：heapq 换成 deque，进队分成“放队头”和“放队尾”。

import math
from collections import deque

toll_roads = {                     # 城 -> {邻城: 过路费次数}，双向各存一条
    "A": {"B": 1, "C": 0},
    "B": {"A": 1, "C": 0, "D": 1},
    "C": {"A": 0, "B": 0, "E": 1},
    "D": {"B": 1, "E": 0},
    "E": {"C": 1, "D": 0},
}

def zero_one_bfs(graph, source):
    distances = {source: 0}
    finished = set()
    queue = deque([(0, source)])            # 放 (距离, 点)
    while queue:
        distance, node = queue.popleft()    # 永远从队头取
        if node in finished:                # 过期记录：这个点早就确定了
            continue
        finished.add(node)
        for neighbor, weight in graph.get(node, {}).items():
            candidate = distance + weight
            if candidate < distances.get(neighbor, math.inf):   # 松弛
                distances[neighbor] = candidate
                if weight == 0:
                    queue.appendleft((candidate, neighbor))     # 0 边：和当前点一样近，插到队头
                else:
                    queue.append((candidate, neighbor))         # 1 边：远一层，排到队尾
    return distances

zero_one_bfs(toll_roads, "A")    # {'A': 0, 'B': 0, 'C': 0, 'E': 1, 'D': 1}

问题 1：边权只有 0 和 1（0-1 BFS）

普通 BFS 为什么不行。第 13 课的 BFS 数的是“走了几条边”。A 到 B 只有 1 条边，BFS 会说 B 最近；可那条路要收费，绕 A → C → B 走两条免费路才是 0。边权不全相同时，边数少不等于代价小。

Dijkstra 行，但多了 log。Dijkstra 对任何非负边权都对，O((V + E) log V)，log 来自堆。边权只有 0 和 1 时，用不着堆这么强的工具。

关键观察。Dijkstra 需要堆，是因为要“每次取出当前最近的点”。边权只有 0/1 时，有一个更便宜的办法保持顺序：

  • 从队头取出距离为 d 的点。走一条 0 边，邻居的距离还是 d，和队头一样小，所以插到队头（appendleft）。
  • 走一条 1 边，邻居的距离是 d + 1，比队里所有距离为 d 的都大，所以排到队尾（append）。

这样 deque 里的距离从队头到队尾始终是非递减的，而且只有 d 和 d + 1 两种值。队头就是最近的点，作用和 Dijkstra 的堆顶一样，但每次进出队只要 O(1)。

deque： 队头 →ddd+1d+1← 队尾 0 边的邻居插左边，1 边的邻居接右边

什么时候算“确定”。和第 16 课一样：一个点出队时才确定。同一个点可能先经 1 边被放到队尾，后来又经 0 边变得更近、被插到队头，于是队里有它的两条记录。后取出的那条是过期记录，跳过。注意这和第 35 课的普通 BFS 不一样：普通 BFS 在入队时就标记，因为第一次碰到就是最近；0-1 BFS 第一次碰到时不一定最近，不能在入队时就定下来。

为什么是对的。它就是用 deque 代替了堆的 Dijkstra。只要 deque 一直有序，每次取出的都是最近的点，第 16 课的“取出就确定”的论证原样成立。

复杂度。每条边最多松弛成功一次，带来一次进队，所以进出队 O(V + E) 次，每次 O(1)。总时间 O(V + E)，和 BFS 一样。

网格版：最少打穿几堵墙

第 35 课说过，网格就是一张隐式的图。网格里 "." 是空地，"#" 是墙，从左上走到右下，最少要打穿几堵墙？走进空地代价 0，走进墙代价 1，正好是 0/1 边权：

起点的右边和下边都是墙，至少打一堵；打穿 (0, 1) 进到 (0, 2)，往下走到 (2, 2)，之后右边和下边又都是墙，再打一堵。答案是 2。写法就是把上面代码里的“邻居”换成第 35 课的方向数组，代价看下一格是不是墙。这道题是 LeetCode 2290，在练习里要写。

问题 2：任意两点之间（Floyd-Warshall）

现在要一张表：任意两座城之间最少过几次收费站。一种做法是从每座城各跑一次 0-1 BFS（或 Dijkstra）。点不多时还有一个更省事的写法：Floyd-Warshall，三重循环，十行代码。

注意别和第 29 课混淆。第 29 课的“Floyd 判环”是用快慢指针判断链表有没有环，和这里的 Floyd-Warshall 最短路是两个不同的算法，只是都以 Robert Floyd 命名。

表从哪里开始

用第 13 课的邻接矩阵思路：dist[i][j] 先填“i 直接走到 j 的边权”；i 等于 j 填 0；没有直达的边填 math.inf（表示目前到不了）。主线例子的初始表：

ABCDE
A010∞∞
B1001∞
C000∞1
D∞1∞00
E∞∞100

一个一个放开中转站

想象一开始不准中途经过任何城，只能直达，表就是上面那张。然后规则一点点放宽：先允许途中经过 A，再允许经过 A、B，再允许 A、B、C……每放开一个中转站 k，就对每一对 (i, j) 问一句：

dist[i][k] + dist[k][j] < dist[i][j] 吗？     # 先到 k、再从 k 到 j，比现在记着的更近吗？

更近就改。这就是第 16 课的松弛，只不过“绕道的点”换成了 k。五个中转站都放开以后，任何路线都被允许了，表里就是真正的最短距离。

import math

def floyd_warshall(graph):
    nodes = list(graph)                     # 本例每座城都是 graph 的键
    dist = {i: {j: (0 if i == j else math.inf) for j in nodes} for i in nodes}
    for i, edges in graph.items():
        for j, weight in edges.items():
            dist[i][j] = weight
    for k in nodes:                         # 中转站：必须在最外层
        for i in nodes:
            for j in nodes:
                if dist[i][k] + dist[k][j] < dist[i][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]
    return dist

table = floyd_warshall(toll_roads)
table["A"]["D"]     # 1：A → C → B → D，只在 B–D 交一次

在主线例子上，每一轮改了什么：

  • k = A：没有任何一对能经过 A 变近，不变。
  • k = B：A → B → D 得 1 + 1 = 2，dist[A][D] 从 ∞ 变成 2；C → B → D 得 0 + 1 = 1，dist[C][D] 变成 1（反方向同理）。
  • k = C：A → C → B 得 0 + 0 = 0，dist[A][B] 从 1 变成 0；A → C → D 得 0 + 1 = 1，dist[A][D] 从 2 又变成 1——这里用到的 dist[C][D] = 1 是上一轮刚算出来的，它本身已经“经过了 B”。A → C → E、B → C → E 也都变成 1。
  • k = D、k = E：不变。最终表是：A、B、C 互相之间 0，D、E 之间 0，两组之间 1。

为什么 k 必须在最外层

这是一张第 19 课讲的 DP 表。状态：distk[i][j] = 从 i 到 j、途中只准经过“前 k 个中转站”的最短距离。转移：放开第 k 个中转站后，最短路要么不经过它（还是 distk−1[i][j]），要么经过它一次（distk−1[i][k] + distk−1[k][j]），取小的。

算第 k 层的任何一格，都要用到第 k − 1 层的整张表。所以必须一层一层来：先把 k = A 这一层对所有 (i, j) 做完，再做 k = B 这一层。k 在最外层，正好就是“一层一层”。

把 k 放到最里层（先定 i、j，再试所有 k）就错了：dist[i][j] 只在轮到 (i, j) 那一次被计算，那时它要用的 dist[i][k]、dist[k][j] 可能还没被算好，之后它们变短了，dist[i][j] 也不会再更新。自测第 1 题有一个具体的反例。

为什么可以原地改，不用存 V 张表。第 k 轮里，第 k 行和第 k 列不会变：dist[k][k] 是 0，dist[i][k] + dist[k][k] 不可能比 dist[i][k] 更小。所以这一轮用到的 dist[i][k] 和 dist[k][j]，改不改都一样，一张表就够了。

负权边和负环

Floyd 允许负权边（Dijkstra 不允许）。但如果有负环——绕一圈边权加起来小于 0——每多绕一圈就更短，最短路没有意义。三重循环跑完后，只要某个 dist[i][i] < 0（从 i 出发绕回 i 总和是负的），就说明有负环。

复杂度：n 不超过几百时最省事

三重循环，时间 O(n³)，表要 O(n²) 空间（n 就是点数 V）。n = 200 时 200³ = 800 万次比较，C++ 一眨眼，Python 几秒。n 再大就不划算了：n = 2000 是 80 亿次。点多、边少（稀疏）的图，还是从每个点各跑一次 Dijkstra。

问题 3：有负权边（Bellman-Ford）

假设主线例子里 C–B 这条路给补贴，走一次返 1 次过路费，边权变成 −1。马上出问题：路是双向的，B → C → B 绕一圈是 −1 + −1 = −2，每绕一圈都“更便宜”，这就是负环，最短路不存在。所以负权边一般出现在单向的图里。换一张单向的小图：A → B 2，A → C 3，C → B −2（返现 2），B → D 1。正确答案：A 到 B 走 A → C → B 是 3 − 2 = 1，A 到 D 是 1 + 1 = 2。

Dijkstra 为什么错。第 16 课说过：Dijkstra 取出一个点就当它确定了。从 A 出发，B（2）比 C（3）近，B 先出堆、被确定成 2，并用它把 D 更新成 3。之后 C 出堆，经过 −2 的边把 B 改成 1——可 B 已经确定过了，不会再出堆去更新 D。D 停在 3，错了。负边让一个“更远的点”绕回来反超，这正是第 16 课说的“负权边不能用”。

Bellman-Ford 一句话：把所有边松弛 V − 1 轮。不挑顺序、不用堆，每一轮把每条边都试一遍“经过它能不能更短”。

def bellman_ford(graph, source):
    nodes = set(graph) | {neighbor for edges in graph.values() for neighbor in edges}
    distances = {source: 0}
    for _ in range(len(nodes) - 1):         # V - 1 轮
        for node, edges in graph.items():   # 每一轮：所有边都松弛一次
            for neighbor, weight in edges.items():
                if node in distances and distances[node] + weight < distances.get(neighbor, math.inf):
                    distances[neighbor] = distances[node] + weight
    return distances

bellman_ford({"A": {"B": 2, "C": 3}, "C": {"B": -2}, "B": {"D": 1}}, "A")
# {'A': 0, 'B': 1, 'C': 3, 'D': 2}

为什么是 V − 1 轮。没有负环时，最短路不会重复经过同一个点，所以最多 V 个点、V − 1 条边。第 1 轮之后，“只用 1 条边”的最短路一定算对了；第 2 轮之后，“最多 2 条边”的也对了……第 V − 1 轮之后全部算对。

顺手判负环。V − 1 轮之后再松弛一轮，如果还有边能让距离变短，说明有负环。复杂度 O(V × E)，比 Dijkstra 慢得多，所以只在真有负权边时才用。

动手玩

先点 0-1 BFS 从 A 出发：虚线是免费路（0），实线是收费路（1）。下面的 deque 里，绿框是插到队头的，蓝框是排到队尾的。注意 B：先经过收费路被记成 1、排到队尾，接着经过免费路 C–B 改成 0、插到队头，于是队尾留下一条过期的 (1, B)。

再点 Floyd：逐个放开中转站：橙色的点是当前的中转站 k，表里浅橙色是第 k 行和第 k 列（这一轮要用的数），深橙色是刚被改小的格子。留意 dist[A][D]：k = B 时变成 2，k = C 时又变成 1。

该用哪个

边权要什么用时间
没有权（或全都一样）单源BFS（第 13 课）O(V + E)
只有 0 和 1单源0-1 BFSO(V + E)
非负单源Dijkstra（第 16 课）O((V + E) log V)
有负权边单源，顺便判负环Bellman-FordO(V × E)
任意（不能有负环）全源，n 不超过几百Floyd-WarshallO(n³)
非负，图大且稀疏全源每个点各跑一次 DijkstraO(V × (V + E) log V)

记法：从上往下，能处理的边权越来越“宽”，代价越来越大。先看边权，能用上面的就别用下面的。

最容易错的地方

  • 0-1 BFS 在入队时就标记已访问。那是普通 BFS 的写法。0-1 BFS 里一个点第一次被碰到时不一定最近，要等出队时才确定。
  • 0-1 BFS 把 0 边和 1 边的方向放反。0 边要 appendleft（同样近，先处理），1 边才 append。
  • Floyd 把 k 写在里层。不报错，但某些图会算出 ∞ 或者偏大的数。k 一定在最外层。
  • Floyd 初始表忘了对角线填 0。dist[i][i] 最后会是 ∞ 或者“绕一圈回到 i”的长度，而不是 0。
  • 有负权边还用 Dijkstra。不报错，结果可能错。见到负权先想 Bellman-Ford。

自测

1. 一条单向的链 B → D → C → A，每条边权 1。点的循环顺序是 A、B、C、D。把 k 写在最里层（for i、for j、for k），dist[B][A] 会算成多少？ ∞。轮到 (i, j) = (B, A) 时：经过 D 要用 dist[D][A]，可 D 那一行排在 B 后面，还没算，是 ∞；经过 C 要用 dist[B][C]，j = C 排在 j = A 后面，也还没算，是 ∞。之后它们都被算出来了，可 (B, A) 这一格不会再回头算。正确答案是 3，k 放在最外层就能得到。
2. 0-1 BFS 里，如果 1 边也用 appendleft，会怎样？ deque 不再有序：距离 d + 1 的点跑到了距离 d 的点前面，先被取出、先被“确定”，可它后来还可能经过 0 边变短，答案就错了。
3. 边权是 0、1、2 三种，还能用 deque 吗？ 不能直接用：只有队头和队尾两个口子，放不下三种距离 d、d + 1、d + 2 的顺序。可以把每条权重 2 的边拆成两条权重 1 的边（中间加一个点），再跑 0-1 BFS；或者直接用 Dijkstra。
