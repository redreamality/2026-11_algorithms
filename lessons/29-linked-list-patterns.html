第 29 课 · 链表高频技巧

链表面试题翻来覆去就是几招：改指针前先记住后面的节点（反转）、在头前面放一个哑节点（合并、删除）、快慢指针（找中点、判环、找入环点）、前后指针拉开固定距离（倒数第 N 个）。这一课把每一招讲透，并说明它为什么是对的。

开始前要会：Python —— 类型标注（X | None、引号前向引用）、多重赋值（slow = fast = head）、f-string、raise 与 try/except、__repr__、lambda（自测脚本里用到）；前面的课 —— 第 2 课 · 单链表（Node、顺着 next 走）、第 8 课 · 归并排序（题 2 的“合并”就是它的合并步骤）、第 25 课 · 双指针（快慢指针第一次出现）。

实战里怎么写：业务代码里几乎不手写链表

先说实话：Python 业务代码里几乎没人写 ListNode。但“顺着 next 一路走”的结构到处都有，只是不叫链表：员工 → 经理 → 总监的上级关系、分类表的 parent_id、短链接的重定向链，本质都是“key → 下一个 key”。这时本课的技巧（尤其是判环）就是真需求：数据录错了，重定向或上级链会无限循环。

场景用什么代价
存一串数据、随机访问list按下标 O(1)，中间插入 O(n)
两头都要进出：队列、撤销栈、最近 N 条collections.deque（内部就是分块的双向链表）两端 O(1)
反转、合并两份有序数据reversed(items)、heapq.merge(a, b)O(n)
“下一个是谁”的链（重定向、上级链）判环，数据不大用 set 记走过的节点O(n) 时间，O(n) 空间
同上，但数据很大或不能额外存快慢指针（本课题 4）O(n) 时间，O(1) 空间
def follow_redirects(redirects: dict[str, str], start: str) -> list[str]:
    """短链接一路跳到底，返回路径；发现环就报错。"""
    path, seen = [start], {start}
    while path[-1] in redirects:
        next_url = redirects[path[-1]]
        if next_url in seen:
            raise ValueError(f"重定向成环：{' → '.join(path + [next_url])}")
        path.append(next_url)
        seen.add(next_url)
    return path

def reporting_chain_has_cycle(manager_of: dict[str, str], employee: str) -> bool:
    """上级链有没有环。快慢指针：不用额外存走过的人。"""
    slow = fast = employee
    while fast in manager_of and manager_of[fast] in manager_of:
        slow = manager_of[slow]                  # 走一步
        fast = manager_of[manager_of[fast]]      # 走两步
        if slow == fast:
            return True
    return False

准备：节点和两个小工具

class ListNode:
    def __init__(self, value, next=None):
        self.value = value
        self.next = next

和第 2 课的 Node 一样：每个节点只记自己的值和下一个节点。面试题里一般只给你 head（头节点），没有 tail，也没有 size。

骨架文件里已经写好了 build_linked_list([1, 2, 3])（把 Python 列表变成链表）和 linked_list_to_list(head)（把链表变回列表），自己测试时直接用。

做链表题最重要的习惯：在纸上画图。画出三四个节点，写出每一步之后每个 next 指向谁。大部分链表 bug 都是“改了一个指针，结果后面的节点找不到了”，画图能一眼看出来。

技巧 0：哑节点（dummy node）

它解决什么问题：很多操作需要“站在前一个节点上”。比如删除节点 x，要让 x 前面那个节点的 next 跳过 x。但头节点前面没有节点，删头节点就得单独写一个 if。合并链表时也一样：结果链表的头是谁，要比较完第一次才知道，又得单独处理。

做法：新建一个不存真实数据的节点，放在 head 前面：

dummy_node = ListNode(0, head)   # dummy_node.next 就是原来的 head
# …… 各种操作，头节点现在也有“前一个节点”了 ……
return dummy_node.next           # 真正的头永远是 dummy_node.next

这样每个真实节点都有前一个节点，删头节点和删中间节点就是同一种写法。注意最后要返回 dummy_node.next，而不是原来的 head，因为原来的 head 可能已经被删掉或者换了位置。

什么时候用：只要头节点可能被删掉、被换掉，或者你要从零开始拼出一条新链表，就先放一个哑节点。

题 1：反转链表（LeetCode 206）

题意：给出单链表的头节点，把整条链表反转过来，返回新的头节点。

例子：1 → 2 → 3 → 4 → 5 变成 5 → 4 → 3 → 2 → 1。

暴力做法的问题：把所有值倒进 Python 列表，倒过来再建一条新链表。时间是 O(n)，但要 O(n) 的额外空间，而且等于绕开了链表本身。面试官要的是原地反转：不建新节点，只改每个节点的 next，额外空间 O(1)。

关键观察：反转就是让每个节点的 next 从“指向后一个”改成“指向前一个”。难点在于：一旦改了 current_node.next，原来的后一个节点就找不到了。所以改之前，必须先把它存起来。

做法：三个变量一起往前走。

def reverse_list(head):
    previous_node = None        # 已经反转好的那一段的头（一开始是空的）
    current_node = head         # 还没反转的那一段的头
    while current_node is not None:
        next_node = current_node.next      # ① 先记住后面，不然下一步改完就丢了
        current_node.next = previous_node  # ② 掉头：指向前一个
        previous_node = current_node       # ③ 两个指针一起往前挪一格
        current_node = next_node
    return previous_node        # current_node 走到 None 时，previous_node 是原来的尾巴，也就是新的头

为什么是对的：每一轮开始时，链表被分成两段：previous_node 开头的那段已经反转好了（例如 2 → 1 → None），current_node 开头的那段还没动（例如 3 → 4 → 5 → None）。每一轮把 current_node 这一个节点从“没动的段”摘下来，接到“反转好的段”的最前面。两段的关系始终成立，当没动的段变空（current_node 是 None），反转好的段就是整条链表。

也可以用递归写：先把 head.next 之后的部分反转好，再让 head.next.next = head、head.next = None。但递归要用 O(n) 的调用栈空间，链表很长时会爆栈，面试时优先写循环版本。

复杂度：每个节点处理一次，时间 O(n)；只用了三个变量，额外空间 O(1)。

题 2：合并两个有序链表（LeetCode 21）

题意：两条链表都已经从小到大排好序，把它们合并成一条从小到大的链表。要求直接复用原来的节点。

例子：1 → 2 → 4 和 1 → 3 → 4 合并成 1 → 1 → 2 → 3 → 4 → 4。

暴力做法的问题：把两条链表的值都倒进列表、排序、再建新链表，时间 O((m+n) log(m+n))，还要额外空间，而且没用上“两条已经有序”这个条件。

关键观察：这就是归并排序（第 8 课）里的“合并”步骤：两条都有序，那么整体最小的数，一定是两条链表当前的头中较小的那个。每次取走一个，问题规模就减 1。

做法：结果链表从零开始拼，头是谁一开始不知道，所以用哑节点；再用 tail_node 记住结果链表的最后一个节点，新节点接在它后面。

def merge_two_sorted_lists(first_head, second_head):
    dummy_node = ListNode(0)
    tail_node = dummy_node
    while first_head is not None and second_head is not None:
        if first_head.value <= second_head.value:
            tail_node.next = first_head        # 把较小的节点接到结果后面
            first_head = first_head.next       # 这条链表往前走
        else:
            tail_node.next = second_head
            second_head = second_head.next
        tail_node = tail_node.next             # 结果链表的尾巴也往前走
    # 有一条已经走完了，另一条剩下的部分本来就有序，整段接上即可
    tail_node.next = first_head if first_head is not None else second_head
    return dummy_node.next

为什么是对的：每次接上去的都是“剩下所有节点里最小的”，所以结果是有序的；每个节点恰好被接一次，不会丢也不会重复。用 <= 让相等时先取第一条的节点，可以保持稳定性。

复杂度：时间 O(m + n)，额外空间 O(1)（只多了一个哑节点）。

技巧：快慢指针

两个指针从 head 出发，slow 每次走 1 步，fast 每次走 2 步。它们之间的距离每走一轮就拉开 1 步。这个简单的设定能一次遍历解决三件事：找中点、判断有没有环、找入环点。

题 3：链表的中间节点（LeetCode 876）

题意：返回链表的中间节点；节点数是偶数时有两个中间节点，返回第二个。

例子：1 → 2 → 3 → 4 → 5 返回 3；1 → 2 → 3 → 4 → 5 → 6 返回 4。

普通做法：先走一遍数出长度 n，再从头走 n // 2 步。这也是 O(n)，没有错，只是要走两遍。快慢指针一遍就够，而且它是后面回文链表、链表排序等题的基本零件。

def middle_node(head):
    slow = fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next          # 走 1 步
        fast = fast.next.next     # 走 2 步
    return slow

为什么是对的：走了 k 轮之后，slow 在下标 k，fast 在下标 2k。fast 走到尽头时，slow 恰好走了一半。具体来说：

  • 长度 5（奇数）：两轮后 fast 在下标 4（最后一个节点），fast.next 是 None，停下；slow 在下标 2，正是中间。
  • 长度 6（偶数）：三轮后 fast 走到了下标 6，也就是 None，停下；slow 在下标 3，是两个中间节点（下标 2、3）中的第二个。

循环条件要同时检查 fast 和 fast.next：fast.next.next 要求 fast.next 不是 None，否则会报 AttributeError。

题 4：判断链表有没有环（LeetCode 141）

题意：链表最后一个节点的 next 可能不是 None，而是指回前面的某个节点，形成一个环。判断有没有环。

例子：3 → 2 → 0 → -4 → (回到 2) 有环；1 → 2 → 3 → None 没有环。

暴力做法的问题：用一个集合记录走过的节点，走到一个已经见过的节点就说明有环。时间 O(n)，但集合要 O(n) 的额外空间。

关键观察：如果有环，一个人一直往前走会在环里永远绕圈。让一快一慢两个人同时走，就像操场上跑步：跑得快的人迟早会从后面套圈追上跑得慢的人。如果没有环，快的人会先跑到终点（None）。

def has_cycle(head):
    slow = fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:          # 比较的是“是不是同一个节点”，用 is
            return True
    return False                  # fast 走到了 None，说明链表有尽头

为什么一定会相遇，而不会“跳过去”：等两个指针都进了环，看 fast 在 slow 后面还差几步（沿着环的方向数）。每一轮 slow 走 1 步、fast 走 2 步，这个差距恰好减少 1。差距是一个整数，每次减 1，一定会正好减到 0，不可能从 1 直接跳到 −1。差距最多是环长 L，所以 slow 进环后最多再走 L 轮就会相遇。

复杂度：时间 O(n)，额外空间 O(1)。

题 5：找入环点（LeetCode 142）

题意：如果有环，返回开始进入环的第一个节点；没有环返回 None。

例子：1 → 2 → 3 → 4 → 5 → 6 → (回到 3)，入环点是 3。

暴力做法的问题：同样可以用集合，第一个被重复访问的节点就是入环点，但要 O(n) 空间。

做法：分两个阶段。第一阶段和上一题一样，找到 slow 和 fast 的相遇点。第二阶段，一个指针 from_head 从 head 出发，另一个 from_meeting 从相遇点出发，都每次走 1 步，它们相遇的地方就是入环点。

def find_cycle_entry(head):
    slow = fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:                       # 第一阶段：相遇，说明有环
            from_head = head
            from_meeting = slow
            while from_head is not from_meeting:   # 第二阶段：都每次走 1 步
                from_head = from_head.next
                from_meeting = from_meeting.next
            return from_head
    return None

为什么是对的：记 head 到入环点的距离为 a，环的长度为 L。

  1. 相遇时，设 slow 一共走了 s 步，那么 fast 走了 2s 步。fast 多走的那 s 步全都是在环里绕圈，所以 s 是 L 的整数倍。
  2. slow 的 s 步可以拆成两段：先走 a 步到入环点，再在环里走 s − a 步到相遇点。
  3. 现在让 from_meeting 从相遇点再走 a 步。相当于从入环点出发，在环里一共走了 (s − a) + a = s 步。s 是 L 的整数倍，所以它正好回到入环点。
  4. 同时，from_head 从 head 走 a 步，也正好到入环点。前 a 步里 from_head 还在环外，from_meeting 在环里，它们不会提前碰面。所以两者第一次相遇的地方就是入环点。

我们并不知道 a 是多少，但不需要知道：让它们一起走，相遇就停。拿例子验证一下：a = 2，L = 4（环是 3、4、5、6）。第一阶段两指针在 5 相遇，此时 slow 走了 4 步，正是 L 的倍数。第二阶段 from_head 走 1 → 2 → 3，from_meeting 走 5 → 6 → 3，在 3 相遇。

复杂度：时间 O(n)，额外空间 O(1)。

题 6：删除链表的倒数第 N 个节点（LeetCode 19）

题意：删除链表的倒数第 n 个节点，返回删除后的头节点。保证 n 不超过链表长度。

例子：1 → 2 → 3 → 4 → 5，n = 2，倒数第 2 个是 4，结果 1 → 2 → 3 → 5。1 → 2，n = 2，要删的是头节点，结果 2。

普通做法：先走一遍数出长度 L，倒数第 n 个就是正数第 L − n + 1 个，再走一遍找到它的前一个节点删掉。要遍历两遍。

关键观察：如果有两个指针，前面的比后面的领先 n 步，那么当前面的指针走到最后一个节点时，后面的指针正好停在“倒数第 n 个的前一个节点”上，可以直接删。这样只遍历一遍。

def remove_nth_from_end(head, n):
    dummy_node = ListNode(0, head)   # 要删的可能是头节点，所以先放哑节点
    ahead = behind = dummy_node
    for _ in range(n):               # ahead 先走 n 步，拉开距离
        ahead = ahead.next
    while ahead.next is not None:    # 一起走，直到 ahead 停在最后一个节点
        ahead = ahead.next
        behind = behind.next
    behind.next = behind.next.next   # behind 的下一个就是倒数第 n 个，跳过它
    return dummy_node.next

为什么是对的：把哑节点记作位置 0，真实节点依次是位置 1 到 L。ahead 先走 n 步到位置 n；然后两个一起走，直到 ahead 到位置 L（最后一个节点），一起走了 L − n 步，behind 停在位置 L − n。倒数第 n 个节点在位置 L − n + 1，正好是 behind 的下一个。

哑节点的作用：n 等于长度 L 时，要删的是头节点，behind 一步都不走，停在哑节点上，behind.next = behind.next.next 照样成立。没有哑节点的话，这种情况得单独写一个 if。

复杂度：时间 O(n)，额外空间 O(1)。

综合题：回文链表（LeetCode 234）

判断 1 → 2 → 2 → 1 这样的链表从前往后读和从后往前读是否一样。单链表不能往回走，所以：① 用快慢指针找到中点；② 把后半段反转；③ 一个指针从 head、一个从反转后的后半段开头出发，逐个比较值。三个零件都是上面讲过的，时间 O(n)，额外空间 O(1)。

怎么认出这类题

  • “反转链表”“反转第 m 到第 n 个”“每 k 个一组反转”：三指针反转，局部反转时用哑节点记住反转段的前一个节点。
  • “合并有序链表”“拼接”“按某种规则重排”：哑节点 + tail 指针从零拼。
  • “中点”“前半段 / 后半段”“回文”：快慢指针找中点。
  • “有没有环”“入环点”“重复的数（把数组看成链表）”：快慢指针（Floyd 判环）。
  • “倒数第 k 个”：前后指针拉开 k 步。
  • “删除……节点”“头节点可能被删”：先放哑节点，最后返回 dummy_node.next。
  • 题目要求“O(1) 额外空间”：基本就是在提示你用指针技巧，而不是集合或数组。

动手玩

建议依次试试：点 反转链表，用“上一步 / 下一步”看 previous_node、current_node、next_node 三个指针每一步怎么动、箭头怎么掉头；点 找中点，再把链表改成 6 个数对比一下停在哪；点 删除倒数第 N 个，把 N 改成链表长度，看哑节点怎么让“删头节点”不用特殊处理；最后点 判环并找入环点，看 fast 怎么在环里追上 slow，以及第二阶段两个指针怎么在入环点碰头。

最容易错的地方

  • 反转时先改了 next，忘了先存后面的节点，后半条链表就丢了。顺序永远是：先存 next_node，再改指针，最后往前挪。
  • 返回了旧的 head：反转后应该返回 previous_node；用了哑节点的题应该返回 dummy_node.next。
  • 快慢指针的循环条件只写了 fast.next：fast 自己是 None 时访问 fast.next 会报错。要写 fast is not None and fast.next is not None。
  • 判环时用 == 比较节点：应该比较“是不是同一个节点对象”，用 is。两个不同的节点可能值相同。
  • 删除倒数第 N 个时不放哑节点，删头节点的情况就会出错。
  • 合并链表时忘了接上剩下的那一段，结果少了一截。

练习

补全 dsa/linked_list_patterns.py。建议顺序：reverse_list → merge_two_sorted_lists → middle_node → has_cycle → find_cycle_entry → remove_nth_from_end → is_palindrome。写完一个就运行一次，看打印出来的“期望”和“实际”是否一致：

uv run dsa/linked_list_patterns.py

自测

1. 反转链表时，为什么一定要先执行 next_node = current_node.next？ 因为下一步 current_node.next = previous_node 会把指向后面的指针改掉，改完之后就再也找不到原来的后一个节点了。必须先把它存起来，循环才能继续往后走。
2. 判环时，fast 每次走 3 步行不行？为什么通常走 2 步？ 不一定行。两指针都进环后，每轮差距减少 2。差距是奇数时，会从 1 直接变成 −1，越过对方；如果环长是偶数，差距在环上永远是奇数，两个指针就永远碰不上。走 2 步时差距每轮恰好减 1，一定能正好减到 0；而且找入环点的推导也依赖“fast 走的路程恰好是 slow 的两倍”。
3. 哪些题需要哑节点？ 头节点可能被删掉或换掉（删除节点、删除倒数第 N 个、局部反转），或者要从零开始拼一条新链表（合并链表）。用了哑节点，最后返回 dummy_node.next。
