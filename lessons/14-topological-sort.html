第 14 课 · 拓扑排序

有先后依赖的一堆事，排成一条队，保证每件事都排在它依赖的事后面。比如排课：先修课必须在前。

先定义依赖图 Kahn 模板 正确性直觉 标准库应用 动画与练习

开始前要会：Python —— setdefault / defaultdict、try/except 与 raise、类型标注（Mapping / Iterable）；前面的课 —— 第 13 课 · 图的表示与遍历（队列见 第 3 课）

先定义依赖图：节点、边和入度

把课程画成有向图：u → v 表示“学 v 之前要先学 u”。

微积分→数据结构→算法 （编程入门 → 数据结构 也成立）

一个合法的顺序：微积分、编程入门、数据结构、算法……答案往往不止一个，只要每条边都“从前指向后”就行。

前提：图里不能有环。A 要先学 B、B 又要先学 A，谁都开不了头。没有环的有向图叫 DAG。

先记 Kahn 算法模板

入度 = 指向这个点的边数 = 它还差几门先修课。入度为 0 的课，现在就能学。

from collections import deque
from graphlib import CycleError

def topological_order(dependencies):         # {课: [它的先修课, ...]}
    dependents = {}                          # 反过来存：先修课 -> 依赖它的课
    remaining = {}                           # 入度：每门课还差几门先修课
    for course, prerequisites in dependencies.items():
        remaining.setdefault(course, 0)
        dependents.setdefault(course, [])
        for prerequisite in set(prerequisites):   # 重复的依赖只算一次
            dependents.setdefault(prerequisite, []).append(course)
            remaining.setdefault(prerequisite, 0)
            remaining[course] += 1

    queue = deque(course for course, count in remaining.items() if count == 0)
    order = []
    while queue:
        course = queue.popleft()             # 学完这门课
        order.append(course)
        for dependent in dependents[course]: # 它不再挡着后面的课
            remaining[dependent] -= 1
            if remaining[dependent] == 0:
                queue.append(dependent)      # 这门课的先修课全学完了
    if len(order) < len(remaining):
        raise CycleError("存在循环依赖")
    return order

注意输入存的是“我依赖谁”，而 Kahn 算法要的是“谁依赖我”（学完一门课，去给后面的课减入度），所以第一步先把边反过来存一份。

正确性直觉：入度为 0 的节点没有未完成的前置边，可以安全放到结果里；删除它后，只会让后继节点少一条未完成的边。若最后仍有节点，剩下的节点互相等待，必然含环。

队列：微积分编程入门 ← 一开始入度为 0 的都进来

标准库应用：graphlib.TopologicalSorter

构建系统、包管理器、任务调度器、数据库迁移，都要先排出“谁先做”。Python 3.9 起，标准库 graphlib.TopologicalSorter 已经帮你写好了，输入就是一个 dict：节点 → 它依赖的节点。

场景用什么代价
只要一个合法顺序（安装依赖、跑迁移）TopologicalSorter(依赖表).static_order()O(n + m)
能并行就并行（CI 构建、任务编排）prepare() → 循环 get_ready() / done()O(n + m)
配置写出了循环依赖捕获 graphlib.CycleError，error.args[1] 是环上的节点和排序一起检查，不另花时间
from graphlib import CycleError, TopologicalSorter

build_steps = {                       # 步骤 -> 它要等的步骤
    "codegen": ["install"],
    "lint": ["install"],
    "compile": ["codegen"],
    "package": ["compile", "lint"],
}

list(TopologicalSorter(build_steps).static_order())
# ['install', 'codegen', 'lint', 'compile', 'package']（合法顺序之一）

sorter = TopologicalSorter(build_steps)
sorter.prepare()                      # 有环在这里就抛 CycleError
while sorter.is_active():
    ready = sorter.get_ready()        # 依赖全部完成、现在就能开工的步骤
    for step in ready:                # 真实项目里交给线程池并行跑
        run(step)
        sorter.done(step)

try:
    TopologicalSorter({"a": ["b"], "b": ["a"]}).prepare()
except CycleError as error:
    # error.args 是抛异常时传进去的参数元组；graphlib 把环上的节点列表放在 args[1]
    print("循环依赖：", error.args[1])  # ['a', 'b', 'a']

完整可运行的版本（安装顺序、用线程池并行构建、找出循环依赖）在 examples/topo_sort_in_practice.py（uv run examples/topo_sort_in_practice.py）。

有环会怎样：排不完

环上的点互相挡着，入度永远减不到 0，永远进不了队列。所以队列空了、结果却不到 n 个，就说明有环。拓扑排序顺手就把“有没有环”判断了。

复杂度

步骤代价
建邻接表、数入度O(n + m)
每个点进出队列一次O(n)
每条边减一次入度O(m)
合计O(n + m)，n 个点、m 条边

动手玩

先点排序（无环），盯住橙色的入度数字怎么往下掉；再点排序（有环），多了一条“编程入门要先修毕设”的边，看排到哪里卡住。

最容易错的地方

  • 方向搞反：{"数据结构": ["微积分"]} 是数据结构依赖微积分，所以是数据结构的入度加一，微积分学完后去给数据结构减一。
  • 忘了只出现在依赖里的点（上例的微积分可能不是键）：它入度为 0，一开始就该入队。
  • 有环时不报错，悄悄返回一个不完整的列表。

练习

补全 dsa/topo_sort.py。输入格式和 graphlib 一样（节点 → 它依赖的节点），节点可以是任何可哈希的东西，有环抛 graphlib.CycleError。建议顺序：topological_order → parallel_batches（一次拿走当前所有入度为 0 的点，作为可以并行的一批）→ has_cycle（一两行就够）。测试不比对唯一答案，只检查每个节点是不是都排在它的依赖后面；parallel_batches 的结果会和 graphlib 逐批比对。

uv run dsa/topo_sort.py               # 构建流水线的端到端例子，逐条打印期望和实际
uv run pytest tests/test_topo_sort.py

自测

1. 队列换成栈，结果还对吗？ 对。只要每次取出的点入度为 0 就行，取的先后只影响得到哪一个合法顺序。
2. 怎么判断拓扑序是不是唯一的？ 每一步队列里都恰好只有 1 个点，顺序就是唯一的；某一步有 2 个以上可选，就不唯一。
3. 除了 Kahn，还有别的做法吗？ 用 DFS：一个点的所有后继都访问完时，把它记下来；最后把记录反过来就是拓扑序。
