第 17 课 · 最小生成树（Kruskal）

给几座村子修路，要让所有村子都连通，又要总花费最少。Kruskal 的办法很朴素：从最便宜的路开始修，会绕成圈的就不修。

先定义树和边 Kruskal 模板 正确性直觉 实际应用 动画与练习

开始前要会：Python —— key=、operator.itemgetter 与排序稳定性、字典推导式与生成器表达式（{room: room for room in rooms}、sum(w for _, _, w in tree)）、解包（for start, end, meters in ...）、异常（找不到答案时 raise ValueError）、setdefault、类型标注、f-string；前面的课 —— 第 15 课 · 并查集（判环靠它）、第 13 课 · 图（连通块）、第 0 课 · 复杂度。

先定义最小生成树：点、边和连通状态

无向带权图，n 个点。挑出一些边，让所有点连通、没有环，这就是一棵生成树，它恰好有 n − 1 条边。总权最小的那棵叫最小生成树（MST）。

上面 5 条边就是动画里那张图的 MST，总权 2+4+3+1+8 = 18。

先记 Kruskal 模板

chosen = []
for start, end, weight in sorted(edges, key=lambda edge: edge[2]):   # ① 按权从小到大
    if find(start) != find(end):          # ② 两头不在同一块：连上不会成环
        union(start, end)
        chosen.append((start, end, weight))
        if len(chosen) == node_count - 1: # 选够了，提前收工
            break
    # 否则两头早就连通了，再加这条边就成环，跳过
if len(chosen) < node_count - 1:
    raise ValueError("图不连通")

“会不会成环”就是问 u 和 v 是不是已经连通，这正是上一课并查集最擅长的：find 看是不是同一个老大，union 把两块合并。

正确性直觉：按权从小到大考察边。若一条边连接两个不同连通块，它可以安全加入；若两端已经连通，加入就会成环。每次选择都保留当前连通块之间最便宜的连接，直到得到 n − 1 条边。

实际应用：sorted + 小并查集

布网线、铺管道、修路这类“全连上、总成本最低”的问题，以及把相近的东西分组（门店划片区、相似文档归类），用的都是最小生成树。标准库没有现成的 MST，不过 Kruskal 就是 sorted 加上第 15 课的小并查集，十几行就能写完。

场景用什么代价
布线 / 管道总成本最低Kruskal：按成本排序 + 并查集判环O(E log E)
把点分成 k 组，组间尽量远Kruskal 跑到剩 k 块就停（单链接聚类）O(E log E)
稠密图（几乎两两有边）Prim（堆，像 Dijkstra）O(E log V)
大规模、要很多种图算法networkx / scipy（本课不依赖）—
from operator import itemgetter

def cheapest_cabling(rooms, routes):          # routes: [(房间, 房间, 米数), ...]
    parent = {room: room for room in rooms}

    def find(room):
        while parent[room] != room:
            parent[room] = parent[parent[room]]   # 顺手把路径缩短一半
            room = parent[room]
        return room

    plan = []
    for start, end, meters in sorted(routes, key=itemgetter(2)):   # 只按成本排
        root_start, root_end = find(start), find(end)
        if root_start != root_end:            # 两头还没连通：这根线有用
            parent[root_end] = root_start
            plan.append((start, end, meters))
    if len(plan) != len(rooms) - 1:
        raise ValueError("有房间无论如何都连不上")
    return plan

rooms = ["机房", "前台", "会议室", "研发区"]
routes = [("机房", "前台", 30), ("机房", "研发区", 12), ("前台", "会议室", 8), ("会议室", "研发区", 15)]
cheapest_cabling(rooms, routes)
# [('前台', '会议室', 8), ('机房', '研发区', 12), ('会议室', '研发区', 15)]，共 35 米

注意排序要写 key=itemgetter(2)：直接 sorted(routes) 会先按房间名排序，排出来的顺序就不是按成本了。完整可运行的版本（布线方案，以及把门店分成两个配送片区）在 examples/kruskal_in_practice.py，运行 uv run examples/kruskal_in_practice.py。

已连通的一块：{A, B, C, D, E}考察 B–D：两头都在里面 → 跳过B–D 5

复杂度

步骤代价
边排序O(E log E)
每条边一次 find / union几乎 O(1)，合计约 O(E)
合计O(E log E)，E 是边数

瓶颈在排序。选够 n − 1 条边就可以提前收工。

动手玩

点开始 Kruskal，看下面的边列表按权排好后一条条被考察：绿色是选中，划线是因为成环跳过。再点不连通的图：F 没有路，边看完了也凑不够 n − 1 条。

最容易错的地方

  • 判环只看“两头是不是同一块”，不用真的去图里找环。
  • 不连通时边全看完也不够 n − 1 条，要报错，不能悄悄返回一片森林。
  • 自环 (u, u, 权) 两头天然同一块，会被自动跳过；重边只会选便宜的那条。
  • 直接 sorted(edges)：元组先比第一项，排出来是按节点名而不是按权；就算把权放第一项，同权时也会去比较节点，节点没法比大小就抛 TypeError。要写 key=。

自测

1. 为什么“先挑最便宜的边”不会吃亏？ 把点分成任意两半，横跨两半的边里最便宜的那条，一定能出现在某棵 MST 里（换掉别的横跨边只会更贵或一样）。Kruskal 每次选的边恰好都是这种边。
2. 边权有相同的，MST 唯一吗？ 不一定。比如三角形三条边都是 1，选哪两条都行，但总权一定相同。
3. 还有别的 MST 算法吗？ Prim：从一个点出发，每次用堆挑“连到树外最便宜的边”，有点像 Dijkstra。稠密图上 Prim 常常更快。
