第 20 课 · 动态规划（二）：背包与序列

上一课是“递归 + 记个本子”。这一课反过来：直接画一张表，从小格子往大格子填，填到右下角就是答案。

开始前要会：Python —— NamedTuple（骨架和实战里的 Item / Campaign）、推导式与二维表（[[0] * (budget + 1) for _ in range(...)]）、enumerate、range 倒序、切片 [::-1]、sorted 与 key=、f-string 的 {x!r}、collections.abc 的 Sequence；前面的课 —— 第 19 课 · 动态规划（一）（格子代表什么、从哪几个格子推出来）、第 18 课 · 贪心（实战里“按性价比贪心”的反例）。

先定义 统一表格模板 逐题比较 应用场景 看动画 练习与自测

先定义：表格状态和转移

这一课的共同结构是：先定义一个表格状态，再从已经算好的小状态转移到当前格。表格中的每一格必须回答两句话：它代表什么，以及它依赖哪些更小的格子。若要返回具体方案，还要保存足够的信息，最后从答案格反向走回去。

统一表格模板：当前选择与不选择

for current in items:
    for state in states:
        keep = 上一层、同一状态的答案
        take = 上一层、扣掉当前选择后的答案
        table[current][state] = max(keep, take)

背包的“选 / 不选”、LCS 的“匹配 / 跳过”、LIS 的“接在某个更小值后面”，都是在替换状态含义和转移规则。先把这两个部分写清楚，再决定能不能压缩空间。

应用场景：实战里怎么写，先看标准库有没有

这一课的几个 DP 在真实项目里天天出现，只是常常藏在库里。difflib 是标准库里的文本对比模块（预备课没讲它，这里就地补两句话）：unified_diff(旧, 新, ...) 逐行给出和 git diff 一样的补丁，行前加 - 表示删、+ 表示加、空格表示没变；get_close_matches(词, 候选列表) 挑出和这个词最接近的几个候选，拼写纠错就用它：

场景用什么代价
比较两个文件 / 两版配置，生成补丁标准库 difflib.unified_diff约 O(n × m)，和 LCS 同一类
拼写纠错、“你是不是想输入”difflib.get_close_matches，或自己写编辑距离每对字符串 O(n × m)
预算内挑一组需求 / 广告位，收益最大标准库没有：自己写 0-1 背包，并回溯出选了哪些O(件数 × 预算)；规模很大时换整数规划求解器

逐题比较：0-1 背包，每件东西选或不选

预算是 budget，每件物品有花费（cost）和价值（value），每件最多拿一次，问最多能拿多少价值。

dp[i][c] = 只看前 i 件、容量为 c 时的最大价值。看第 i 件（重 w、值 v）：

不选：dp[i-1][c]
选  ：dp[i-1][c-w] + v      # 前提 c >= w
dp[i][c] = 两者取大
上一行：dp[i-1][c-w]……dp[i-1][c]
这一行：　　　　……dp[i][c]

每格只看上一行的两个格子。第 0 行（一件都不拿）全是 0。填完以后从右下角往回走，就知道选了哪些：

def choose_items(items: list[Item], budget: int) -> list[Item]:
    best = [[0] * (budget + 1) for _ in range(len(items) + 1)]
    for index, item in enumerate(items, start=1):
        for remaining in range(budget + 1):
            best[index][remaining] = best[index - 1][remaining]                 # 不选
            if remaining >= item.cost:                                          # 选
                with_item = best[index - 1][remaining - item.cost] + item.value
                best[index][remaining] = max(best[index][remaining], with_item)

    chosen, remaining = [], budget
    for index in range(len(items), 0, -1):
        if best[index][remaining] != best[index - 1][remaining]:   # 这一格变了，说明第 index 件被选了
            chosen.append(items[index - 1])
            remaining -= items[index - 1].cost
    return chosen[::-1]

压成一维：只留一行 dp[c]，c 从大到小倒着循环。倒着走时 dp[c-w] 还是“上一行”的旧值；正着走它已经被本行改过，同一件就会被拿好几次（那是“完全背包”）。

最长公共子序列（LCS）

子序列：按顺序挑出一些字符，可以不连续。"ABCB" 和 "BDCAB" 的 LCS 是 "BCB"，长度 3。

dp[i][j] = a 前 i 个字符 和 b 前 j 个字符 的 LCS 长度
a[i-1] == b[j-1]：dp[i-1][j-1] + 1      # 左上 + 1
否则           ：max(dp[i-1][j], dp[i][j-1])   # 上、左取大

想要具体的串：从右下角往回走，字符相同就收下并走左上，否则往大的那边走。

元素不一定是字符：把两个文件按行切成列表，LCS 就是“没变的那些行”，剩下的旧行标 -、新行标 +，这就是 diff。练习里的 diff_lines 就做这件事。

最长递增子序列（LIS）

dp[i] = 以 nums[i] 结尾的最长递增子序列长度。往前看所有比它小的 nums[j]，接在最长的那个后面：

dp[i] = 1 + max(dp[j] for j < i if nums[j] < nums[i])   # 没有就是 1
答案 = max(dp)          # 不一定是 dp[-1]！

动手玩

点 0-1 背包 或 LCS，用“上一步 / 下一步”慢慢看：橙色是正在填的格，蓝色是它依赖的格。LCS 填完后还会沿红色路线往回走，找出具体的子序列。

复杂度

问题时间空间
0-1 背包O(n·budget)O(n·budget)，只要最优值时压一维 O(budget)；要回溯方案就得留整张表
LCS / 编辑距离O(m·n)O(m·n)
LISO(n²)O(n)

暴力枚举所有子集或子序列是 O(2ⁿ)。DP 快，是因为每个格子只算一次。

最容易错的三个地方

  • 下标差一：表多开一行一列给“空”，所以第 i 行对应的字符是 a[i-1]。
  • 背包压一维时把 c 写成正着循环：同一件会被重复拿。要倒着。
  • LIS 的答案是 max(dp)，不是最后一格；空列表要返回 0。

自测

1. 背包压成一维，为什么 c 要倒着循环？ dp[c] 要用“上一行”的 dp[c-w]。倒着走时 c-w 还没被这一行改过；正着走就会用到本行刚算好的值，相当于同一件拿了两次。
2. LCS 表里，字符相同时为什么只看左上？ 两个末尾字符配成一对，用掉了 a 和 b 各一个字符，剩下的就是 dp[i-1][j-1] 那个子问题。
3. LIS 的 dp[i] 为什么要定义成“以 nums[i] 结尾”？ 这样才知道最后一个数是多少，新数能不能接上去。如果定义成“前 i 个里的最长”，就不知道能不能接了。
