第 31 课 · 二叉树高频题

面试里的二叉树题，大多数都是同一个套路：先想清楚“递归函数返回什么”，再在后序位置（左右子树都算完之后）用左右两边的结果拼出当前节点的结果。

开始前要会：Python —— 嵌套函数与 nonlocal、生成器表达式、类型标注（X | None、引号前向引用）、float("inf")、lambda、try/except、f-string；前面的课 —— 第 5 课 · 递归与分治、第 10 课 · 二叉树与遍历（后序、层序）、第 11 课 · 二叉搜索树、第 3 课 · 栈与队列（deque、显式栈）。

这一课默认你已经学过第 10 课（二叉树与递归遍历）和第 11 课（二叉搜索树）。树节点的写法和第 10 课一样：

class TreeNode:
    def __init__(self, val, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

题目里的树都用 LeetCode 的层序写法给出，比如 [3, 9, 20, None, None, 15, 7]：先写根，再从左到右写第二层、第三层……None 表示那个位置没有节点。

统一套路：递归函数返回什么，在哪里汇总

处理一棵树，等于处理根、处理左子树、处理右子树。左右子树本身也是树，所以可以交给同一个函数递归处理。写这类函数时，按下面三步想：

  1. 定义返回值。用一句话说清楚：“solve(node) 返回以 node 为根的这棵子树的____”。这句话说不清楚，代码一定写不对。
  2. 写空树的出口。node is None 时应该返回什么？比如深度是 0，“是否对称”是 True。
  3. 假设左右子树已经算好，拼出当前节点的答案。不要在脑子里展开整个递归过程，只需要相信：solve(node.left) 会按第 1 步的定义返回正确的结果。
def solve(node):
    if node is None:
        return 空树对应的结果
    left_result = solve(node.left)      # 左子树的结果
    right_result = solve(node.right)    # 右子树的结果
    # ↓ 后序位置：两个孩子都已经算完，这里能同时看到 left_result 和 right_result
    return 用 left_result、right_result 和 node.val 算出的结果

为什么强调“后序位置”？因为只有在这里，左右两棵子树的信息才同时拿到了手。第 10 课讲过，后序遍历就是“先处理两个孩子，再处理自己”。很多题目问的是“某个节点下面整体是什么情况”，这种信息只能从下往上汇总，所以都写在后序位置。

按“答案放在哪里”，这一课的题可以分成三种：

类型说明本课的题
返回值就是答案递归函数的返回值直接就是题目要的东西最大深度、翻转、对称、最近公共祖先
返回值是“给父亲用的信息”，答案另外记函数返回父亲需要的东西（比如深度），题目要的答案在后序位置顺手更新到一个外部变量里直径（还有进阶题“最大路径和”）
需要从上往下传信息孩子要知道祖先给它的限制，所以把信息作为参数往下传（这是前序方向）验证二叉搜索树（传上下界）、右视图（传深度）

实战里怎么写：业务里的树长什么样

业务代码里很少见到 left / right 的二叉树，常见的是下面两种。套路完全一样，只是“两个孩子”变成了“一个 children 列表”，或者变成了“指向父亲的指针”：

场景树的样子用什么代价
评论楼中楼、菜单、目录（嵌套 JSON）：最多嵌套几层、每条下面有几条回复每个节点一个 children 列表后序递归，max(..., default=0) 处理没有孩子的情况O(n)
组织架构、地区、商品分类（数据库一行一个节点）：两个人最近的共同上级每行一个 parent_id把一方的上级链放进 set，从另一方往上走，第一个碰到的就是O(深度)，不用遍历整棵树
数据可能非常深（用户能无限回复）同上显式栈 stack = [...] 改成循环；Python 默认递归上限约 1000 层O(n)
def max_nesting_depth(comment):
    """楼中楼最多嵌套几层：本课“最大深度”的 N 叉版本。"""
    return 1 + max((max_nesting_depth(child) for child in comment["children"]), default=0)


def max_nesting_depth_iterative(comment):
    """同一件事用显式栈写，5000 层也不会 RecursionError。"""
    deepest, stack = 0, [(comment, 1)]
    while stack:
        current, depth = stack.pop()
        deepest = max(deepest, depth)
        stack.extend((child, depth + 1) for child in current["children"])
    return deepest


def lowest_common_manager(first_person, second_person, manager_of):
    """有父指针时的最近公共祖先：manager_of 是 {员工: 直属上级}，CEO 的上级是 None。"""
    ancestors_of_first = set()
    while first_person is not None:
        ancestors_of_first.add(first_person)
        first_person = manager_of[first_person]
    while second_person not in ancestors_of_first:
        second_person = manager_of[second_person]
    return second_person

两处 Python 细节：max() 遇到空的序列会抛 ValueError，max(生成器, default=0) 里的 default=0 表示“一个孩子都没有时按 0 算”（叶子节点的深度是 1，不是 1 + 0 之外的东西）；递归上限那一行说的 RecursionError，就是函数嵌套调用太深（默认约 1000 层）时 Python 抛的异常。

完整可运行的版本在 examples/tree_patterns_in_practice.py（uv run examples/tree_patterns_in_practice.py），还有一个“每条评论下有多少回复”的后序汇总。下面的题目是 LeetCode 的二叉树版本：只有父亲指向孩子、没有父指针，所以最近公共祖先要用题五的递归做法。

怎么认出这类题

  • 题目给的是一棵二叉树（root: TreeNode），问的是深度、高度、路径长度、是否平衡、是否对称、是否合法、祖先等整棵树或子树的性质：基本都是本课的递归套路。
  • 出现“任意两个节点之间”“路径不一定经过根”：答案的“最高点”可能是任何一个节点，要在每个节点的后序位置都算一次，并用一个外部变量记最大值。
  • 出现“每一层”“从右边看”“从上到下第几层”：考虑层序遍历（队列），或者递归时把深度当参数往下传。
  • 出现“二叉搜索树”“验证”“第 K 小”：利用中序遍历是有序的，或者往下传上下界。

题一：最大深度（LeetCode 104）

题意：从根走到最远的叶子，路上一共经过几个节点。例如 [3, 9, 20, None, None, 15, 7]：3 的左孩子是 9，右孩子是 20，20 下面还有 15 和 7。最长的一条是 3 → 20 → 15，经过 3 个节点，所以答案是 3。

套路怎么用：这是套路最小的例子，没有更慢的“暴力做法”可以对比，正好用来熟悉三步。

  1. 返回值：max_depth(node) 返回以 node 为根的子树有多深。
  2. 空树出口：None 的深度是 0。
  3. 拼答案：左子树深 left_depth，右子树深 right_depth，加上 node 自己这一层，就是 1 + max(left_depth, right_depth)。

为什么对：从 node 往下走的最长路线，第一步要么进左子树、要么进右子树。进了左子树之后，最多还能走 left_depth 个节点，右边同理，所以取两者的较大值再加 1。

复杂度：每个节点只被访问一次，时间 O(n)；调用栈最深等于树高 h，额外空间 O(h)。

题二：翻转二叉树（LeetCode 226）

题意：把每个节点的左孩子和右孩子对调，相当于让整棵树照镜子。例如 [4, 2, 7, 1, 3, 6, 9] 翻转后变成 [4, 7, 2, 9, 6, 3, 1]。

关键观察：“整棵树照镜子”等于“左子树照镜子、右子树照镜子，再把两棵子树换个位置”。这句话本身就是递归定义。

套路怎么用：返回值是翻转后的根；空树翻转后还是空树；在后序位置，先分别拿到翻转好的左子树 inverted_left 和右子树 inverted_right，然后令 node.left = inverted_right、node.right = inverted_left。

容易写错的地方：如果先写 node.left = invert_tree(node.right)，这一行已经把 node.left 覆盖掉了，下一行再拿 node.left 去翻转，翻的其实是刚换过来的那棵。所以要先用两个变量把结果存下来，再一起赋值。

复杂度：时间 O(n)，额外空间 O(h)。

题三：对称二叉树（LeetCode 101）

题意：判断一棵树是不是左右镜像对称。例如 [1, 2, 2, 3, 4, 4, 3] 是对称的：第二层是 2、2，第三层从左到右是 3、4、4、3。而 [1, 2, 2, None, 3, None, 3] 不对称：两个 3 都挂在右边。

直接的做法：先把树复制一份并翻转（题二），再逐个节点比较两棵树是否完全相同。这样是对的，时间也是 O(n)，但要多复制一整棵树。

关键观察：“整棵树对称”其实是在说“根的左子树和右子树互为镜像”。所以要判断的是两棵树之间的关系，递归函数要同时拿两棵树：is_mirror(left_subtree, right_subtree)。

两棵树什么时候互为镜像：

  • 两棵都是空的：是镜像。只有一棵是空的：不是。
  • 两个根的值不相等：不是。
  • 值相等时，还要求外侧一对互为镜像（左树的左孩子 ↔ 右树的右孩子），并且内侧一对也互为镜像（左树的右孩子 ↔ 右树的左孩子）。

照镜子时，左边最外面的东西对应右边最外面的东西，所以要“外侧配外侧、内侧配内侧”。最后答案是 is_mirror(root.left, root.right)，空树直接算对称。

复杂度：每对节点只比一次，时间 O(n)，额外空间 O(h)。

题四：二叉树的直径（LeetCode 543）——本课重点

题意：树里任意两个节点之间的最长路径有几条边。这条路径可以不经过根。例如 [1, 2, 3, 4, 5]：4 → 2 → 1 → 3 有 3 条边，是最长的，答案是 3。

先看任意一条路径的形状：树上的一条路径一定先往上走、再往下走，中间有一个最高点（“拐弯的那个节点”）。以节点 X 为最高点的最长路径 = 从 X 往左子树一路走到最深处 + 从 X 往右子树一路走到最深处。左边那段有 left_depth 条边（左子树有多深，就要走几条边），右边同理，所以长度是 left_depth + right_depth。

暴力做法为什么慢：既然每条路径都有一个最高点，那就把每个节点都当一次最高点：对每个节点分别调用一次 max_depth 求左右深度，取最大的 left_depth + right_depth。问题是 max_depth 每次都要把整棵子树走一遍。如果树退化成一条链，第一个节点下面有 n − 1 个节点，第二个有 n − 2 个……加起来是 O(n2)。

关键观察：求整棵树的深度时，递归本来就会在每个节点的后序位置算出 left_depth 和 right_depth。暴力做法反复算的东西，在一次深度递归里已经全部出现过了，只是我们没有利用它。

套路怎么用：递归函数仍然返回深度（因为父亲需要的是深度，不是直径），题目要的直径另外记在一个外部变量 longest_path 里：

def diameter_of_binary_tree(root):
    longest_path = 0

    def depth(node):                       # 返回以 node 为根的子树有多深
        nonlocal longest_path
        if node is None:
            return 0
        left_depth = depth(node.left)
        right_depth = depth(node.right)
        # 后序位置：以 node 为最高点的最长路径有 left_depth + right_depth 条边
        longest_path = max(longest_path, left_depth + right_depth)
        return 1 + max(left_depth, right_depth)   # 交给父亲的仍然是深度

    depth(root)
    return longest_path

为什么对：最长路径一定有一个最高点；递归会在每个节点的后序位置都算一次“以它为最高点的最长路径”；所以真正的最长路径一定被算到过，longest_path 取的是所有这些值里的最大值。

为什么返回深度而不是直径：父亲想算“以自己为最高点的路径”，只能从孩子那里接上一条往下走的直线（深度），而不能接上孩子内部那条拐了弯的路径。所以返回值和答案是两回事——这是这类题最关键、也最容易想混的地方。下面的动画里会看到：答案出现在节点 2，而不是根节点 1。

复杂度：一次递归，每个节点访问一次，时间 O(n)，额外空间 O(h)。

下面这棵树的直径是 6（8 → 6 → 4 → 2 → 5 → 7 → 9），最高点是节点 2，不经过根。点求直径，用“上一步 / 下一步”慢慢看：橙色是正在处理的节点；处理完的节点变绿，下面的蓝字是它交给父亲的返回值（深度）；下方一行记录目前找到的最长路径。最后一帧用红色标出整条直径。

题五：最近公共祖先（LeetCode 236）

题意：给出树里的两个节点 first_node 和 second_node，找出离它们最近的共同祖先。一个节点也算自己的祖先。例如在 [3, 5, 1, 6, 2, 0, 8, None, None, 7, 4] 里：5 和 1 的最近公共祖先是根 3；5 和 4 的最近公共祖先是 5（4 在 5 的下面，而 5 是它自己的祖先）。

直接的做法：先从根找到两个节点，各记下一条“从根到它”的路径，再从头比较两条路径，最后一个相同的节点就是答案。这是对的，时间 O(n)，但要走两遍、还要存路径。更慢的做法是对每个节点都检查“它的子树里是否两个都有”，最坏 O(n2)。

关键观察：从最近公共祖先往下看，两个目标节点要么分别在它的左右两侧，要么其中一个就是它自己。再往下任何一个节点，都最多只能“看到”一个目标。

套路怎么用：定义 lowest_common_ancestor(node, ...) 返回“在 node 这棵子树里找到的东西”：

  • node 是空的：什么都没找到，返回 None。
  • node 本身就是两个目标之一：返回 node，不用再往下找。
  • 否则去左右子树找，得到 found_in_left 和 found_in_right。后序位置分三种情况：两边都找到了，说明两个目标分居 node 两侧，node 就是答案，返回 node；只有一边找到了，把那一边的结果原样往上交；两边都没找到，返回 None。

为什么“遇到目标就直接返回”是对的：假设先遇到了 first_node。如果 second_node 在它下面，那么答案就是 first_node 本身，往上交它没错；如果 second_node 不在它下面，那它一定在别的分支里，会从另一侧被找到，在更高的某个节点汇合，那个节点会发现“左右都找到了”，返回自己。题目保证两个节点都在树里，所以这两种情况覆盖了全部可能。

复杂度：每个节点最多访问一次，时间 O(n)，额外空间 O(h)。

题六：右视图（LeetCode 199）

题意：站在树的右边往左看，从上到下能看到哪些节点。例如 [1, 2, 3, None, 5, None, 4] 看到的是 [1, 3, 4]。注意：看到的不一定是“右孩子”。[1, 2, 3, 4] 的第三层只有一个节点 4，它挂在左边的 2 下面，但从右边看过去，这一层没有别的东西挡住它，所以答案是 [1, 3, 4]。只沿着右孩子一路走下去是错的。

关键观察：“从右边看到的”就是每一层最右边的那个节点。题目问的是“每一层”，这正是层序遍历的信号。

做法一（层序）：和第 10 课的层序遍历一样用队列，但一次处理一整层：处理前先记下这一层有几个节点 level_size，出队 level_size 次，最后出队的那个就是这一层最右边的节点。

做法二（递归往下传深度）：递归时先走右孩子，再走左孩子，并把当前深度 depth 作为参数往下传。这样每一层第一个被访问到的节点就是最右边的那个。怎么判断“第一次到达这一层”？如果结果列表 visible_values 的长度正好等于 depth，说明这一层还没有人登记过。

复杂度：两种做法都是每个节点访问一次，时间 O(n)。

题七：验证二叉搜索树（LeetCode 98）

题意：判断一棵树是不是二叉搜索树（第 11 课）：任何节点左子树里的所有值都严格小于它，右子树里的所有值都严格大于它。

最常见的错误：只拿每个节点和它的两个孩子比。看 [5, 4, 6, None, None, 3, 7]：根 5，右孩子 6，6 的左孩子是 3。每个节点和孩子比都没问题（3 < 6），但 3 在 5 的右子树里，却比 5 小，所以这棵树不是二叉搜索树。“和孩子比”只检查了局部，而定义要求的是整棵子树。

暴力做法为什么慢：按定义硬查：对每个节点，求出左子树的最大值和右子树的最小值来比较。每次求最大最小值都要走一遍子树，最坏 O(n2)。

关键观察：换个角度，从上往下看：每个节点的值都被它所有祖先限制在一个区间里。从根往左走一步，后面所有节点都必须小于根，于是上界变成根的值；往右走一步，下界变成根的值。祖先越多，区间越窄。

套路怎么用：这题信息是从上往下流的，所以把上下界作为参数往下传：check(node, lower_bound, upper_bound) 表示“node 这棵子树里的值是否全都严格落在 (lower_bound, upper_bound) 之间”。空树返回 True；当前值不在区间里返回 False；否则检查 check(node.left, lower_bound, node.val) 和 check(node.right, node.val, upper_bound) 是否都为 True。根的区间是负无穷到正无穷（Python 里写 float("-inf") 和 float("inf")）。

为什么对：一个节点的区间，正好由“它在每个祖先的左边还是右边”决定，这和二叉搜索树的定义一一对应：在某个祖先的左子树里，就必须比那个祖先小；在右子树里，就必须比它大。

另一种做法：二叉搜索树的中序遍历是严格递增的。中序遍历时记住上一个值 previous_value，只要当前值不大于它就返回 False。

复杂度：两种做法都是时间 O(n)，额外空间 O(h)。

最近公共祖先在子树里找到的目标或答案O(n)O(h)
右视图（层序：不用递归）O(n)O(w)，w 是最宽一层的节点数
验证二叉搜索树子树是否全部落在区间内O(n)O(h)

h 是树高：树比较平衡时约为 log n，退化成一条链时是 n。

最容易错的地方

  • 直径的单位：题目数的是边，不是节点。按本课“深度 = 节点数”的定义，left_depth + right_depth 正好就是边数，不要再减 1 或加 1。
  • 直径的返回值：递归函数返回直径而不是深度，父亲就没法接着往上拼了。返回值是给父亲用的，答案另外记。
  • 右视图只走右孩子：左子树更深时，下面几层从右边看到的是左子树里的节点。
  • 验证二叉搜索树只和孩子比：必须和整条祖先链给出的上下界比。另外题目要求“严格”小于和大于，相等也不合法。
  • 翻转时先覆盖再递归：先用变量存好两个翻转结果，再一起赋值。

LeetCode 124 · 二叉树中的最大路径和

题意：二叉树中的路径是一个节点序列，序列中每对相邻节点之间都有一条边相连，同一个节点在一条路径中最多出现一次。路径至少包含一个节点，不一定经过根节点。路径和是路径上所有节点值之和。给定根节点 root，返回所有路径中最大的路径和。

例子：输入 root = [-10, 9, 20, null, null, 15, 7]（根 -10，左孩子 9 是叶子，右孩子 20 下面挂着 15 和 7），输出 42。最优路径是 15 → 20 → 7，和为 42；它不经过根，因为加上 -10 只会变小。

数据范围：节点数在 [1, 3 × 104] 之间，-1000 ≤ 节点值 ≤ 1000，节点值可以是负数。

LeetCode 235 · 二叉搜索树的最近公共祖先

题意：给定一棵二叉搜索树和树中两个不同的节点 p、q，返回它们的最近公共祖先：同时是 p 和 q 的祖先、且深度最大的节点（一个节点也可以是它自己的祖先）。

例子：输入 root = [6, 2, 8, 0, 4, 7, 9, null, null, 3, 5]，p = 2，q = 8，输出 6。这棵树的根是 6，左孩子 2（下面挂着 0 和 4，4 下面又挂着 3 和 5），右孩子 8（下面挂着 7 和 9）；2 和 8 分别在 6 的两侧，所以最近公共祖先是 6。

数据范围：节点数在 [2, 105] 之间，所有节点值互不相同，p ≠ q，且 p、q 都在树中。

LeetCode 230 · 二叉搜索树中第 K 小的元素

题意：给定二叉搜索树的根节点 root 和整数 k，返回树中第 k 小的节点值（k 从 1 开始计数）。

例子：输入 root = [3, 1, 4, null, 2]，k = 1，输出 1。这棵树的根是 3，左孩子 1，右孩子 4，1 的右孩子是 2；所有值从小到大是 1、2、3、4，第 1 小是 1。

数据范围：节点数为 n，1 ≤ k ≤ n ≤ 104，0 ≤ 节点值 ≤ 104。

练习

补全 dsa/tree_patterns.py。建议顺序：max_depth → invert_tree → is_symmetric → diameter_of_binary_tree → lowest_common_ancestor → right_side_view → is_valid_bst。建树、打印树的工具函数已经写好，不用动。写完一题就运行一次，看打印出来的「输入、期望、实际」是否一致：

uv run dsa/tree_patterns.py

自测

1. 直径那题，递归函数为什么返回深度，而不是直接返回直径？ 父亲要算“以自己为最高点的最长路径”，需要从左右孩子各接上一条一直往下走的路线，这条路线的长度就是深度。孩子内部那条拐了弯的路径，父亲接不上去。所以返回给父亲的必须是深度，直径只能在每个节点的后序位置另外比较、另外记录。
2. 最近公共祖先里，如果某个节点的左右子树各找到了一个目标，为什么它就一定是“最近”的？ 两个目标分别在它的左子树和右子树里。再往下走任意一步，只能进入其中一边，就会丢掉另一个目标，所以它下面没有任何节点同时是两个目标的祖先。它是公共祖先里最深的一个，也就是最近的。
3. 验证二叉搜索树时，为什么要把上下界往下传，而不是在后序位置汇总？ 也可以在后序位置汇总：让递归函数返回子树的最小值和最大值，父亲检查“左子树最大值 < 自己 < 右子树最小值”。这样同样是 O(n)。往下传上下界只是写起来更短。两种写法的区别在于信息的流向：一个从下往上汇总，一个从上往下限制。
