第 45 课 · 树形 DP

树形 DP 的状态定义在“以 v 为根的子树”上：先算完所有孩子，再用孩子的结果拼出 v 的结果。说白了就是第 31 课的后序位置汇总，只是每个节点要交给父亲的不止一个数。

阅读路线

阅读路线：先理解本课要解决的问题和核心模板，再看题目如何逐步套用；应用场景用于说明这个方法在真实代码里的位置，最后再做练习和自测。

开始前要会：Python —— 解包（一次返回两个数）、推导式与生成器表达式、range 倒序（本课还会用到 reversed，下面就地讲）、setdefault、类型标注；前面的课 —— 第 10 课 · 二叉树与遍历（后序）、第 31 课 · 二叉树高频题（后序位置汇总、直径）、第 13 课 · 图的表示与 BFS（邻接表）、第 5 课 · 递归（递归深度）、第 37 课 · 一维 DP（打家劫舍）。

本课一条主线：一棵 6 个节点的树。先用第 31 课的 TreeNode 二叉树形式做打家劫舍 III（题 1），再把同一棵树换成笔试常见的“节点编号 + 边列表”输入，做同一道题的一般版本（题 2）和树的直径（题 3）。

二叉树形式（层序）：[3, 4, 5, 1, 3, None, 1]
边列表形式：values = [3, 4, 5, 1, 3, 1]，edges = [(0, 1), (0, 2), (1, 3), (1, 4), (2, 5)]（节点编号按层序从 0 编起）
             节点 0（价值 3）
            /              \
     节点 1（4）          节点 2（5）
      /       \                 \
 节点 3（1） 节点 4（3）      节点 5（1）

先定义几个词

  • 子树：节点 v 和它下面所有的后代组成的那棵树，叫“以 v 为根的子树”。叶子的子树只有它自己。
  • 后序（第 10 课）：先处理所有孩子，再处理自己。只有在这个时刻，所有孩子的结果才都已经算好。
  • 树形 DP：状态写成 dp[v] 或 dp[v][几种情况]，代表“以 v 为根的子树”的某个最优值；转移只用 v 的孩子的状态；按后序（自底向上）计算。答案通常在根上，或者是所有节点里的最大值。

和第 31 课的关系：第 31 课的递归函数每个节点只返回一个数（深度、是否对称……）。树形 DP 常常要返回几个数，因为父亲做决定时，需要知道孩子在不同情况下的结果（比如“孩子被选”和“孩子没被选”）。

应用场景：父子表 + 倒序处理

业务里的树很少是 left / right，常见的是“每条记录有一个父亲”：组织架构（每人一个上级）、目录（每个目录一个父目录）、评论楼中楼。典型需求是自底向上汇总：

场景每个节点算什么从孩子那里要什么
目录占用空间（du 命令）这个目录连同子目录的总大小每个子目录的总大小
团建邀请：直属上下级不能同时来邀请 / 不邀请这个人时，他这一支的最大开心值每个下属的两种结果
机房网线连成一棵树，最远的两台机器往下最远能走几根网线每个孩子往下最远的距离

组织架构、目录可能很深，所以业务代码一般不用递归：先从根出发得到一个“父亲总在孩子前面”的顺序，再倒着处理，孩子就总在父亲之前算好：

def folder_sizes(parent_of, own_size):            # parent_of[目录] = 父目录，根的父目录是 None
    children = {}
    for folder, parent in parent_of.items():
        if parent is None:
            root = folder
        else:
            children.setdefault(parent, []).append(folder)

    order = [root]
    for folder in order:                          # 一边遍历一边往后追加：从根开始的 BFS 顺序
        order.extend(children.get(folder, []))

    total = {}
    for folder in reversed(order):                # 倒过来：孩子一定先算好
        total[folder] = own_size[folder] + sum(total[child] for child in children.get(folder, []))
    return total

folder_sizes({"/": None, "/home": "/", "/var": "/"}, {"/": 1, "/home": 30, "/var": 12})
# {'/var': 12, '/home': 30, '/': 43}

两处 Python 细节：for folder in order 的循环体里往 order 末尾追加元素，循环会继续走到这些新元素，所以这一个循环就完成了从根开始的 BFS（效果和第 13 课用 deque 的队列写法一样，只是用过的元素不弹出）；reversed(order) 从最后一个元素往前遍历列表，不复制列表，和 order[::-1] 的顺序一样。

完整可运行的版本在 examples/tree_dp_in_practice.py（uv run examples/tree_dp_in_practice.py），包括团建邀请名单和最远的两台机器。下面按题讲原理。

题 1：打家劫舍 III（LeetCode 337）

题意：房子连成一棵二叉树，有边直接相连的两间房子（父子）不能在同一晚都偷。最多能偷多少？

例子：上面那棵树，偷节点 1 和节点 2（4 + 5 = 9）最多。偷根再偷三个孙子只有 3 + 1 + 3 + 1 = 8。

回顾第 37 课：一排房子的打家劫舍，每间房子只有“偷 / 不偷”两种选择，不偷时左边那间随意，偷时左边那间不能偷。树上一样，只是“左边那一间”变成了“所有孩子”。

直接写递归为什么慢：最直接的想法是 rob(node) = max(偷 node + 四个孙子的 rob, 两个孩子的 rob)。算 rob(根) 时要算孙子的 rob；算 rob(孩子) 时又要算这些孙子的 rob。同一棵子树被算了好几遍，越往下重复越多。

关键观察：父亲做决定时，只需要知道每个孩子在两种情况下的结果：“孩子被偷时孩子这棵子树最多多少”和“孩子没被偷时最多多少”。那就让每个节点一次返回这两个数，每棵子树只算一遍。

套四步法（第 37 课）：

  1. 状态：对每个节点 v，take_this = 偷 v 时，以 v 为根的子树最多偷多少；skip_this = 不偷 v 时最多偷多少。
  2. 转移：偷 v，两个孩子都不能偷：take_this = v.val + left_skip + right_skip。不偷 v，每个孩子偷不偷随意，各取大的：skip_this = max(left_take, left_skip) + max(right_take, right_skip)。
  3. 初始值：空树返回 (0, 0)。
  4. 遍历顺序：后序，先递归算两个孩子，再算自己。答案是根的两个数里大的。
def rob_tree(root):
    def best_pair(node):                     # 返回 (偷 node 时的最大值, 不偷 node 时的最大值)
        if node is None:
            return 0, 0
        left_take, left_skip = best_pair(node.left)
        right_take, right_skip = best_pair(node.right)
        take_this = node.val + left_skip + right_skip
        skip_this = max(left_take, left_skip) + max(right_take, right_skip)
        return take_this, skip_this

    return max(best_pair(root))

在例子上从下往上算：三个叶子 (1, 0)、(3, 0)、(1, 0)；节点 1 偷 = 4 + 0 + 0 = 4，不偷 = 1 + 3 = 4；节点 2 偷 = 5，不偷 = 1；根偷 = 3 + 4 + 1 = 8，不偷 = max(4, 4) + max(5, 1) = 9。答案 9。下面动画的第一个按钮就是这个过程。

为什么对：以 v 为根的子树里的任何一种偷法，v 要么被偷、要么没被偷。被偷时孩子都不能偷，两个孩子的子树又互不影响，各自取“不偷孩子”的最优；没被偷时孩子不受限制，各自取两种里的最优。两种情况都考虑了，所以不会漏。

复杂度：每个节点只访问一次，O(n) 时间；递归深度是树高 h，额外空间 O(h)。

笔试里的树：边列表、邻接表、递归深度

笔试（尤其是 ACM 模式）很少给 TreeNode，通常这样给一棵树：第一行 n，下面 n − 1 行每行两个编号 a b，表示 a 和 b 之间有一条边。边没有方向，也不说谁是父亲。处理分三步：

  1. 建邻接表（第 13 课）：adjacency[v] = 和 v 相连的所有节点。边没有方向，所以 a 记进 b 的列表，b 也记进 a 的列表。
  2. 自己选根、定父子：通常选 0（或题目说的 1）当根。从根出发 BFS，第一次走到一个节点时，记下是从哪个节点走过来的，那就是它的 parent。之后遍历邻居时，跳过 parent，剩下的就是孩子；不跳过会走回头路。
  3. 注意递归深度：n 常常到 105，如果树退化成一条长链，递归要嵌套 105 层，超过 Python 默认约 1000 层的上限，抛 RecursionError（第 5 课）。调大上限（sys.setrecursionlimit）在一些环境里会直接把程序撑崩，最稳的是不递归：BFS 得到的顺序里父亲总在孩子前面，倒着处理这个顺序，就是自底向上。
def children_first_order(node_count, edges, root=0):
    adjacency = [[] for _ in range(node_count)]
    for first, second in edges:                 # 边没有方向，两头都记
        adjacency[first].append(second)
        adjacency[second].append(first)
    parent = [-1] * node_count
    parent[root] = root                         # 根的父亲记成自己，表示“已经走到过”
    order = [root]
    for node in order:                          # BFS：一边遍历一边追加
        for neighbor in adjacency[node]:
            if parent[neighbor] == -1:
                parent[neighbor] = node
                order.append(neighbor)
    return adjacency, parent, order             # reversed(order) 就是“孩子总在父亲前面”

后面两题都用这个模板。倒着处理 order 时，节点 v 的孩子就是 adjacency[v] 里不等于 parent[v] 的那些。

题 2：同一道题换成边列表（没有上司的舞会）

题意：n 个节点，values[v] 是节点 v 的价值，edges 是 n − 1 条边。有边相连的两个节点不能都选，选出的价值总和最大是多少？这道题有个有名的说法叫“没有上司的舞会”：公司的上下级关系是一棵树，直属上下级不能同时来，求来的人开心值总和最大。和题 1 的区别只有两点：输入是边列表；每个节点的孩子可以不止两个。

例子：values = [3, 4, 5, 1, 3, 1]，edges = [(0, 1), (0, 2), (1, 3), (1, 4), (2, 5)]，就是主线那棵树，答案 9。

套四步法：

  1. 状态：take[v] = 选 v 时以 v 为根的子树的最大总和；skip[v] = 不选 v 时的最大总和。
  2. 转移：对 v 的每个孩子 child，take[v] += skip[child]，skip[v] += max(take[child], skip[child])。
  3. 初始值：take[v] = values[v]，skip[v] = 0（还没加任何孩子时）。
  4. 遍历顺序：倒着处理 BFS 顺序。答案是 max(take[0], skip[0])。
def max_non_adjacent_total(values, edges):
    if not values:
        return 0
    adjacency, parent, order = children_first_order(len(values), edges)
    take = list(values)
    skip = [0] * len(values)
    for node in reversed(order):                 # 孩子一定先算好
        for child in adjacency[node]:
            if child != parent[node]:
                take[node] += skip[child]
                skip[node] += max(take[child], skip[child])
    return max(take[0], skip[0])

复杂度：建邻接表 O(n)，BFS O(n)，倒序处理时每条边看两次，总共 O(n) 时间、O(n) 空间，没有递归。

题 3：树的直径（LeetCode 1245）

题意：n 个节点、n − 1 条边的树，最远的两个节点之间有几条边？

例子：主线那棵树，节点 3 → 1 → 0 → 2 → 5 有 4 条边，是最长的，答案 4。

回顾第 31 课：二叉树的直径。每条路径都有一个最高点，以 v 为最高点的最长路径 = 往左走到最深 + 往右走到最深。递归函数返回深度，答案另外记。

推广到一般的树：孩子可以有很多个。以 v 为最高点的路径，最多从两个孩子方向往下走（一条路径经过 v 时，只能从一边进、另一边出）。所以要找最深的两个孩子方向。

套四步法：

  1. 状态：deepest[v] = 从 v 只往下走（走向孩子），最多能走几条边。叶子是 0。
  2. 转移：每个孩子 child 方向能走 deepest[child] + 1 条边。deepest[v] 取其中最大的；同时用最大的两个之和更新答案 longest（只有一个孩子时第二大算 0）。
  3. 初始值：deepest[v] = 0，longest = 0。
  4. 遍历顺序：倒着处理 BFS 顺序。答案是 longest，不是 deepest[0]。
def tree_diameter(node_count, edges):
    if node_count <= 1:
        return 0
    adjacency, parent, order = children_first_order(node_count, edges)
    deepest = [0] * node_count
    longest = 0
    for node in reversed(order):
        first, second = 0, 0                     # 最深和第二深的孩子方向
        for child in adjacency[node]:
            if child != parent[node]:
                depth = deepest[child] + 1
                if depth > first:
                    first, second = depth, first
                elif depth > second:
                    second = depth
        deepest[node] = first                    # 交给父亲的是一条往下的直线
        longest = max(longest, first + second)   # 以 node 为最高点的最长路径
    return longest

为什么对：和第 31 课一样。最长路径一定有一个最高点（离根最近的那个节点），处理到这个节点时，它的两段分别落在两个不同的孩子方向里，长度都不会超过那个方向的最深值，而最深的两个方向之和正好能取到。所以 longest 一定会被更新成答案。

复杂度：O(n) 时间、O(n) 空间。

另一种写法：两次 BFS。从任意节点 BFS 找到最远的节点 A，再从 A 出发 BFS 找到最远的节点 B，A 到 B 就是一条直径。要输出具体路径时这种写法更顺手（examples/tree_dp_in_practice.py 里用的就是它）。但它只适用于边权都非负的直径，树形 DP 的写法能推广到更多题。

怎么认出这类题

  • 输入是一棵树（n 个点、n − 1 条边、连通，或者给了每个点的父亲），问最大 / 最小 / 方案数。
  • “相邻的不能同时选”“每个点要被覆盖”“选一些点使……”：每个节点要区分几种情况（选 / 不选、被覆盖 / 没被覆盖），返回多个数。
  • “最长路径”“最远的两个点”：最高点 + 最深的两个方向。
  • “每个子树的……”：后序汇总。

LeetCode 124 · 二叉树中的最大路径和

题意：二叉树中的路径是一串节点，相邻两个节点之间有边相连，同一个节点最多出现一次；路径至少含一个节点，不一定经过根。路径和是路径上节点值的总和。返回所有非空路径中的最大路径和。

例子：输入 root = [-10, 9, 20, null, null, 15, 7]，即根 -10 的左孩子是 9，右孩子是 20，20 的左右孩子是 15 和 7；输出 42，最优路径是 15 → 20 → 7。

数据范围：节点数 ≤ 3 × 104，-1000 ≤ 节点值 ≤ 1000（可以是负数）。

LeetCode 968 · 监控二叉树

题意：在二叉树的节点上安装摄像头，每个摄像头能监视它所在的节点、它的父节点和它的直接子节点。返回监视所有节点所需的最少摄像头数量。

例子：输入 root = [0, 0, null, 0, 0]，即根只有左孩子，这个左孩子有两个孩子；输出 1，摄像头装在根的左孩子上，就能同时监视根和它的两个孩子。

数据范围：节点数 ≤ 1000，节点值都是 0。

LeetCode 2246 · 相邻字符不同的最长路径

题意：一棵 n 个节点的树，根是节点 0，用数组 parent 表示，parent[i] 是节点 i 的父节点，parent[0] = -1。字符串 s 的 s[i] 是节点 i 的字符。返回最长路径的长度，要求路径上任意相邻的两个节点字符不同。这里路径长度是路径上的节点数，不是边数。

例子：输入 parent = [-1, 0, 0, 1, 1, 2]，s = "abacbe"，即边 0–1、0–2、1–3、1–4、2–5，字符依次是 a、b、a、c、b、e；输出 3，最长路径是 3 → 1 → 0（c、b、a）。0 和 2 都是 a，所以路径不能经过边 0–2。

数据范围：n ≤ 105，s 只含小写字母。

LeetCode 834 · 树中距离之和

题意：一棵 n 个节点（编号 0 到 n − 1）的无向树，edges 是边列表。返回长度为 n 的数组 answer，answer[i] 是节点 i 到其他所有节点的距离（边数）之和。

例子：输入 n = 6，edges = [[0, 1], [0, 2], [2, 3], [2, 4], [2, 5]]，输出 [8, 12, 6, 10, 10, 10]。以节点 0 为例：到 1、2 的距离各是 1，到 3、4、5 的距离各是 2，和为 1 + 1 + 2 + 2 + 2 = 8。

数据范围：n ≤ 3 × 104。

最容易错的地方

  • 邻接表只记了一个方向：边没有方向，a 和 b 要互相记。
  • 遍历邻居时没跳过父亲：会把父亲当成孩子，结果翻倍甚至死循环。
  • 递归写法在长链上 RecursionError：笔试里 n 上万就用 BFS 顺序倒着处理。
  • 直径返回了 deepest[0]：那只是从根往下的最长直线。答案是所有节点里“最深两个方向之和”的最大值。
  • 打家劫舍 III 写成“偷根就偷所有孙子”：不偷孩子时，孙子也可以不偷。用两个状态就不会想错。
  • 节点编号从 1 开始的题目，列表开 n + 1 个，或者读入时统一减 1。

练习

补全 dsa/tree_dp.py。建议顺序：build_adjacency_list → rob_tree → max_non_adjacent_total → tree_diameter。动手前，先用一句话写下每个节点要交给父亲哪几个数。

uv run dsa/tree_dp.py
uv run pytest tests/test_tree_dp.py

测试会拿你的结果和暴力枚举（所有选法、每个点 BFS 一遍）比对，还会用 2 万个节点的长链检查你没有用递归。

自测

1. 打家劫舍 III 为什么每个节点要返回两个数，一个不够吗？ 只返回“这棵子树最多偷多少”时，父亲不知道这个最优值是不是偷了孩子本身。父亲想偷自己，就必须知道“不偷孩子时孩子子树最多多少”。所以要把两种情况分开返回。
2. 边列表给出的树，为什么倒着处理 BFS 顺序就是自底向上？ BFS 从根开始，一个节点只有在它的父亲被处理之后才会被加进 order，所以 order 里父亲总在孩子前面。倒过来，孩子就总在父亲前面，处理父亲时所有孩子都已经算好了，效果和后序遍历一样，但没有递归。
3. 树的直径为什么要记“最深的两个”孩子方向，而不是“最深的一个”？ 以 v 为最高点的路径从一个孩子方向上来、经过 v、再从另一个孩子方向下去，长度是两个方向之和。只记最深的一个，就只能算出从 v 往下的直线，漏掉拐弯的路径。交给父亲的仍然只是最深的一个（deepest[v]），因为父亲只能从 v 接一条往下的直线。
