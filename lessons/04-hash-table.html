第 4 课 · 哈希表（拉链法）

哈希表 = 数组 + 链表：用哈希函数把 key 算成一个下标，直接跳到那一格；同一格装不下的，就挂成一串。

开始前要会：Python —— Counter、defaultdict、get、推导式、继承 MutableMapping、魔法方法、异常约定（KeyError）、@property 与 @dataclass、functools.cache、global、生成器；前面的课 —— 第 0 课 · 复杂度（“平均 O(1)”的伏笔在这里揭晓）、第 1 课 · 动态数组（翻倍扩容、均摊）、第 2 课 · 链表（拉链法的“链”）。

实战里怎么写：dict、set 和它们的亲戚

dict 和 set 就是哈希表，业务代码里没人另造一个。要会的是按场景挑对工具：

场景用什么代价
按 key 查 / 改dict平均 O(1)
计数、取前几名collections.Counter 的 most_common(k)计数 O(n)
分组collections.defaultdict(list)每条 O(1)，不用先判断 key 在不在
去重、判断“见没见过”、交并差set平均 O(1)
缓存函数结果functools.cache（用法见预备课）底层就是 dict，参数当 key
自定义对象当 key@dataclass(frozen=True)自动生成 __hash__ 和 __eq__

表里有几个预备课没讲的小东西，先说清楚用法：

  • hash(x) 是内置函数，把一个值算成一个整数：同样的值一定算出同样的整数，hash(42) == 42，hash("ab") 是一个很大的整数。list、dict、set 这类可变的值不能算，hash([1]) 抛 TypeError: unhashable type，所以它们不能当 dict 的 key、不能放进 set（为什么，见文末自测 1）。
  • @dataclass(frozen=True)：和普通 @dataclass 一样，但对象建好后字段不能再改（改了抛异常），于是 Python 敢替它生成 __hash__，它就能当 key 了。
  • set 之间可以做集合运算：a - b 是在 a 不在 b 的，a & b 是两边都有的，a | b 是合起来的。
from collections import Counter, defaultdict

access_log = [("alice", "/home"), ("bob", "/cart"), ("alice", "/cart"), ("alice", "/home")]

Counter(path for _, path in access_log).most_common(1)   # [('/home', 2)]

pages_by_user = defaultdict(list)
for user, path in access_log:
    pages_by_user[user].append(path)                     # 第一次出现自动建空列表

visitors = {user for user, _ in access_log}              # 去重：{'alice', 'bob'}

类比：按姓氏分的储物柜

一排柜子，按名字首字母放东西。找“张三”不用一个个翻，直接去 Z 柜。Z 柜里有好几个人（冲突）？没关系，柜子里挨个看就行，人不多，很快。

长什么样

[0]→8: a→4: c
[1]→5: b
[2]→空
[3]→空

4 个桶。下标 = hash(key) % 桶数：8 和 4 除以 4 都余 0，冲突了，于是挂在 0 号桶的同一条链上。

三步走：读、写、删都一样

手写版做成一个和 dict 用法一样的 HashMap。table[key] 的实现：

def __getitem__(self, key):
    bucket_index = hash(key) % len(self._buckets)   # ① 算下标，O(1)
    for stored_key, value in self._buckets[bucket_index]:   # ② 在这个桶的链上挨个比 key
        if stored_key == key:
            return value                             # ③ 找到了就返回
    raise KeyError(key)                              # 和 dict 一样，找不到抛 KeyError

table[key] = value（动画里的 put）和 del table[key]（remove）也是这三步，只是第 ③ 步换成改值或删掉这一对。

只要每条链都很短，第 ② 步就是常数时间，整体平均 O(1)。

链怎么保持很短：负载因子 + 扩容

负载因子 = 元素个数 / 桶数。超过 0.75 就把桶数翻倍，然后每个 key 重新算下标、搬进新桶，这叫 rehash。 桶数变了，% 桶数 的结果也变了，所以不能整条链原样搬过去。和动态数组一样，搬家 O(n)，但翻倍让它均摊下来还是 O(1)。

操作平均最坏（所有 key 撞进同一个桶）
读 / 写 / 删（put / get / remove）O(1)O(n)
扩容 rehashO(n)，但很少发生，均摊 O(1)

动手玩

建议依次试试：put(9)，9 % 4 = 1，看它和 5 撞在一个桶；再把 key 改成 6 点 put，第 4 个元素让负载因子变成 1.00，看扩容和 rehash 一个个搬；最后 get 一个不存在的 key。

最容易错的三个地方

  • 给已存在的 key 赋值，要覆盖 value，不能再挂一个，size 也不变。
  • rehash 时要按新桶数重新算下标，不能直接把旧链复制过去。
  • key 不存在时，table[key] 和 del table[key] 都要抛 KeyError，和 dict 一样。in 和 get 是靠接住这个 KeyError 实现的，抛错了别的异常它们就坏了。

练习

补全 dsa/hash_table.py 里的 HashMap。它继承 collections.abc.MutableMapping：你只写 __setitem__、__getitem__、__delitem__、__iter__，get、pop、setdefault、in、items()、== 都是 Python 自动送的，写完就能像 dict 一样直接用。

建议顺序：_index → __setitem__（先不管扩容）→ __getitem__ → __delitem__ → __iter__ → _resize，最后在 __setitem__ 里接上扩容。

自测

1. 为什么 dict 的 key 必须是不可变的（比如不能用 list）？ key 放进去时按当时的 hash 选了桶。如果之后 key 变了，hash 也变了，再查就会去错的桶，永远找不到它。
2. 负载因子阈值设成 0.1 或 10 会怎样？ 0.1：链极短，但九成的桶空着，浪费内存。10：省内存，但每条链平均 10 个，查找变慢。0.75 是两者的折中。
3. 哈希表能按 key 从小到大遍历吗？ 不能高效做到。key 被打散到各个桶里，顺序和大小无关。（Python 的 dict 遍历是按插入顺序，不是按大小。）要按大小有序，现在可以用 sortedcontainers.SortedDict（用法见预备课）；它为什么能一直有序，第 11 课的二叉搜索树会讲。
