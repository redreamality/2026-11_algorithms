第 26 课 · 滑动窗口

滑动窗口 = 用两个同方向走的下标框住一段连续区间，右边界负责把新元素放进来，左边界负责把旧元素请出去。枚举所有子串或子数组要 O(n²)，滑动窗口只要 O(n)。

先理解窗口 通用模板 如何识别 逐题套用 题单与练习

开始前要会：Python —— enumerate、dict 的 setdefault / get、推导式、类与 __init__、类型标注（dict[str, ...]）；前面的课 —— 第 3 课 · 栈与队列（deque）、第 4 课 · 哈希表（用 dict 计数）、第 25 课 · 双指针（两个下标同方向走、不回头）。

先看本课的阅读顺序

先把“窗口”想成一段连续的内容，再记住右边扩张、左边收缩的模板。之后遇到每道题，只需要回答三个问题：窗口里要维护什么？什么时候不合法？答案应该在收缩前还是收缩后记录？

实战里怎么写：先看真实代码里的滑动窗口

真实项目里最常见的是“按时间滑动的窗口”：限流、移动平均、最近 N 条日志、近 7 天销售额。几乎都用标准库 collections.deque，它两端进出都是 O(1)（list.pop(0) 是 O(n)，不要用）。

场景用什么代价
限流：任意 60 秒内同一用户最多 N 次请求deque 存请求时间：右边 append 新请求，左边 popleft 过期的每次请求均摊 O(1)，空间 O(N)
只保留最近 N 条（最近错误、最近读数）deque(maxlen=N)，满了自动从左边挤掉最旧的O(1)
移动平均、近 k 天的滚动和维护窗口和：进一个加、出一个减总共 O(n)；每次重新 sum 窗口是 O(n·k)
from collections import deque

class RateLimiter:
    """滑动时间窗口限流：任意 window_seconds 秒内，同一个用户最多 max_requests 次。"""

    def __init__(self, max_requests: int, window_seconds: float) -> None:
        self.max_requests = max_requests
        self.window_seconds = window_seconds
        self._request_times: dict[str, deque[float]] = {}

    def allow(self, user_id: str, now: float) -> bool:
        request_times = self._request_times.setdefault(user_id, deque())
        while request_times and request_times[0] <= now - self.window_seconds:
            request_times.popleft()        # 收缩：过期的请求移出窗口
        if len(request_times) >= self.max_requests:
            return False
        request_times.append(now)          # 扩张：新请求放进窗口
        return True

recent_errors = deque(maxlen=100)          # maxlen=N：最多存 N 条，满了再 append 就自动从左边挤掉最旧的

完整可运行的版本在 examples/sliding_window_in_practice.py（uv run examples/sliding_window_in_practice.py），还有移动平均和滚动和的例子。限流器里“右边进、左边出、每个元素只进出一次”，正是下面面试题用的同一个模板。

窗口是什么

窗口就是数组（或字符串）里连续的一段，用 window_start 和 window_end 两个下标表示，两端都包含。窗口只会做两种动作：

  • 扩张：window_end 右移一格，把一个新元素放进窗口。
  • 收缩：window_start 右移一格，把最左边的元素移出窗口。
text = "abcabcbb"： abcabcbb window_start = 1，window_end = 3，窗口是 "bca"

它是上一课“快慢指针”的近亲：两个下标同方向走，都不回头。不同的是，滑动窗口关心的是两个下标之间的整段内容，所以通常要额外维护一份“窗口里有什么”的统计，比如窗口里的字符集合、每个字符的个数、窗口里数字的和。每次扩张或收缩时，只更新进来或出去的那一个元素，统计就保持正确，不用重新扫一遍窗口。

通用模板

window_start = 0
for window_end in range(len(items)):
    把 items[window_end] 加进窗口的统计
    while 窗口需要收缩:
        （如果求“最短”，在这里先记录答案）
        把 items[window_start] 从窗口的统计里去掉
        window_start += 1
    （如果求“最长”，在这里记录答案）

求最长和求最短的写法刚好相反，这是本课最需要记住的一点：

要求什么时候收缩在哪里记录答案本课例题
最长的合法窗口窗口不合法了，收缩到重新合法为止收缩完以后（这时窗口一定合法）无重复字符的最长子串
最短的合法窗口窗口合法的时候，尽量收缩，看还能不能更短收缩循环里面，每次收缩之前最小覆盖子串、长度最小的子数组

为什么是 O(n)：内层有一个 while，看起来像两层循环，但 window_start 从头到尾只往右走，整个过程中加起来最多走 n 步。所以每个元素最多进窗口一次、出窗口一次，总共 2n 次操作，时间 O(n)。

什么时候不能用：滑动窗口依赖一个前提，就是“窗口扩张时，状态只会往一个方向变”。比如数组全是正数时，窗口越长和越大；收缩一定让和变小。如果数组里有负数，加进一个数和可能反而变小，“该不该收缩”就判断不了，这时要换用下一课的前缀和。

怎么认出这类题

  • 题目里出现“连续子数组”“子串”（注意不是“子序列”，子序列可以不连续，通常是动态规划）。
  • 要找最长 / 最短的、满足某个条件的连续一段，或者要数满足条件的段有多少个。
  • 条件是“不含重复”“包含某些字符”“和至少为某个数”“最多有 k 个某种元素”这类，并且窗口变长时条件只会越来越难满足（或越来越容易满足）。
  • 题目给了固定长度 k，问“每个长度为 k 的连续段”怎么样。这是固定大小的窗口：右边进一个，左边就出一个。

第 1 题：无重复字符的最长子串（求最长）

题意：给一个字符串，找出其中不含重复字符的最长子串，返回它的长度。子串必须连续。

例子："abcabcbb" 返回 3，最长的是 "abc"。"pwwkew" 返回 3，最长的是 "wke"；"pwke" 虽然也没有重复，但它在原串里不连续，是子序列不是子串。

暴力做法为什么慢：枚举每个起点，从起点往右一个个加字符，遇到重复就停。起点有 n 个，每个起点最多往右走 n 步，O(n²)。

关键观察：假设从起点 2 出发，一直走到下标 5 时遇到了重复。暴力做法接下来会从起点 3 重新出发，把 3、4 这些字符再检查一遍。但其实我们已经知道 3 到 4 这一段没有重复，没必要重查。只需要把左边界往右挪，挪到把那个重复的字符挤出窗口为止，然后继续往右扩张。

怎么用上滑动窗口：用一个集合 characters_in_window 记录窗口里有哪些字符。

  1. window_end 往右走一格，新字符是 character。
  2. 如果 character 已经在集合里，窗口就不合法了。不断把 text[window_start] 移出集合、window_start 右移，直到 character 不在集合里。
  3. 把 character 加进集合。此时窗口一定没有重复，用窗口长度 window_end - window_start + 1 更新答案。
characters_in_window = set()
window_start = 0
longest_length = 0
for window_end, character in enumerate(text):
    while character in characters_in_window:          # 有重复，收缩
        characters_in_window.remove(text[window_start])
        window_start += 1
    characters_in_window.add(character)
    longest_length = max(longest_length, window_end - window_start + 1)

为什么是对的：对每一个 window_end，收缩完以后的窗口是“以 window_end 结尾的、最长的无重复子串”。为什么是最长：window_start 只在窗口里有重复时才右移，而且挪到刚好没有重复就停。答案子串一定以某个位置结尾，所以把每个 window_end 的最长值取最大，就是答案。

复杂度：window_start 和 window_end 各走一遍，时间 O(n)；集合最多装下所有不同的字符，空间 O(字符种类数)。

第 2 题：最小覆盖子串（求最短）

题意：给字符串 source 和 target，在 source 里找最短的连续子串，使 target 里的每个字符都被包含，重复的字符要包含同样多次。找不到返回空字符串。

例子：source = "ADOBECODEBANC"，target = "ABC"，返回 "BANC"。"ADOBEC" 也包含 A、B、C，但它长 6，"BANC" 只长 4。再比如 target = "AA"，窗口里就必须有两个 A。

暴力做法为什么慢：枚举所有子串 O(n²) 个，每个再检查是否覆盖 target，更慢。

关键观察：如果窗口 [window_start, window_end] 已经覆盖了 target，那么往右再加字符一定还覆盖，但只会更长，没有意义。有意义的是试着把左边界往右挪，看看去掉左边的字符后是否还覆盖。一旦不覆盖了，就只能继续扩张右边界。

怎么用上滑动窗口：判断“窗口是否覆盖 target”如果每次都重新数一遍，就又变慢了。所以维护两样东西：

  • need_count：一个 dict，need_count[character] 表示窗口里还差几个这个字符。一开始等于 target 里每个字符的个数。字符进窗口就减 1，出窗口就加 1。变成负数表示窗口里这个字符多了，多出来的不影响覆盖。
  • missing_count：窗口里总共还差几个字符，一开始等于 len(target)。只有当进来的字符“正好是还缺的”（进来之前 need_count[character] > 0）时才减 1。missing_count == 0 就表示窗口已经覆盖了 target，判断是 O(1)。
need_count = {}                                   # target 里每个字符需要几个
for character in target:
    need_count[character] = need_count.get(character, 0) + 1
missing_count = len(target)
window_start = 0
best_start, best_length = 0, None
for window_end, character in enumerate(source):
    if need_count.get(character, 0) > 0:         # 进来的是还缺的字符
        missing_count -= 1
    need_count[character] = need_count.get(character, 0) - 1
    while missing_count == 0:                     # 已经覆盖，尽量收缩
        window_length = window_end - window_start + 1
        if best_length is None or window_length < best_length:
            best_start, best_length = window_start, window_length
        removed_character = source[window_start]
        need_count[removed_character] += 1
        if need_count[removed_character] > 0:     # 移出去以后又缺了
            missing_count += 1
        window_start += 1

用例子走一遍：右边界一路走到下标 5（"ADOBEC"）时第一次覆盖 A、B、C，记录长度 6。左边界移出 A 后又缺 A，停止收缩。右边界继续走，走到下标 10 的 A 才再次覆盖（"DOBECODEBA"），这时左边界可以一路收缩：D、O 是多余的字符，B 移出后窗口里还有下标 9 的 B，E、C 也移出……直到移出下标 5 的 C 又缺 C。最后右边界走到下标 12 的 C，再次覆盖并收缩，得到 "BANC"。下面的动画把每一步都画了出来。

为什么是对的：对每一个 window_end，收缩循环会把左边界推到“再推一格就不覆盖”的位置，所以在这个右边界下，记录到的就是最短的覆盖窗口。答案一定以某个位置结尾，因此也一定被记录过。

复杂度：两个下标各走一遍 source，加上统计 target，时间 O(len(source) + len(target))；dict 的大小是 O(字符种类数)。

第 3 题：长度最小的子数组（求最短）

题意：数组 numbers 里都是正整数。找出和大于等于 target 的最短连续子数组，返回它的长度，不存在返回 0。

例子：target = 7，numbers = [2, 3, 1, 2, 4, 3]，返回 2，因为 [4, 3] 的和是 7。[2, 3, 1, 2] 的和是 8 也满足，但它长 4。

暴力做法为什么慢：枚举每个起点，往右累加直到和够了。O(n²)。

关键观察：所有数都是正数，所以窗口变长和一定变大，变短和一定变小。窗口的和已经够了，再往右扩张只会更长，没有意义；应该从左边收缩，看看更短的窗口是否也够。

window_start = 0
window_sum = 0
shortest_length = None
for window_end, number in enumerate(numbers):
    window_sum += number
    while window_sum >= target:                   # 和够了，记录答案并收缩
        window_length = window_end - window_start + 1
        if shortest_length is None or window_length < shortest_length:
            shortest_length = window_length
        window_sum -= numbers[window_start]
        window_start += 1
return shortest_length or 0

为什么是对的：和第 2 题相同，对每个右边界，收缩循环找到的是以它结尾、和够了的最短窗口。如果数组里有负数，这个推理就不成立了：收缩时去掉一个负数，和反而变大，可能错过更短的答案。

复杂度：时间 O(n)，额外空间 O(1)。

动手玩

三个按钮各演示一道题。蓝色格子是当前窗口，橙色是这一步刚进来或刚出去的元素，绿色是到目前为止找到的最好答案。建议先看 无重复最长子串，留意窗口什么时候收缩；再看 最小覆盖子串，对照下方“还差的字符”一栏，看 missing_count 是怎么变成 0、又是怎么变回 1 的。

最容易错的地方

  • 求最长时把记录答案写在收缩循环里面，或者求最短时写在外面。回到上面的表格：最长在收缩之后记录，最短在收缩之前记录。
  • 收缩用 if 而不是 while：一次可能要移出好几个元素才能让窗口重新合法（例如 "abcb" 遇到第二个 b 时要移出 a 和 b）。
  • 最小覆盖子串里，missing_count 不管三七二十一每进一个字符都减 1。只有进来的是“还缺的”字符才减，多出来的同种字符不算。
  • 窗口长度写成 window_end - window_start，少了 1。两端都包含时长度是 window_end - window_start + 1。
  • 在有负数的数组上用滑动窗口找“和为某值”的子数组。负数会破坏“窗口越长和越大”的前提，要换用第 27 课的前缀和。

练习

补全 dsa/sliding_window.py。建议顺序：min_subarray_length（最简单，只维护一个和）→ longest_substring_without_repeat → min_window_substring。每写完一个函数，运行下面的命令，看每个例子的“期望”和“实际”是否一致：

uv run dsa/sliding_window.py

都通过之后，再去 LeetCode 上做上面表格里的题，特别是 438 和 567，它们和最小覆盖子串几乎是同一个模板。

自测

1. 内层有 while 循环，为什么总时间还是 O(n)？ 因为 window_start 只往右走、从不回头，整个过程中加起来最多走 n 步。内层 while 的执行次数不是“每次外层都可能跑 n 次”，而是“所有外层加起来一共最多 n 次”。外层 n 次加内层总共 n 次，是 O(n)。
2. 第 1 题能不能让 window_start 直接跳过去，而不是一格一格挪？ 可以。用 dict 记录每个字符最后一次出现的下标 last_index_by_character。遇到重复字符时，window_start 直接跳到 max(window_start, last_index_by_character[character] + 1)。要取 max，是因为那个下标可能已经在窗口左边了（例如 "abba" 遇到第二个 a 时）。复杂度仍然是 O(n)，只是常数小一些。
3. 如果 numbers 里有负数，长度最小的子数组还能用滑动窗口吗？ 不能。窗口和够了以后收缩，去掉的可能是负数，和反而变大，“收缩到不够为止”的推理不成立。这种情况要用到后面几课的工具：前缀和（第 27 课）加单调队列（后面会见到），对应 LeetCode 862，和至少为 K 的最短子数组。
