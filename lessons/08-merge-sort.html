第 8 课 · 归并排序

对半分，两半各自排好，再像拉拉链一样合并。分到只剩 1 个时，它自己就是有序的。

问题直觉 核心定义与不变量 通用操作模板 题目与动画 应用场景 易错点与练习

开始前要会：Python —— 生成器（yield、iter、next）、yield from、类型标注（Iterable、Iterator）、itertools.islice、切片与 extend、f-string；前面的课 —— 第 5 课 · 递归与分治（归并排序是典型的分治）、第 7 课 · 简单排序（稳定性）、第 0 课 · 复杂度。

问题直觉：为什么先拆开再合并

直接在一整段乱序数据里找位置很难；把数组拆成小段后，每段都能先变成有序，再用一次线性扫描合成结果。归并排序的关键收益来自“合并两个有序段”很容易。

核心定义与不变量：合并时两边都已排序

合并过程的不变量是：输出区始终有序，且两边输入指针之前的元素都已经被取走。递归出口是长度 0 或 1，因为它天然有序。

核心是“合并”

想象桌上两叠已经从小到大排好的牌。每次只看两叠最上面那张，拿走小的放到新的一叠。某一叠拿光了，另一叠剩下的直接整叠放上去。

a：146 　b：237
结果：1234 ← 4 < 7，取 4

每个元素只被拿一次，所以合并长度共 n 的两段是 O(n)。

通用操作模板：先拆，再合

def merge(left, right):
    """两个有序列表合并成一个新列表。相等时先取 left 的，排序才稳定。"""
    merged = []
    left_index = right_index = 0
    while left_index < len(left) and right_index < len(right):
        if right[right_index] < left[left_index]:
            merged.append(right[right_index])
            right_index += 1
        else:
            merged.append(left[left_index])
            left_index += 1
    merged.extend(left[left_index:])     # 剩下的那一段直接接上
    merged.extend(right[right_index:])
    return merged

def merge_sort(items):
    if len(items) <= 1:                 # 出口：0 或 1 个，天然有序
        return list(items)
    middle = len(items) // 2
    left = merge_sort(items[:middle])
    right = merge_sort(items[middle:])
    return merge(left, right)

练习里的 merge 更进一步：和 heapq.merge 一样用 iter() / next() 一个个取、用 yield 产出，这样传进来的是文件或生成器也能合并。

为什么是 O(n log n)

每次对半切，切 log n 层就只剩 1 个。每一层的所有合并加起来，正好把 n 个元素各过一遍，是 O(n)。所以总共 O(n log n)。

归并排序插入排序（上一课）
最好 / 平均 / 最坏都是 O(n log n)O(n) / O(n²) / O(n²)
额外空间O(n)，合并要一个新数组O(1)
稳定是是

它的优点是稳：不管输入长什么样都是 O(n log n)。代价是要额外 O(n) 的空间。Python 的 sorted 用的 Timsort 就是归并排序加插入排序的改良版。

应用场景：有序日志、外部排序与惰性合并

sorted() 用的 Timsort 本身就是归并排序的改良版，不用自己写。归并的思想真正派上用场，是合并已经有序的数据：

合并这件事标准库里有现成的：heapq.merge(序列1, 序列2, …, key=…)。把任意多个已经排好序的序列传给它，它就按从小到大的顺序逐个产出，边读边出、不用全部装进内存。reverse=True 表示输入和输出都是从大到小。它内部用「堆」实现——堆是第 12 课的主角，这里先当现成工具用。

场景用什么代价
几台服务器的日志各自有序，合成一份时间线heapq.merge(*files, key=...)O(n log k)，k 路；惰性，每路同时只读一行
数据大到内存放不下外部排序：切块 sorted 后写临时文件，再 heapq.mergeO(n log n)，内存只要一块
两个小列表合并后要有序sorted(a + b)Timsort 认得出两段有序区，接近 O(n)
import heapq

# 两个日志文件各自按时间排好序
with open("server_a.log") as server_a, open("server_b.log") as server_b:
    for line in heapq.merge(server_a, server_b, key=lambda line: line[:5]):
        print(line, end="")

题目与动画

先点 merge_sort 看完整过程：上半段是拆分树，下半段从底往上合并，i、j 是两边的指针，淡掉的是已经取走的。默认数组里有两个 2，留意它们相遇时取的是哪一边。也可以自己输入数组，或者点 随机一组。

易错点与练习

  • 只有右边严格更小才取右边，相等时先取左边，排序才稳定。
  • 循环结束后，剩下的那一段别忘了接上（迭代器版本用 yield from）。
  • 不要用 pop(0) 从列表头部取数：每次都是 O(n)，整个排序就退化了。
  • 带 key 时别在每次比较里都调用 key：先把 (key, 元素) 配成对，比较 key，最后再把元素取出来。

练习

补全 dsa/merge_sort.py。接口和标准库一致：merge(left, right, *, key, reverse) 像只合并两路的 heapq.merge，返回惰性迭代器；merge_sort(iterable, *, key, reverse) 像 sorted()，返回新列表。建议顺序：merge → merge_sort → 加上 key、reverse。学有余力再做 count_inversions（衡量两份排名的分歧）：在从右边取元素时顺手计数。

uv run dsa/merge_sort.py               # 合并两个日志文件、按销量排商品的端到端例子
uv run pytest tests/test_merge_sort.py

自测

1. 为什么切成两半之后，递归到 1 个就可以停？ 只有 0 或 1 个元素的列表本来就是有序的，不用排。合并就从这些最小的有序段开始。
2. 数组已经排好序了，归并排序会更快吗？ 基本不会，还是 O(n log n)：它照样拆、照样合并。插入排序这时只要 O(n)，反而更快。
3. 额外的 O(n) 空间花在哪了？ 合并时要把结果写进一个新数组，不能在原地边比边放，否则会覆盖还没比较的元素。
