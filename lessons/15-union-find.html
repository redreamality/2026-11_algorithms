第 15 课 · 并查集

并查集只回答一个问题：这两个是不是一伙的？支持“把两伙合成一伙”和“查是不是一伙”，两件事都近似 O(1)。

实战里怎么写：复制一个二十行的小类

标准库没有并查集，但它短到不值得引第三方库，实际项目里就是自己写一个小类。parent 用 dict，元素直接用业务里的东西（邮箱、设备 ID、(行, 列)），不用先编号成 0..n-1。

场景用什么代价
账号合并、相似记录去重聚类dict 版并查集每次操作近似 O(1)
网络里加一根线会不会成环、Kruskal 判环union 返回 False 就是成环近似 O(1)
要拆分，或要知道“怎么连上的”不适合，改用图 + BFS（第 13 课）O(V + E)
class DisjointSet:
    def __init__(self):
        self.parent = {}
        self.size = {}

    def find(self, element):
        self.parent.setdefault(element, element)      # 第一次见到就自成一组
        self.size.setdefault(element, 1)
        root = element
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[element] != root:           # 路径压缩
            self.parent[element], element = root, self.parent[element]
        return root

    def union(self, a, b):
        root_a, root_b = self.find(a), self.find(b)
        if root_a == root_b:
            return False                              # 本来就是一伙
        if self.size[root_a] < self.size[root_b]:     # 小树挂到大树下
            root_a, root_b = root_b, root_a
        self.parent[root_b] = root_a
        self.size[root_a] += self.size[root_b]
        return True

# 账号合并：同一条注册记录里的邮箱属于同一个人
emails = DisjointSet()
for addresses in [["ann@work.example.com", "ann@home.example.com"],
                  ["ann@home.example.com", "ann.lee@example.com"]]:
    for address in addresses:
        emails.union(addresses[0], address)
emails.find("ann.lee@example.com") == emails.find("ann@work.example.com")   # True

完整可运行的版本（账号合并、找出机房里多余的网线）在 examples/union_find_in_practice.py（uv run examples/union_find_in_practice.py）。下面一步步看为什么这么写。

类比：问老大

每个人只记一件事：我的上级是谁。想知道自己属于哪一伙，就一路往上问，问到“上级是自己”的那个人，他就是这伙的老大（根）。两个人老大相同，就是一伙的。

长什么样：一个 parent 数组 = 一片森林

读法：2 → 1 → 0，0 指向自己，是根；4 → 3，3 是根。所以有两个集合 {0, 1, 2} 和 {3, 4}。

两个操作

def find(element):                    # 一路往上走到根
    while parent[element] != element:
        element = parent[element]
    return element

def union(a, b):                      # 把一个根挂到另一个根下面
    root_a, root_b = find(a), find(b)
    if root_a == root_b:
        return False                  # 本来就是一伙
    parent[root_b] = root_a
    return True

上图用 list 是为了画起来直观；实际写成 dict（parent = {"ann": "ann", "bob": "ann"}）道理完全一样，元素就不必是 0..n-1 了。

合并只改一个指针，不用搬任何元素。慢的地方在 find：树要是长成一条长链，就得走 O(n) 步。

两个优化：让树一直很矮

  • 按大小合并：总是把小树的根挂到大树的根下面。这样树高最多 O(log n)。
  • 路径压缩：find 找到根以后，把路上经过的每个点都直接指向根。下次再查，一步就到。
def find(element):
    root = element
    while parent[root] != root:           # 第一趟：找到根
        root = parent[root]
    while parent[element] != root:        # 第二趟：沿途全改成指向根
        parent[element], element = root, parent[element]
    return root

用两趟循环而不是递归：一条 20 万长的链，递归写法会超过 Python 的递归深度。

复杂度

做法find / union
什么优化都不做最坏 O(n)
只按大小合并O(log n)
两个都做O(α(n))，α 增长极慢，实际不超过 5，当成 O(1)

动手玩

先连点几次 union（比如 0,1 → 2,3 → 1,3），看小树怎么挂到大树下；再点长链 + find(4)，用“上一步 / 下一步”看路径压缩怎么把一条链拍扁。橙色箭头是刚改过的指针。

最容易错的地方

  • union 时挂的是根：要写 parent[root_b] = root_a，不是 parent[b] = a。
  • a、b 本来就在一起时，集合数不能减，size 也不能加。
  • size 只在根上有意义；查 x 的集合大小，要先 find 到根。

练习

补全 dsa/union_find.py。parent 是 dict，元素可以是任何可哈希的东西；union 碰到新元素自动加进来，find 碰到没见过的元素抛 KeyError，和 dict 一样。建议顺序：add → find（先写不压缩的，跑通后再加压缩）→ union → connected → size_of → groups（把所有元素按根分组）。

自测

1. 并查集能“拆开”一个集合吗？ 不能。它只支持合并，拆分要重建。需要拆的场景得换别的结构。
2. 怎么用并查集判断无向图里有没有环？ 逐条看边 (u, v)：如果 u、v 已经 connected，这条边就连成了环；否则 union(u, v)。
3. 数一张无向图有几个连通块，最快怎么写？ UnionFind(所有节点)，每条边 union 一次，最后 set_count 就是答案。
