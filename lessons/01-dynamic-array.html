第 1 课 · 动态数组

数组是一排连续的格子，所以按下标取数很快；“动态”的意思是：格子不够时，换一排更大的。

为什么按下标取数是 O(1)

格子连续、大小一样，第 i 格的位置可以直接算出来：起点 + i × 格子大小。不用从头数。

7394 ·· size = 4，capacity = 6，arr[2] 一步就到

size 是装了几个，capacity 是一共有几个格子。

满了怎么办：搬家

原地没法加长，只能新开一排两倍大的格子，把旧的逐个搬过去：

满了： 1234
搬家后： 1234 5···

搬家这么贵，append 怎么还算 O(1)？

搬一次家要 O(n)，但是搬完以后，接下来 n 次 append 都不用再搬。把这次搬家的成本平摊到这 n 次上，每次只多出 O(1)。 这叫均摊 O(1)。

关键在于翻倍。如果每次只多加 10 个格子，几乎每加 10 个元素就要搬一次家，append 就退化成 O(n) 了。

插入和删除中间元素：O(n)

在中间插入，后面所有元素都要往右挪一格，给它腾地方：

1★2 →3 →4 → insert(1, ★)

挪的时候要从最后一个开始往右搬，否则会把还没搬的元素盖掉。删除正好反过来：从被删的位置开始，把右边的逐个往左搬。

小结

操作复杂度
按下标读 / 写O(1)
末尾 append / pop均摊 O(1)
中间 insert / removeO(n)

Python 的 list 就是这样实现的。所以 list.insert(0, x) 很慢，要在头部频繁增删，就用 collections.deque。

自测

1. 从空数组开始连续 append 9 次，capacity 依次变成多少？ 1, 2, 4, 4, 8, 8, 8, 8, 16。测试里检查的就是这个序列。
2. 写好 insert 以后，append 能不能直接写成一行？ 能：self.insert(len(self), value)。复用写好的代码，可以少一处出 bug 的地方。
3. 思考：如果 pop 到只剩一半就把容量缩一半，会出什么问题？ 刚好在临界点上反复 append、pop，就会不停地扩容、缩容，每次都是 O(n)。常见的做法是降到 1/4 才缩一半。
