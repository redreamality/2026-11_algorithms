第 1 课 · 动态数组

数组是一排连续的格子，所以按下标取数很快；“动态”的意思是：格子不够时，换一排更大的。

先理解 核心对象 模板与不变量 应用场景 练习与自测

开始前要会：Python —— 魔法方法（__getitem__、__len__、__eq__、NotImplemented）、继承 collections.abc、@property、异常约定（IndexError）与 pytest.raises、切片与 range 步长、多重赋值、f-string 的 !r；前面的课 —— 第 0 课 · 复杂度。

先理解：连续格子解决什么问题

如果经常按位置读取、在末尾追加，连续格子能让读取直接跳到目标位置；代价是中间插入时必须搬动后面的元素。

核心对象：size、capacity 与下标

为什么按下标取数是 O(1)

格子连续、大小一样，第 i 格的位置可以直接算出来：起点 + i × 格子大小。不用从头数。

7394 ·· size = 4，capacity = 6，arr[2] 一步就到

size 是装了几个，capacity 是一共有几个格子。

模板与不变量：扩容、追加、搬移

满了怎么办：搬家

原地没法加长，只能新开一排两倍大的格子，把旧的逐个搬过去：

满了： 1234
搬家后： 1234 5···

搬家这么贵，append 怎么还算 O(1)？

搬一次家要 O(n)，但是搬完以后，接下来 n 次 append 都不用再搬。把这次搬家的成本平摊到这 n 次上，每次只多出 O(1)。 这叫均摊 O(1)。

关键在于翻倍。如果每次只多加 10 个格子，几乎每加 10 个元素就要搬一次家，append 就退化成 O(n) 了。

插入和删除中间元素：O(n)

在中间插入，后面所有元素都要往右挪一格，给它腾地方：

1★2 →3 →4 → insert(1, ★)

挪的时候要从最后一个开始往右搬，否则会把还没搬的元素盖掉。删除正好反过来：从被删的位置开始，把右边的逐个往左搬。

应用场景：直接用 list

Python 的 list 就是动态数组，业务代码里没人另造一个。要会的是什么时候 list 合适、什么时候换别的：

场景用什么代价
末尾追加、按下标读写list 的 append、items[i]均摊 O(1) / O(1)
头部频繁增删（任务队列）数据少时 list 也行；数据多时换第 3 课会讲的 dequelist.insert(0, x)、del items[0] 是 O(n)，原因见下文
拼一大段文本先 append 进 list，最后 "\n".join(lines)整体 O(总长度)
分批处理（每 500 条写一次库）切片 rows[start:start + 500]每批 O(批大小)
def build_csv(rows):
    lines = ["name,score"]
    for name, score in rows:
        lines.append(f"{name},{score}")      # 均摊 O(1)
    return "\n".join(lines)                  # 一次性拼接

rows = [("Ann", 90)] * 1200
batches = [rows[start:start + 500] for start in range(0, len(rows), 500)]   # 三批：500、500、200

recent_pages = []                            # 只留最近 3 条
for page in ["首页", "搜索", "商品", "购物车"]:
    recent_pages.append(page)
    if len(recent_pages) > 3:
        del recent_pages[0]                  # 删开头要把后面全部左移，O(n)；这里 n = 3，无所谓
print(recent_pages)                          # ['搜索', '商品', '购物车']

动手玩

建议依次试试：

  1. 连点几次 append，看满了以后怎么搬家。
  2. 点几次 连续 append 8 次，盯住底下的“平均每加一个搬几次”：它总是小于 2，这就是均摊 O(1)。
  3. 把 i 设成 0，点 insert(i)，数一数挪了几次。

小结

操作复杂度
按下标读 / 写O(1)
末尾 append / pop均摊 O(1)
中间 insert / removeO(n)

Python 的 list 就是这样实现的。所以 list.insert(0, x) 很慢。要在头部频繁增删、数据又多，就得换一种结构，第 3 课会讲的 collections.deque 就是为此而生的，这里先不展开。

练习与自测

练习

补全 dsa/dynamic_array.py 里的 DynamicArray，写完它就能像 list 一样用：arr[-1]、del arr[0]、x in arr、for x in arr。规则写在文件顶部，最重要的一条：_data 只能用下标读写，不许对它调用 append。

它继承 collections.abc.MutableSequence：你只写 __getitem__、__setitem__、__delitem__、insert，append、pop、remove、extend、index、in 都是 Python 自动送的。比如送的 append(value) 就是 self.insert(len(self), value)；动画里的 remove_at(i) 对应的就是 del arr[i]。

建议顺序：_check_index（负下标换成正的，越界抛 IndexError）→ __getitem__ / __setitem__ → _resize → insert → __delitem__。

uv run dsa/dynamic_array.py               # 播放列表的端到端例子，逐条打印期望和实际
uv run pytest tests/test_dynamic_array.py

自测

1. 从空数组开始连续 append 9 次，capacity 依次变成多少？ 1, 2, 4, 4, 8, 8, 8, 8, 16。测试里检查的就是这个序列。
2. 为什么这个 DynamicArray 不用自己写 append？ MutableSequence 送的 append 就是 self.insert(len(self), value)。在末尾插入不用挪元素，所以仍然是均摊 O(1)。复用写好的代码，可以少一处出 bug 的地方。
3. 思考：如果 pop 到只剩一半就把容量缩一半，会出什么问题？ 刚好在临界点上反复 append、pop，就会不停地扩容、缩容，每次都是 O(n)。常见的做法是降到 1/4 才缩一半。
