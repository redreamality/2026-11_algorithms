第 42 课 · 树状数组（Fenwick Tree）

树状数组 = 把前缀和拆成几块提前存好，每一块的长度由下标的 lowbit 决定。改一个数只要更新 O(log n) 块，求前缀和只要加 O(log n) 块。它解决的是第 27 课前缀和“数组一改就要重算”的问题。

开始前要会：Python —— 类与 __init__、__len__、__getitem__、__setitem__、raise IndexError、推导式（dict 推导式）、set、enumerate、SortedList；前面的课 —— 第 27 课 · 前缀和（prefix_sum[count] 的含义、区间和 = 两个前缀和相减）、第 39 课 · 位运算（&、number & -number 只留下最低位的 1）、第 41 课 · 差分数组（区间加只改两格；本课沿用它的主线例子）、第 6 课 · 二分查找（实战里的 bisect_right）。

为什么需要它

第 27 课的前缀和数组，查一段的和是 O(1)，但数组里改一个数，它后面所有的前缀和都要跟着改，一次 O(n)。不存前缀和、直接用原数组呢？改一个数 O(1)，查一段的和又变成 O(n)。两头总有一头慢：

存什么改一个数求前 count 个数的和
原数组O(1)O(n)
前缀和数组（第 27 课）O(n)O(1)
树状数组O(log n)O(log n)

改和查交替出现很多次时（例如每天的销售额会被事后修正，报表又要随时查区间合计），两边都是 O(log n) 的树状数组最划算。第 41 课最后说的“改和查交替进行”，也是用它解决。

类比：公司按部门汇总报销。如果只存每个人的金额，老板问“前 7 个人一共多少”就要一个个加；如果只存“前 i 个人的累计”，有一个人改了金额，后面所有累计都要重算。折中的办法是每个组长记自己组的小计，大组长再记几个小组的合计：改一个人，只要通知他头上那几层组长；问前 7 个人的总数，只要找几位组长把小计报上来。树状数组就是按照二进制规则把“组”分好的这样一套小计。

实战里怎么写

Python 标准库里没有树状数组。实际项目里有两种做法：

场景用什么代价
数组会改，还要反复查前缀和 / 区间和就地写一个二十行的 FenwickTree 类（下面这段）改、查都是 O(log n)
只关心“比我大的有几个”“我排第几”sortedcontainers.SortedList：add 加入，bisect_right 数个数（预备课讲过）加入、查询都约 O(log n)
class FenwickTree:
    """对外下标从 0 开始，内部 tree 从 1 开始编号。"""

    def __init__(self, size: int) -> None:
        self._tree = [0] * (size + 1)

    def add(self, index: int, delta: int) -> None:
        position = index + 1
        while position < len(self._tree):
            self._tree[position] += delta
            position += position & -position      # 往上跳：加上 lowbit

    def prefix_sum(self, count: int) -> int:
        """前 count 个数的和。"""
        total = 0
        while count > 0:
            total += self._tree[count]
            count -= count & -count               # 往下跳：减去 lowbit
        return total

完整可运行的版本在 examples/fenwick_tree_in_practice.py（uv run examples/fenwick_tree_in_practice.py）：一个能事后修正某天销售额的报表、一个“比我分数高的有几个人”的排行榜，以及用树状数组和 SortedList 两种写法数逆序对。这段代码只有两个循环，但每一行为什么这么写，要读完下面三节才能看懂。下面各节和练习里的 FenwickTree 构造时直接传入整个数组（FenwickTree(numbers)），其余和这段一样。

先定义 lowbit

位置 position 的 lowbit，是 position 的二进制里最低位的那个 1 单独拿出来所代表的数。第 39 课讲过它的写法：

def lowbit(position):
    return position & -position

lowbit(6)    # 6 = 0b110，最低位的 1 在第 1 位，返回 0b10 = 2
lowbit(8)    # 8 = 0b1000，返回 8
lowbit(7)    # 7 = 0b111，返回 1

为什么 position & -position 正好是它：第 39 课说过 ~a == -a - 1，也就是 -a == ~a + 1。以 6 为例：~6 把每一位翻过来，末尾原来的 0 变成 1、最低位的 1 变成 0：…1001；再加 1，末尾那串 1 进位变回 0，进位停在原来最低位的 1 那里：…1010。这时只有“最低位的 1”那一位和 6 相同，更高的位全和 6 相反，“与”一下就只剩这一位：0110 & …1010 = 0010。

lowbit 一定是 2 的幂（1、2、4、8……）。奇数的 lowbit 都是 1。

树状数组存的是什么

沿用第 41 课的主线例子 numbers = [3, 1, 4, 1, 5, 9, 2, 6]，n = 8。

树状数组内部有一个长度 n + 1 的 list tree，从 1 开始编号（tree[0] 不用）。为了和 Python 的下标区分，下面把从 1 开始的编号叫做位置：numbers[index] 在位置 index + 1。规则只有一条：

tree[position] = 位置 position - lowbit(position) + 1 到 position 这一段的和

也就是说，tree[position] 管着以 position 结尾、长度为 lowbit(position) 的一段。我们说 tree[position] 管辖这一段。

查前缀和：往下跳，每次减 lowbit

prefix_sum(count) 和第 27 课的 prefix_sum[count] 意思一样：前 count 个数的和，也就是位置 1 到 count 的和。以 prefix_sum(7) 为例：

  1. 从位置 7 开始。tree[7] 管位置 7～7，先拿上它。还剩位置 1～6 没算。
  2. 7 - lowbit(7) = 6。tree[6] 管位置 5～6，拿上。还剩 1～4。
  3. 6 - lowbit(6) = 4。tree[4] 管位置 1～4，拿上。
  4. 4 - lowbit(4) = 0，停。

结果是 tree[7] + tree[6] + tree[4] = 2 + 14 + 9 = 25，验算 3 + 1 + 4 + 1 + 5 + 9 + 2 = 25。

def prefix_sum(self, count):
    total = 0
    position = count
    while position > 0:
        total += self.tree[position]
        position -= lowbit(position)        # 跳到“还没算的那一段”的结尾
    return total

为什么拼起来不重不漏：tree[position] 管辖的那一段，左端是 position - lowbit(position) + 1。拿完它之后，还没算的正好是位置 1 到 position - lowbit(position)，下一步就从这里接着拿，一段紧挨着一段，直到 0。

为什么是 O(log n)：减去 lowbit 就是把二进制最低位的 1 去掉（和第 39 课的 n & (n - 1) 效果一样）。7 = 111 → 6 = 110 → 4 = 100 → 0，每跳一次少一个 1。count 的二进制最多有 log2 n + 1 个 1，所以最多跳这么多次。

单点加：往上跳，每次加 lowbit

add(index, delta) 把 numbers[index] 加上 delta。要更新的是所有管辖范围包含这个位置的 tree 格子。以 add(4, 3) 为例（下标 4 就是位置 5，numbers[4] 从 5 变成 8）：

  1. 从位置 5 开始。tree[5] 管 5～5，加 3，变成 8。
  2. 5 + lowbit(5) = 6。tree[6] 管 5～6，包含位置 5，加 3，变成 17。
  3. 6 + lowbit(6) = 8。tree[8] 管 1～8，包含位置 5，加 3，变成 34。
  4. 8 + lowbit(8) = 16 > n，停。

对照上面的图：包含位置 5 的横条只有 tree[5]、tree[6]、tree[8] 三条，一条不多、一条不少。

def add(self, index, delta):
    position = index + 1                    # 下标换成位置
    while position <= len(self):
        self.tree[position] += delta
        position += lowbit(position)        # 跳到“下一个包含我的、更宽的段”

为什么加 lowbit 就是下一个包含它的段：直观地看，position + lowbit(position) 会让最低位的 1 进位，lowbit 至少翻一倍，管辖的段向左延伸，正好把当前这一段整个盖住。图上看就是：从一条横条往上，找到第一条“罩住它”的横条。严格的证明不要求掌握。

为什么是 O(log n)：每跳一次 lowbit 至少翻倍，从 1 翻到超过 n 最多 log2 n + 1 次。

建树：最简单的做法是 tree 全 0，然后对每个下标调用一次 add(index, numbers[index])，一共 O(n log n)。（选做：从位置 1 到 n 扫一遍，每格把自己的值加到 position + lowbit(position) 那一格，O(n) 建完。）

区间查询

和第 27 课一模一样：下标 left 到 right（两端都包含）的和，等于“前 right + 1 个”减“前 left 个”：

def range_sum(self, left, right):
    return self.prefix_sum(right + 1) - self.prefix_sum(left)

add(4, 3) 之后，range_sum(2, 5) = prefix_sum(6) - prefix_sum(2) = 26 - 4 = 22，验算 4 + 1 + 8 + 9 = 22。两次前缀和查询，仍然是 O(log n)。单个数 numbers[index] 就是 range_sum(index, index)；把它改成 value，就是 add(index, value - 当前值)。

动手玩

三个按钮。前缀和查询演示 prefix_sum(7)：从位置 7 往下跳，橙色是正在拿的格子，绿色是已经拿过的。单点加演示 add(4, 3)：从位置 5 往上跳，经过的格子都加 3；做完再查一次 prefix_sum(7)，变成 28。逆序对计数演示下面的应用，每一步用树状数组数“前面比我大的有几个”。每一帧都显示当前位置的二进制，看 lowbit 怎么变。

区间加、单点查：把差分数组放进树状数组

第 41 课的差分数组区间加是 O(1)，但查一个数要从头加，O(n)。注意“查 numbers[index]”正是“求差分数组前 index + 1 项的和”，也就是差分数组的前缀和查询。所以把差分数组存进一棵树状数组：

  • 区间加 add(left, right, delta)：差分的两次单点加，add(left, delta) 和 add(right + 1, -delta)，O(log n)。
  • 单点查 numbers[index]：差分树状数组的 prefix_sum(index + 1)，O(log n)。
class RangeAddPointQuery:
    def __init__(self, numbers):
        difference = [0] * (len(numbers) + 1)         # 第 41 课的差分数组，多一格
        previous = 0
        for index, number in enumerate(numbers):
            difference[index] = number - previous
            previous = number
        self._difference = FenwickTree(difference)

    def add(self, left, right, delta):
        self._difference.add(left, delta)
        self._difference.add(right + 1, -delta)

    def __getitem__(self, index):
        return self._difference.prefix_sum(index + 1)

用第 41 课同样的两次操作验证：add(2, 5, 2) 之后 values[5] 是 11；再 add(4, 7, 3)，values[5] 是 14，整个数组是 [3, 1, 6, 3, 10, 14, 5, 9]，和第 41 课还原出来的一样。区别是这里任何时候都能马上查，不用等所有修改做完。

典型应用：逆序对计数

逆序对：数组里一对下标 i < j，满足 numbers[i] > numbers[j]，也就是“排在前面的反而更大”。逆序对的个数衡量一个数组离“从小到大排好”有多远：排好序的数组是 0 个，倒序的数组最多，是 n(n - 1)/2 个。两个相等的数不算逆序对。

例子：[3, 1, 4, 1, 5, 9, 2, 6] 有 8 个逆序对：3 和后面的 1、1、2；4 和 1、2；5 和 2；9 和 2、6。

暴力做法为什么慢：两层循环看每一对，O(n²)，n = 105 时是 50 亿对。

关键观察：从左往右走，走到 numbers[j] 时，以它为“右边那个”的逆序对个数，就是前面已经出现过的数里，比它大的有几个。如果有一个数组 seen_count_by_value，第 v 格记“值 v 前面出现过几次”，那么：

前面比它大的个数 = 前面一共几个数 - 前面 <= numbers[j] 的个数
                 = j - (seen_count_by_value 前 numbers[j] + 1 格的和)

“前几格的和”就是前缀和查询，处理完 numbers[j] 又要在第 numbers[j] 格加 1，改和查交替出现，正好用树状数组：每个数一次查询、一次单点加，都是 O(log n)。

离散化：问题是值可能是负数，也可能大到 109，开不了那么长的数组。但我们只关心数之间的大小关系，不关心具体值。所以先把每个值换成它在“去重排序后的列表”里的下标，叫它的排名（从 0 开始）。这一步叫离散化：值换成排名以后，大小关系不变，而排名一定在 0 到 n - 1 之间。

sorted(set([3, 1, 4, 1, 5, 9, 2, 6]))     # [1, 2, 3, 4, 5, 6, 9]
rank_of = {value: rank for rank, value in enumerate(sorted(set(numbers)))}
# {1: 0, 2: 1, 3: 2, 4: 3, 5: 4, 6: 5, 9: 6}
def count_inversions(numbers):
    rank_of = {value: rank for rank, value in enumerate(sorted(set(numbers)))}
    seen = FenwickTree([0] * len(rank_of))           # 第 rank 格：这个排名出现过几次
    inversion_count = 0
    for seen_count, number in enumerate(numbers):    # seen_count 就是“前面一共几个数”
        rank = rank_of[number]
        inversion_count += seen_count - seen.prefix_sum(rank + 1)   # 前面比它大的个数
        seen.add(rank, 1)                            # 先查后记，不和自己比
    return inversion_count

为什么相等的数不会被算进去：查的是“前面 <= 它的个数”，和它相等的数被算在“不大于”这边，所以减掉以后只剩严格大于的。上表 j = 3 时前面有一个 1，它没被算作逆序对。

复杂度：离散化排序 O(n log n)，之后 n 次查询和 n 次单点加各 O(log n)，总共 O(n log n)，额外空间 O(n)。归并排序（第 8 课）在合并时顺便数也能做到 O(n log n)；树状数组的写法更短，而且同一个模板还能回答“右边比我小的有几个”（LeetCode 315）这类问题。

什么时候需要线段树

树状数组擅长“前缀能相减”的量（和、个数）。如果要查一段的最大值 / 最小值，或者要“区间加 + 区间求和”同时做又想写得直观，一般改用线段树：同样是 O(log n)，能维护的东西更多，但代码长好几倍。本课程不展开，笔试里先想树状数组，不够用再想线段树。

怎么认出这类题

  • “数组会被修改，还要反复查区间和”：树状数组（LeetCode 307）。
  • “区间加，同时随时查某个位置的值”：差分 + 树状数组。
  • “逆序对”“右边 / 左边比我小（大）的有几个”“插入时前面有几个比它小”：离散化 + 树状数组计数。
  • 值域很大但个数不多：先离散化，再把值当下标。
  • 要查区间最大 / 最小值，而且数组会改：树状数组不合适，想线段树。

LeetCode 307 · 区域和检索 - 数组可修改

题意：实现类 NumArray：构造函数 NumArray(nums) 接收整数数组；update(index, val) 把 nums[index] 改成 val（是赋值，不是加）；sumRange(left, right) 返回 nums[left] 到 nums[right] 的和（两端都包含）。

例子：nums = [1, 3, 5]，依次调用 sumRange(0, 2)、update(1, 2)、sumRange(0, 2)，返回 9、（无返回值）、8。改完后数组是 [1, 2, 5]，和为 8。

LeetCode 315 · 计算右侧小于当前元素的个数

题意：给定整数数组 nums，返回一个同样长的数组 counts，counts[i] 是 nums[i] 右侧严格小于 nums[i] 的元素个数。

例子：输入 nums = [5, 2, 6, 1]，输出 [2, 1, 1, 0]。5 的右侧有 2 和 1 比它小；2 的右侧只有 1；6 的右侧只有 1；1 的右侧没有元素。

数据范围：n ≤ 105，-104 ≤ nums[i] ≤ 104。

LeetCode 1649 · 通过指令创建有序数组

题意：从空容器 nums 开始，按顺序把 instructions 里的每个数插入 nums（插入后 nums 保持有序）。每次插入的代价是 min(nums 中严格小于它的元素个数, nums 中严格大于它的元素个数)。返回总代价对 109 + 7 取余的结果。

例子：输入 instructions = [1, 5, 6, 2]，输出 1。插入 1、5、6 时代价都是 0（前面要么没有比它小的，要么没有比它大的）；插入 2 时，比它小的有 1 个（1），比它大的有 2 个（5、6），代价 min(1, 2) = 1。

数据范围：n ≤ 105，1 ≤ instructions[i] ≤ 105。

LeetCode 493 · 翻转对

题意：给定整数数组 nums，如果 i < j 且 nums[i] > 2 × nums[j]，就称 (i, j) 是一个翻转对。返回翻转对的个数。

例子：输入 nums = [1, 3, 2, 3, 1]，输出 2。两个翻转对是下标 (1, 4) 和 (3, 4)：3 > 2 × 1。

数据范围：n ≤ 5 × 104；nums[i] 在 32 位有符号整数范围内，可以是负数，2 × nums[j] 在其他语言里会溢出。

LeetCode 370 · 区间加法（会员题）

题意：长度为 length 的数组初始全是 0。updates 里的每一项 [startIndex, endIndex, inc] 表示给下标 startIndex 到 endIndex（两端都包含）的每个元素加上 inc。执行完所有操作后，返回最终的数组。

例子：输入 length = 5，updates = [[1, 3, 2], [2, 4, 3], [0, 2, -2]]，输出 [-2, 0, 3, 5, 3]。三次操作依次得到 [0, 2, 2, 2, 0]、[0, 2, 5, 5, 3]、[-2, 0, 3, 5, 3]。

数据范围：length ≤ 105，updates 最多 104 项。

最容易错的地方

  • 从 0 开始编号：lowbit(0) = 0，position += lowbit(position) 永远停在 0，死循环。内部一定从 1 开始，对外下标进来先 + 1。
  • prefix_sum 的参数含义：本课的 prefix_sum(count) 是“前 count 个”，和第 27 课一致，所以单点值是 prefix_sum(index + 1) - prefix_sum(index)。自己写的时候先定好含义，别一会儿含、一会儿不含。
  • 两个循环的方向写反：查询往下（减 lowbit，到 0 停），修改往上（加 lowbit，超过 n 停）。可以记成“查询找前面的组长，修改通知上面的组长”。
  • __setitem__ 直接改 tree：tree[5] = 8 只改了一格，包含它的 tree[6]、tree[8] 没跟着变。改成某个值要先算出差值，再走 add。
  • 逆序对忘了离散化：值是 109 时开不了那么长的树；有负数时下标直接是负的。
  • 逆序对先记后查：会把自己算进“前面 <= 它的个数”，结果每步少 1，最后少 n。

练习

补全 dsa/fenwick_tree.py。建议顺序：lowbit → FenwickTree（先 __init__、add、prefix_sum，再其余方法）→ RangeAddPointQuery → count_inversions。后两个直接用你写好的 FenwickTree。每写完一个，跑一遍测试：

uv run pytest tests/test_fenwick_tree.py

测试会检查主线例子的 tree 每一格（[0, 3, 4, 4, 9, 5, 14, 2, 31]），对照上面的表排错；也有 10 万次操作的测试，循环次数不是 O(log n) 的写法会超时。

自测

1. n = 8 时，prefix_sum(5) 要加哪几格？add 位置 3 要改哪几格？ prefix_sum(5)：5（101）→ 4（100）→ 0，加 tree[5] + tree[4]，也就是位置 5～5 加上 1～4。add 位置 3：3（011）→ 4（100）→ 8（1000）→ 16 停，改 tree[3]、tree[4]、tree[8]。对照图上的横条检查：包含位置 3 的正是这三条。
2. 为什么树状数组适合求和，却不太适合求区间最大值？ 区间和可以用“两个前缀和相减”算出来，而最大值不能相减：知道前 7 个的最大值和前 2 个的最大值，推不出位置 3～7 的最大值。另外把某个数改小时，包含它的段的最大值也没法用“加上差值”来更新。这类需求用线段树。
3. 第 41 课的差分数组和本课的 RangeAddPointQuery，各在什么情况下更合适？ 所有区间加都做完才要结果：差分数组，每次加 O(1)，最后 O(n) 还原，总共 O(m + n)，最省事。加和查穿插出现：RangeAddPointQuery，每次都是 O(log n)；如果还用差分数组，每次查都要 O(n)。
