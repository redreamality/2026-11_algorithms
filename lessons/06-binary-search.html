第 6 课 · 二分查找

在排好序的数组里找东西：每次看正中间那个，就能扔掉一半。100 万个数，最多看 20 次。

先理解核心对象模板与不变量应用场景练习与自测

开始前要会：Python —— lambda 与 key=、切片（左闭右开）、类型标注（Callable、Sequence、X | None）、@dataclass、列表推导式、f-string 的 !r；前面的课 —— 第 0 课 · 复杂度（O(log n)）。

先理解：每次排除一半

二分查找解决的是“候选范围有序”的问题。比较中间值后，答案只能留在左半边或右半边，下一轮只继续看那一半。

应用场景：用标准库 bisect

业务代码里几乎没人手写二分，标准库 bisect 就是它，3.10 起还支持 key=：

场景用什么代价
有序列表里找位置、数个数、分档bisect.bisect_left / bisect_rightO(log n)
插入并保持有序bisect.insort；改得多就换 sortedcontainers.SortedListinsort 查 O(log n)，挪元素 O(n)
在答案上二分（第一个坏版本、最少几台机器）对 range 用 bisect_left(..., key=判断函数)判断 O(log 范围) 次
只查一次、还没排序直接 in / list.indexO(n)，比先排序 O(n log n) 划算
import bisect

# 分数分档：分数线排好序，bisect_right 告诉你落在第几档
cutoffs, grades = [60, 70, 80, 90], "FDCBA"
grades[bisect.bisect_right(cutoffs, 89)]          # 'B'

# 日志按时间排好序，取 10 点到 11 点这一段（key 作用在列表元素上，target 已经是时间）

# 第一个坏版本：range 不会真的生成一万个数，bisect 只调用 is_broken 十几次

每看一次剩一半，n 折半几次到 1，就要看几次，也就是 log₂ n。代价是：数组必须先排好序。

模板与不变量：左闭右开区间

左闭右开：一种写法用到底

二分最容易写出死循环和差一错误。办法是选定一种写法、守住一个循环不变量：答案始终在 [lo, hi) 里，lo 算、hi 不算。

def find(items, target):
    lo, hi = 0, len(items)          # [0, n)：整个数组（lo、hi 沿用 bisect 的参数名）
    while lo < hi:                  # 区间不空就继续
        middle = (lo + hi) // 2
        if items[middle] == target:
            return middle
        if items[middle] < target:
            lo = middle + 1          # middle 已经看过，从它右边开始
        else:
            hi = middle              # hi 本来就不算，所以是 middle 不是 middle - 1
    raise ValueError(f"{target!r} is not in list")   # 和 list.index 一样，找不到就抛异常

每一轮区间都严格变小，所以一定会停。下面的动画为了画面直观，找不到时显示“返回 -1”；手写版练习按 Python 的习惯抛 ValueError。

lower_bound 和 upper_bound

有重复时，“找到某一个”往往不够。更有用的问题是“第一个 ≥ target 的位置”（lower_bound，也就是 bisect_left）和“第一个 > target 的位置”（upper_bound，也就是 bisect_right）。

47779 lower_bound(7) 指向第一个 7，upper_bound(7) 指向 9；两者相减 = 7 出现了 3 次

写法几乎一样，只是找到相等的值时不停下：lower_bound 遇到 a[mid] >= target 就 hi = mid，继续往左找更早的。最后 lo == hi，就是答案。target 不存在时，它正好是“该插进去的位置”。

动手玩

建议依次试试：找 12 和找 8（看找不到时区间怎么缩成空）；值设成 7，分别点 lower_bound 和 upper_bound，比较它们停在哪；值设成 99，看 hi 一直待在“末尾”。

最容易错的三个地方

  • hi = len(a) 却写成 while lo <= hi：会越界。写法要前后一致。
  • lo = mid（忘了 +1）：只剩两个元素时 mid 就是 lo，区间不再缩小，死循环。
  • 二分不只能在数组上用。答案有单调性（前面全假、后面全真）就能二分，比如第一个坏版本、最少几台服务器、整数平方根（第一个 x * x > n 的 x 减 1）。
  • 用 key= 时，key 只作用在列表元素上，target 不会再过一遍 key：按年龄找人要传 30，不是传一个人。

练习与自测

练习

补全 dsa/binary_search.py。接口和标准库 bisect 一模一样（lo、hi、key），测试会拿随机数据和标准库逐个对比。建议顺序：bisect_left → bisect_right → index（找不到抛 ValueError）→ first_true（在答案上二分）→ isqrt（用 first_true 实现）。

uv run dsa/binary_search.py               # 成绩分档、按日期查订单、第一个坏版本、最少几台服务器
uv run pytest tests/test_binary_search.py

自测

1. 数组没排序，能用二分吗？ 不能。二分靠的是“mid 比 target 小，那它左边全都更小”。没排序，这个推理就不成立。
2. 只为了查一次，先排序（O(n log n)）再二分，划算吗？ 不划算，直接顺序查找 O(n) 更快。排一次、查很多次才划算。
3. 有序列表上要频繁插入删除，还用 bisect.insort 吗？ 不用。insort 找位置是 O(log n)，但 list 插入要把后面的元素全挪一格，O(n)。改得多就换 sortedcontainers.SortedList，增删查都约 O(log n)（第 11 课）。
