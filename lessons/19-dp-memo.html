第 19 课 · 动态规划（一）：从递归到记忆化

动态规划 = 递归 + 不做重复的事。同一个子问题只算一次，把答案记下来，下次直接查。

开始前要会：Python —— 装饰器与 functools.cache（怎么写一个装饰器见下方说明）、闭包与 nonlocal（写装饰器、记命中次数都要用）、*args 解包、dict 当缓存、math.inf、二维表推导式、NamedTuple、类型标注；前面的课 —— 第 5 课 · 递归与分治（DP 就是递归加记忆）、第 18 课 · 贪心（找零的对比）、第 0 课 · 复杂度。

先定义 两种写法 应用场景 看动画 练习与自测

先定义：状态、转移和重复子问题

动态规划先不急着写缓存。先把一个大问题拆成同类型的更小问题：用状态描述“小问题是什么”，用转移说明它怎样由更小状态得到，再给出初始值。如果这些小问题会反复出现，就值得把答案保存下来。

问题出在哪：重复计算

def fibonacci(n: int) -> int:
    if n <= 1:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

算 fib(5) 时，fib(3) 被算了 2 次，fib(2) 被算了 3 次……调用次数大约按 1.6n 增长，fib(40) 要调一亿多次。

fib(5) 调到的 n：5433222……红色是算过的又算一遍

母模板一：记忆化（自顶向下）

类比：做题时把算过的答案写在草稿纸上，再遇到同一题就直接抄。

def fibonacci(n: int, memo: dict[int, int]) -> int:
    if n <= 1:
        return n
    if n in memo:              # 查草稿纸
        return memo[n]
    memo[n] = fibonacci(n - 1, memo) + fibonacci(n - 2, memo)
    return memo[n]

fibonacci(80, {})

递归的写法几乎没变，只多了“先查、再存”两行。每个 n 只真正算一次：O(n)。@cache 做的就是这件事：把“先查、再存”包在一个装饰器里，键是参数，所以参数必须可哈希。练习里你会自己写一个同样用法的 memoize。

预备课只讲了怎么用装饰器，这里补上写一个要用到的几个写法。装饰器本身就是一个“收一个函数、返回一个新函数”的普通函数，新函数靠闭包（预备课第 15 节）记住缓存用的数据；def wrapper(*args, **kwargs) 里的 *args 把位置参数收成一个元组（第 4 节），**kwargs 同理把关键字参数收成一个 dict，调用时再写 function(*args, **kwargs) 原样摊开传回去；函数也是对象，可以往上挂属性，写完 wrapper.cache_info = 某个函数 之后，就能像 fibonacci.cache_info() 那样调。另外 from functools import wraps 后，在 def wrapper 的上一行加 @wraps(function)，会把原函数的名字和 docstring 抄到包装函数上，报错信息更好认。

母模板二：填表（自底向上）

反过来想：既然 fib(n) 只依赖更小的数，就从小往大，一格一格填满一张表。

dp =0112358 dp[6] = dp[5] + dp[4] 
def fibonacci_table(n: int) -> int:
    if n == 0:
        return 0
    dp = [0] * (n + 1)
    dp[1] = 1
    for index in range(2, n + 1):
        dp[index] = dp[index - 1] + dp[index - 2]
    return dp[n]

没有递归，不怕栈溢出。

写法时间额外空间
朴素递归O(1.6n)O(n) 调用栈
记忆化O(n)O(n) memo + 调用栈
填表O(n)O(n)，只留两个变量可降到 O(1)

DP 三问

遇到新题，先回答这三个问题，代码基本就出来了：

  1. 状态：dp[i] 代表什么？例：爬到第 i 级台阶有几种走法。
  2. 转移：dp[i] 怎么由更小的状态算出来？例：最后一步走 1 级或 2 级，dp[i] = dp[i-1] + dp[i-2]。
  3. 初始值：最小的几个状态是多少？例：dp[0] = 1（站着不动也算一种），dp[1] = 1。

应用场景：实战里怎么写一行装饰器

Python 项目里几乎没人手写 memo 字典，标准库 functools 已经做好了：

场景用什么代价 / 注意
参数种类有限的纯函数（递归求解、切词、解析）@functools.cache不限条数，内存随参数种类增长
参数无穷多（查汇率、查用户资料）@functools.lru_cache(maxsize=N)最多存 N 条，满了淘汰最久没用的
状态很多、递归很深（n 上千）改成填表，或先从小到大预热缓存默认递归上限约 1000 层，超了 RecursionError
from functools import cache, lru_cache

@cache
def fibonacci(n: int) -> int:
    return n if n <= 1 else fibonacci(n - 1) + fibonacci(n - 2)

fibonacci(80)              # 一眨眼：每个 n 只真正算一次
fibonacci.cache_info()     # CacheInfo(hits=78, misses=81, maxsize=None, currsize=81)

@lru_cache(maxsize=1024)
def exchange_rate(currency: str) -> float:
    return remote_api.fetch(currency)   # 很慢的远程调用，重复的币种直接走缓存

total = cache(sum)
total((1, 2, 3))           # 6
total([1, 2, 3])           # TypeError: unhashable type: 'list'：参数必须可哈希，list 先转 tuple

还有一条：只缓存纯函数。结果依赖当前时间、数据库这类外部状态时，缓存会一直返回旧值。完整可运行的例子（切词、带淘汰的汇率缓存、阶梯运费）在 examples/dp_memo_in_practice.py（uv run examples/dp_memo_in_practice.py）。

动手玩

建议依次试试：n = 5 点 朴素递归，看红色的重复调用；再点 记忆化，同一棵树里蓝色是“查 memo 命中”，它下面整棵子树都被剪掉了；最后点 填表。方块里的数字是 n，代表一次 fib(n) 调用。

最容易错的三个地方

  • 初始值写错：fib(0) = 0，但爬楼梯的 dp[0] = 1，凑零钱的 dp[0] = 0。每题都要重新想。
  • 表开小了：要算到 dp[n]，表的长度是 n + 1。
  • 凑零钱里“凑不出”要用一个不可能的值（比如 inf）表示，最后再换成 -1，别和 0 混了。

自测

1. 什么样的问题能用 DP？ 两个条件：大问题的答案能由同类型小问题的答案拼出来（最优子结构），而且这些小问题会反复出现（重叠子问题）。归并排序也拆小问题，但不重叠，所以不叫 DP。
2. 凑零钱 coins = [1, 3, 4]、amount = 6，贪心为什么错？ 贪心先拿最大的 4，剩 2 只能用 1 + 1，共 3 枚；最优是 3 + 3，共 2 枚。DP 把每种“最后一枚是谁”都试一遍：dp[a] = min(dp[a - c] + 1)，所以不会漏。
3. 记忆化和填表，选哪个？ 复杂度一样。记忆化好写，直接从递归改过来，只算用得到的状态；填表没有递归深度限制，也方便压缩空间。先写记忆化把思路理顺，再改成填表，是很好的练习。
