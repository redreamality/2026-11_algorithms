第 40 课 · 数论模板

笔试里的“数学题”翻来覆去就是几块模板：辗转相除求最大公约数、试除和筛法找质数、边算边取模、快速幂、用逆元代替除法、预处理阶乘算组合数。这一课用一道抽奖题把它们串起来。

开始前要会：Python —— 整数运算（//、%、大整数不溢出）、推导式、enumerate、类、异常（raise ValueError）；前面的课 —— 第 0 课 · 复杂度、第 5 课 · 递归与分治（递归快速幂）、第 39 课 · 位运算（& 1、>>）。本课用到的数学名词（质数、同余、组合数……）都在下面第一节先定义。

主线题目：幸运卡

整课只用这一道题。它是牛客、蚂蚁笔试里很典型的出法：

题意：抽奖箱里有编号 1, 2, …, 20 的 20 张卡。编号是质数的卡叫幸运卡。随机抽 2 张（不放回），两张都是幸运卡的概率是多少？答案是一个分数 P / Q，请输出 P · Q⁻¹ mod (109 + 7)。

先不管最后那句奇怪的输出格式，手算一下：

  1. 1..20 里的质数是 2、3、5、7、11、13、17、19，共 8 张幸运卡。（怎么让程序找出来：质数判断、筛法两节。）
  2. 从 20 张里选 2 张，一共 C(20, 2) = 20 × 19 / 2 = 190 种选法；从 8 张幸运卡里选 2 张，有 C(8, 2) = 8 × 7 / 2 = 28 种。（组合数怎么取模：最后一节。）
  3. 概率 = 28 / 190。分子分母同时除以最大公约数 2，约分成 14 / 95。（最大公约数怎么求：辗转相除一节。）
  4. “输出 14 · 95⁻¹ mod (109 + 7)”到底是什么意思、为什么要这样出题：取模、快速幂、逆元三节。最终答案是 242105265。

数字大一点，比如 105 张卡抽 3 张，手算就不行了，必须靠下面这些模板。

先认识几个词

下面所有的数都是非负整数。

名词定义主线里的例子
整除、因数、倍数如果 a % b == 0，就说 b 整除 a，b 是 a 的因数（也叫约数），a 是 b 的倍数190 % 2 == 0：2 是 190 的因数，190 是 2 的倍数
质数（素数）大于 1，而且因数只有 1 和它自己的数。1 不是质数；大于 1 又不是质数的数叫合数19 是质数；20 = 4 × 5 是合数
最大公约数 gcd(a, b)a 和 b 共同的因数里最大的那个gcd(190, 28) = 2
最小公倍数 lcm(a, b)a 和 b 共同的倍数里最小的正数lcm(190, 28) = 2660
模、取模a % m 叫 a 对 m 取模，m 叫模数。结果一定在 0..m-1 之间190 % 11 = 3
同余 a ≡ b (mod m)a % m == b % m，读作“a 和 b 模 m 同余”。意思是在只看余数的世界里，a 和 b 是同一个数190 ≡ 14 (mod 11)，因为两个数除以 11 都余 3
阶乘 n!1 × 2 × … × n，约定 0! = 15! = 120
组合数 C(n, k)从 n 个不同的东西里选 k 个（不管顺序）的选法数。公式 C(n, k) = n! / (k! · (n-k)!)；k > n 时为 0C(20, 2) = 190，C(8, 2) = 28

最大公约数：辗转相除法

要解决的问题：28 / 190 约分，要先知道 gcd(190, 28)。

暴力为什么慢：从 28 往下一个个试“能不能同时整除两个数”，最坏要试 min(a, b) 次。数到 1018 就试不完了。

关键观察：gcd(a, b) = gcd(b, a % b)。为什么：设 a = q·b + r（q 是商，r = a % b）。任何同时整除 a 和 b 的数 d，也整除 a - q·b = r；反过来，任何同时整除 b 和 r 的数，也整除 q·b + r = a。所以“a 和 b 的公因数”和“b 和 r 的公因数”是同一批数，最大的那个当然也一样。

一直替换下去，第二个数越来越小，变成 0 时停：gcd(a, 0) = a（任何数都整除 0）。

def gcd(first, second):
    while second:
        first, second = second, first % second
    return first

def lcm(first, second):
    if first == 0 or second == 0:
        return 0
    return first // gcd(first, second) * second     # 先除后乘，中间结果小

gcd(190, 28), gcd(28, 190), lcm(190, 28)            # (2, 2, 2660)

参数顺序反了也没关系：gcd(28, 190) 第一步 28 % 190 = 28，两个数正好换过来。

最小公倍数：lcm(a, b) = a × b / gcd(a, b)。直觉：a × b 一定是公倍数，但把两边共有的因数算了两遍，除掉一份 gcd 就是最小的。用处是通分：1/190 + 1/28 的公分母取 lcm(190, 28) = 2660。

复杂度：O(log min(a, b))。原因是 a % b 一定小于 a 的一半（b ≤ a/2 时，余数 < b ≤ a/2；b > a/2 时，余数 = a - b < a/2），所以每两步 first 至少减半。1018 级别的数也只要不到一百步。

质数判断：试除到 √n

要解决的问题：判断一张卡的编号是不是质数，比如 19。

暴力：用 2, 3, …, n-1 挨个去除，都除不尽就是质数。O(n)，判断 109 + 7 要试十亿次。

关键观察：如果 n = a × b 而且 a ≤ b，那么 a × a ≤ a × b = n，也就是 a ≤ √n。所以合数一定有一个不超过 √n 的因数。只要试到 √n，都除不尽就是质数。

以 19 为例：√19 ≈ 4.36，只试 2、3、4 —— 都除不尽，19 是质数。以 20 为例：试 2 就除尽了，20 是合数。

def is_prime(number):
    if number < 2:                       # 0 和 1 不是质数
        return False
    divisor = 2
    while divisor * divisor <= number:   # 等价于 divisor <= √number，但不用浮点数
        if number % divisor == 0:
            return False
        divisor += 1
    return True

[card for card in range(1, 21) if is_prime(card)]   # [2, 3, 5, 7, 11, 13, 17, 19]
is_prime(10**9 + 7)                                 # True，只试了约 31623 次

为什么写 divisor * divisor <= number 而不写 divisor <= number ** 0.5：** 0.5 算出来的是浮点数，数很大时有误差（见预备课 0.1 + 0.2 的例子），可能少试一个。整数乘法没有误差。

复杂度：O(√n)。

埃氏筛：一次找出 1..n 的所有质数

要解决的问题：数出 1..20（或 1..105）里一共有几张幸运卡。

用上面的 is_prime 为什么不够好：每个数各试一遍，总共 O(n√n)。n = 106 时大约 109 次，太慢。

关键观察：与其一个个“问”是不是质数，不如反过来，把合数划掉：找到一个质数 p，它的倍数 2p、3p、… 一定不是质数。从小到大做，剩下没被划掉的就是质数。这个方法叫埃拉托斯特尼筛法（简称埃氏筛）。

  1. 准备一张表 is_prime_flags，0..n 先全记成 True，再把 0 和 1 改成 False。
  2. 从 prime = 2 开始。如果 prime 还没被划掉，它就是质数，把它的倍数全划掉。
  3. 从 prime × prime 开始划：比它小的倍数 2·prime、3·prime、…、(prime-1)·prime，都有一个更小的因数，之前已经被划掉了。例如 prime = 3 时，6 已经被 2 划掉，直接从 9 开始。
  4. prime × prime > n 就可以停：再往后的数，倍数的起点都超过 n 了，什么也划不掉。这和试除到 √n 是同一个道理。

筛 1..20：prime = 2 划掉 4、6、8、…、20；prime = 3 从 9 开始，划掉 9、15（12 和 18 已经被 2 划掉）；prime = 4 已被划掉，跳过；prime = 5 时 25 > 20，停。剩下 2、3、5、7、11、13、17、19。下面「动手玩」里能一步步看。

def primes_up_to(limit):
    if limit < 2:
        return []
    is_prime_flags = [True] * (limit + 1)
    is_prime_flags[0] = is_prime_flags[1] = False
    prime = 2
    while prime * prime <= limit:
        if is_prime_flags[prime]:
            for multiple in range(prime * prime, limit + 1, prime):
                is_prime_flags[multiple] = False
        prime += 1
    return [number for number, flag in enumerate(is_prime_flags) if flag]

primes_up_to(20)            # [2, 3, 5, 7, 11, 13, 17, 19]
len(primes_up_to(10**5))    # 9592：10 万张卡里有 9592 张幸运卡

复杂度：O(n log log n)，结论记住即可：log log n 增长极慢，n = 106 时只有 3 左右，可以当成“几乎线性”。空间 O(n)。

怎么选：只判断一两个数，用试除；要 1..n 里所有质数（或者要判断很多个不超过 n 的数），先筛一次，之后查表 O(1)。

取模：为什么题目要你输出 “mod 109 + 7”

主线题的答案是 14 / 95，是个分数；换成 105 张卡抽 5 万张，分子分母都有三万多位。题目不想让你输出这种东西，于是规定：所有结果都对 MOD = 109 + 7 取模后再输出。Python 的整数不会溢出，但仍然必须照做，原因有三条：

  • 判题只认那一个整数。评测机逐字比对输出，你输出精确值就是答案错误（Wrong Answer）。分数更没法直接输出，后面会看到它在取模下怎样变成一个整数。
  • 大整数的运算不是 O(1)。两个 d 位的整数相乘，耗时随 d 增长。数越乘越长，整个程序就从 O(n) 退化成远超 O(n)。实测 105! 用大整数直接连乘要 4 秒左右，边乘边取模只要 0.03 秒，笔试时限通常是 1～2 秒。另外，Python 默认拒绝把超过 4300 位的整数转成字符串，直接 print 会报 ValueError。
  • 出题人要照顾 C++、Java。那些语言的整数是 64 位，超过约 9.2 × 1018 就溢出成错误的值。取模让每一步的数都很小，所有语言都能算。

为什么偏偏是 109 + 7：它是质数（后面求逆元要用到）；它小于 230，两个小于它的数相乘不超过 1018，在 64 位整数里放得下。另一个常见的模数 998244353 也是质数，同样的道理。

加、减、乘可以“边算边取模”

同余有一个关键性质：先取模再算，和算完再取模，结果同余。所以每一步都可以取模，让数一直保持在 0..MOD-1：

运算写法用主线数字验证（mod 11）
加(a + b) % MOD 等于 (a % MOD + b % MOD) % MOD(190 + 28) % 11 = 218 % 11 = 9；(3 + 6) % 11 = 9
乘(a * b) % MOD 等于 (a % MOD) * (b % MOD) % MOD190 × 28 % 11 = 5320 % 11 = 7；3 × 6 % 11 = 18 % 11 = 7
减(a - b + MOD) % MOD（a、b 已经在 0..MOD-1 里）(190 % 11 − 28 % 11) = 3 − 6 = −3，加 11 再取模得 8；(190 − 28) % 11 = 162 % 11 = 8
除不能直接取模，要换成乘逆元（下面讲）190 / 95 = 2；但 190 % 11 = 3，95 % 11 = 7，3 / 7 都不是整数

减法为什么要加 MOD：两个取过模的数相减，结果可能是负数（上面的 3 − 6 = −3）。C++、Java 里 -3 % 11 是 -3，输出负数就错了，所以要先加一个 MOD 变成非负再取模。在 Python 里 % 的结果和除数同号（预备课讲过），(-3) % 11 本来就是 8，不加也对；但笔试题解大多是从 C++ 改写来的，你的代码也可能要改写成别的语言，所以统一写成 (a - b + MOD) % MOD，养成习惯不会错。

主线里的用处：“抽 2 张不全是幸运卡”的概率是 1 − 14/95，取模写成 (1 - answer + MOD) % MOD。

带取模的快速幂（迭代版）

求逆元要算 95MOD−2，指数是十亿级别，乘十亿次显然不行。第 5 课写过递归快速幂：xn = (xn//2)2，n 是奇数再多乘一个 x，O(log n)。笔试里更常见的是下面这种迭代写法，再在每次乘法后取模。

关键观察：把指数写成二进制。用 mod 11 下算 79 举例：9 = 二进制 1001 = 8 + 1，所以 79 = 78 × 71。而 71、72、74、78 可以由前一个平方得到。于是从指数的最低位开始：

  • 当前位是 1（exponent & 1，第 39 课）：把当前的 base 乘进结果。
  • 不管是不是 1：base 自己平方一次（7 → 72 → 74 → 78），指数右移一位（exponent >>= 1）。
exponent（二进制）最低位base（代表）result
100117（71）1 × 7 % 11 = 7

1003（74，5 × 5 % 11 = 3）7

def mod_pow(base, exponent, modulus):
    if exponent < 0:
        raise ValueError("exponent must be >= 0")
    result = 1 % modulus              # modulus 是 1 时，任何数取模都是 0
    base %= modulus
    while exponent > 0:
        if exponent & 1:              # 当前最低位是 1
            result = result * base % modulus
        base = base * base % modulus  # base^1 → base^2 → base^4 → ...
        exponent >>= 1                # 去掉最低位
    return result

mod_pow(7, 9, 11)                     # 8
mod_pow(2, 10**18, 10**9 + 7) == pow(2, 10**18, 10**9 + 7)   # True，只循环 60 次

复杂度：O(log exponent)，循环次数等于指数的二进制位数。实战里直接写 Python 内置的 pow(base, exponent, modulus)，它就是这个算法，用 C 实现；不要写成 base ** exponent % modulus，那会先算出完整的大整数再取模，指数大了根本算不完。

乘法逆元：用乘法代替除法

定义：在模 p 下，如果 a × x ≡ 1 (mod p)，就说 x 是 a 的乘法逆元（简称逆元），记作 a−1。它的作用就像普通算术里的 1/a：除以 a，换成乘以 a−1。

例子（mod 11）：7 × 8 = 56 = 5 × 11 + 1，所以 7−1 ≡ 8 (mod 11)。

逆元什么时候存在：当且仅当 gcd(a, p) = 1（a 和 p 没有大于 1 的公因数）。p 是质数时，只要 a 不是 p 的倍数，gcd 一定是 1，逆元一定存在。这就是题目爱用质数当模数的原因。

费马小定理：p 是质数，a 不是 p 的倍数，则 ap−1 ≡ 1 (mod p)。证明不展开，用主线数字验证一下：710 = 79 × 7 ≡ 8 × 7 = 56 ≡ 1 (mod 11)，成立。

把 ap−1 拆成 a × ap−2：a × ap−2 ≡ 1，所以 ap−2 就是 a 的逆元，用快速幂 O(log p) 算出来。检查：711−2 = 79 ≡ 8 (mod 11)，正是上一节算的结果。

def mod_inverse(value, prime_modulus=10**9 + 7):
    if value % prime_modulus == 0:
        raise ValueError("value is a multiple of the modulus, no inverse")
    return mod_pow(value, prime_modulus - 2, prime_modulus)

mod_inverse(7, 11)      # 8
# Python 3.8+ 也可以写 pow(7, -1, 11)，结果一样；模数不是质数时它也能用（只要 gcd 是 1）

分数怎么取模

“输出 P · Q−1 mod MOD”的意思就是：把除以 Q 换成乘以 Q 的逆元。这样每个分数都对应 0..MOD-1 里唯一的一个整数。先在 mod 11 下手算 14 / 95：

  1. 95 % 11 = 7，7 的逆元是 8，所以 95−1 ≡ 8。
  2. 14 × 8 = 112，112 % 11 = 2。所以 14 / 95 ≡ 2 (mod 11)。
  3. 检查：把 2 乘回分母，95 × 2 = 190，190 % 11 = 3 = 14 % 11。确实“2 乘以 95 等于 14”（在只看余数的世界里）。

换成 MOD = 109 + 7 也是一样的步骤，结果是 14 * pow(95, MOD - 2, MOD) % MOD = 242105265。不约分也得到同一个数：28 · 190−1 也是 242105265，因为 28/190 和 14/95 本来就是同一个分数。所以笔试里不必先求 gcd 约分（除非题目要求输出最简分数）。

组合数 C(n, k) mod p：预处理阶乘 + 逆元

要解决的问题：C(n, k) = n! / (k! · (n−k)!)。分子分母取模后不能直接相除，要换成乘逆元：C(n, k) ≡ n! × (k!)−1 × ((n−k)!)−1。

每次现算为什么慢：算一个阶乘 O(n)，再做两次快速幂；如果题目要查很多次组合数（比如对每个 k 都要一个 C(n, k)），重复算阶乘太浪费。

做法：一次性预处理两张表，之后每次查询 O(1)。

  1. factorials[i] = i! mod p：从 factorials[0] = 1 开始，factorials[i] = factorials[i-1] * i % p。
  2. inverse_factorials[i] = (i!)−1 mod p：只对最大的 factorials[max_n] 做一次快速幂求逆元，然后从大往小推：inverse_factorials[i-1] = inverse_factorials[i] * i % p。为什么：1 / (i−1)! = i / i!，也就是 (i−1)! 的逆元 = i! 的逆元 × i。
  3. 查询：factorials[n] * inverse_factorials[k] % p * inverse_factorials[n-k] % p。k < 0 或 k > n 时直接返回 0。
class CombinationTable:
    def __init__(self, max_n, modulus=10**9 + 7):
        self.max_n, self.modulus = max_n, modulus
        self.factorials = [1] * (max_n + 1)
        for number in range(1, max_n + 1):
            self.factorials[number] = self.factorials[number - 1] * number % modulus
        self.inverse_factorials = [1] * (max_n + 1)
        self.inverse_factorials[max_n] = mod_inverse(self.factorials[max_n], modulus)
        for number in range(max_n, 0, -1):
            self.inverse_factorials[number - 1] = self.inverse_factorials[number] * number % modulus

    def choose(self, n, k):
        if n > self.max_n:
            raise ValueError("table is too small")
        if k < 0 or k > n:
            return 0
        return (self.factorials[n] * self.inverse_factorials[k] % self.modulus
                * self.inverse_factorials[n - k] % self.modulus)

table = CombinationTable(20)
table.choose(20, 2), table.choose(8, 2)     # (190, 28)

复杂度：预处理 O(max_n + log p)，每次查询 O(1)。

注意 p 要大于 max_n：否则 p! 及以后的阶乘都是 p 的倍数，没有逆元。109 + 7 远大于笔试里的 n（一般 ≤ 106），不用担心。

    lucky_count = len(primes_up_to(card_count))         # 筛法数幸运卡
    table = CombinationTable(card_count)                # 预处理阶乘和逆元
    favorable = table.choose(lucky_count, draw_count)   # C(8, 2) = 28
    total = table.choose(card_count, draw_count)        # C(20, 2) = 190
    return favorable * mod_inverse(total, MOD) % MOD    # 28 · 190⁻¹

lucky_draw_probability(20, 2)       # 242105265，也就是 14/95
lucky_draw_probability(10**5, 3)    # 859555632，不到一秒

动手玩

三个按钮对应主线的三步。辗转相除：gcd(190, 28)，每一步橙色行是正在算的 first % second，看第二个数怎样很快变成 0。埃氏筛：1..20 的卡片，橙色是当前的质数，红色是这一步刚被划掉的倍数，灰色是之前划掉的，绿色是确定的质数。快速幂：79 mod 11，看指数二进制的每一位决定 base 要不要乘进结果。

怎么认出这类题

  • 题目说“答案可能很大，请对 109 + 7 取模”：每一步加减乘都要 % MOD，减法加 MOD。
  • “输出 P · Q−1 mod …”“答案是分数，输出其在模意义下的值”：逆元。
  • “方案数”“选法有多少种”，又要取模：组合数表；n 到 105～106 就预处理阶乘。
  • “ab mod m”，b 可以到 1018：快速幂。
  • “约分”“最简分数”“两个周期什么时候重合”“能不能平分成若干等份”：gcd / lcm。
  • “1..n 里的质数”“质数个数”，n 到 106：筛法；只判断一个数：试除。

LeetCode 1979 · 找出数组的最大公约数

题意：给整数数组 nums，返回数组中最大数和最小数的最大公约数。

例子：输入 nums = [2, 5, 6, 9, 10]，输出 2。最小数是 2，最大数是 10，gcd(2, 10) = 2。

数据范围：2 ≤ nums.length ≤ 1000，1 ≤ nums[i] ≤ 1000。

LeetCode 204 · 计数质数

题意：给整数 n，返回小于 n 的质数的个数（不含 n 本身）。

例子：输入 n = 10，输出 4。小于 10 的质数是 2、3、5、7。n = 0 和 n = 1 时输出 0。

数据范围：0 ≤ n ≤ 5 × 106。

LeetCode 50 · Pow(x, n)

题意：实现 pow(x, n)，计算浮点数 x 的整数 n 次幂 xn。n 可以是负数，此时结果是 1 / x−n。

例子：输入 x = 2.00000, n = 10，输出 1024.00000。示例 3 输入 x = 2.00000, n = -2，输出 0.25000，因为 2−2 = 1/4。

数据范围：−100.0 < x < 100.0，−231 ≤ n ≤ 231 − 1，x 不为零或者 n > 0，−104 ≤ xn ≤ 104。

LeetCode 372 · 超级次方

题意：计算 ab 对 1337 取模。a 是正整数；b 是一个非常大的正整数，以十进制各位数字组成的数组给出，例如 [1, 0] 表示 10。

例子：输入 a = 2, b = [1, 0]，输出 1024。b 表示 10，210 = 1024，比 1337 小，取模后不变。

数据范围：1 ≤ a ≤ 231 − 1，1 ≤ b.length ≤ 2000，0 ≤ b[i] ≤ 9，b 不含前导 0。

LeetCode 1922 · 统计好数字的数目

题意：一个数字字符串是“好数字”，当且仅当（下标从 0 开始）偶数下标处的数字是偶数（0、2、4、6、8），奇数下标处的数字是质数（2、3、5、7）。例如 "2582" 是好数字，"3245" 不是（下标 0 的 3 不是偶数）。给整数 n，返回长度为 n 的好数字字符串的总数，结果对 109 + 7 取余。字符串可以有前导 0。

例子：输入 n = 1，输出 5，即 "0"、"2"、"4"、"6"、"8"。示例 2 输入 n = 4，输出 400 = 5 × 4 × 5 × 4。

数据范围：1 ≤ n ≤ 1015，结果对 109 + 7 取余。

LeetCode 62 · 不同路径

题意：机器人在 m × n 网格的左上角，每次只能向下或向右移动一步，返回到达右下角的不同路径数。

例子：输入 m = 3, n = 7，输出 28。一共要走 2 步向下、6 步向右，共 8 步，从中选出哪 2 步向下：C(8, 2) = 28。

数据范围：1 ≤ m, n ≤ 100，题目保证答案 ≤ 2 × 109（不用取模）。

最容易错的地方

  • 1 不是质数：is_prime(1) 要返回 False，筛法里 is_prime_flags[1] 要先改成 False。
  • 写成 base ** exponent % modulus：先算出完整的大整数再取模，指数一大就跑不完。用 pow(base, exponent, modulus)。
  • 除法直接取模：(a // b) % MOD 只在 a 本来就能被 b 整除、而且 a 没取过模时才对；一旦 a 是取模后的数，必须换成乘逆元。
  • 减法出负数：写成 (a - b + MOD) % MOD。Python 不加也对，但改写成别的语言就错了。
  • 忘了中间取模：a * b * c % MOD 在 Python 里结果对，但中间结果多了一倍位数；在 C++ 里直接溢出。写成 a * b % MOD * c % MOD。
  • 模数不是质数还用费马小定理：比如模数是 109，ap−2 不是逆元。这时用 pow(a, -1, m)（要求 gcd(a, m) = 1），或者扩展欧几里得算法（本课不讲）。
  • 筛法从 2·prime 开始划：结果仍然对，只是多做了无用功；从 prime * prime 开始才是 O(n log log n) 的标准写法。

自测

1. 为什么 gcd(a, b) = gcd(b, a % b)？ 设 a = q·b + r，r = a % b。能同时整除 a 和 b 的数，也能整除 r = a − q·b；能同时整除 b 和 r 的数，也能整除 a = q·b + r。两组公因数完全相同，最大的那个也相同。
2. Python 整数不会溢出，为什么主线题还是要边算边取模，而不是最后算出精确的 C(n, k) 再取模？ 三个原因：判题机只认取模后的那个整数；大整数相乘的耗时随位数增长，105! 直接连乘要几秒，边乘边取模只要几十毫秒；而且答案是分数，精确值没法表示成一个整数输出，只能用 P · Q−1 mod p 的形式。
3. 预处理组合数表时，为什么 inverse_factorials 要从大往小推，而不是对每个 i! 各做一次快速幂？ 各做一次快速幂是 O(n log p)；从大往小推只做一次快速幂，其余每项一次乘法：(i−1)! 的逆元 = i! 的逆元 × i，因为 1/(i−1)! = i / i!。总共 O(n + log p)。
4. 14/95 mod 11 等于 2。怎样不用逆元，直接检查这个答案对不对？ 把 2 乘回分母：95 × 2 = 190，190 % 11 = 3，而 14 % 11 = 3，两边同余，所以对。这正是逆元的定义：x 是 P/Q 的取模值，当且仅当 Q · x ≡ P (mod p)。
