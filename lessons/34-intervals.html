第 34 课 · 区间问题

区间题几乎都是同一个开头：先排序，再从左往右扫一遍。难点只在于按什么排：要把重叠的区间拼起来，按起点排；要挑出尽量多互不重叠的区间，按终点排。

开始前要会：Python —— lambda 与 key=（sorted 的排序键）、解包（for start, end in …）、float("-inf")、类型标注、f-string；前面的课 —— 第 7 课 · 排序与稳定性（sorted 不动原数据）、第 6 课 · 二分查找（bisect_right）、第 12 课 · 堆与优先队列（题 4 的会议室）、第 18 课 · 贪心（活动选择）。

先把说法统一

一个区间写成 [start, end]，表示从 start 到 end 这一段，比如一场会议从 2 点开到 5 点就是 [2, 5]。

两个区间什么时候重叠？把 [a_start, a_end] 和 [b_start, b_end] 想成数轴上的两条线段。它们不重叠只有两种情况：a 整个在 b 左边（a_end < b_start），或者 a 整个在 b 右边（b_end < a_start）。把这两种情况取反，就得到重叠的条件：

a_start <= b_end and b_start <= a_end

端点刚好相接算不算重叠，要看题目。合并区间那道题里，[1, 3] 和 [3, 5] 在 3 处相接，算重叠，要合成 [1, 5]。会议室那道题里，一场会 10 点结束、下一场 10 点开始，同一间会议室可以接着用，算不重叠（这种区间叫“左闭右开”，写成 [start, end)）。写代码时，这个区别就体现在比较用 < 还是 <=，做题时一定先看清。

实战里怎么写：日程、空闲时段、IP 段

标准库没有现成的“合并区间”函数，但业务里的区间问题套路固定，几行就写完。真实代码里常见的是这几种：

场景用什么代价
合并几个人的忙碌时段，算共同空闲（约会议）sorted 按开始时间排，扫一遍合并，再取相邻两段的空隙O(n log n)
一个点落在哪个区间（IP 段归属、阶梯电价、按时间段生效的配置）区间互不重叠时，起点排好序，bisect_right 找“起点 ≤ 该点的最后一段”，再看终点建表 O(n log n)，每次查 O(log n)
同时进行的最大数量（会议室、并发连接数）heapq 维护各自的结束时间O(n log n)
区间很多，还要频繁增删、查重叠第三方库（如 intervaltree），本项目不引入增删查约 O(log n)
from bisect import bisect_right


def merge_busy(slots):
    """合并忙碌时段。slots 是 (开始分钟, 结束分钟) 列表；10:00 结束、10:00 开始的两段也并成一段。"""
    merged = []
    for start, end in sorted(slots):
        if merged and start <= merged[-1][1]:
            merged[-1] = (merged[-1][0], max(merged[-1][1], end))
        else:
            merged.append((start, end))
    return merged


def common_free_slots(busy, day_start, day_end, minimum_length):
    """工作时间内大家都有空、且不短于 minimum_length 分钟的时段。"""
    free_slots, cursor = [], day_start
    for start, end in merge_busy(busy):
        if start - cursor >= minimum_length:
            free_slots.append((cursor, start))
        cursor = max(cursor, end)
    if day_end - cursor >= minimum_length:
        free_slots.append((cursor, day_end))
    return free_slots


def owner_of(address_value, range_starts, range_rows):
    """IP 段归属：range_rows 是按起点排好序、互不重叠的 (起点, 终点, 归属)。"""
    index = bisect_right(range_starts, address_value) - 1
    if index < 0:
        return None
    _, last, owner = range_rows[index]
    return owner if address_value <= last else None   # 也可能落在两段之间的空隙里

完整可运行的版本在 examples/intervals_in_practice.py（uv run examples/intervals_in_practice.py），IP 用标准库 ipaddress 转成整数再比较：IPv4Address("10.0.0.1") 把点分十进制的地址变成能比较大小的对象，int(...) 再取出它对应的 32 位整数（例如 int(IPv4Address("10.0.0.1")) 是 167772161），这样 IP 段就变成了普通的整数区间。合并时段就是下面的题 1，会议室就是题 4。

怎么认出这类题

题目给的是一组“开始时间、结束时间”或者“左端点、右端点”，并且出现下面这些说法时，基本就是区间题：

  • “合并所有重叠的区间”“把有交集的区间合在一起”：按起点排序，合并。
  • “插入一个新区间，结果仍要有序且不重叠”：已经有序，一趟扫描分三段。
  • “最少删除几个区间，使剩下的互不重叠”“最多能参加几个活动”“最少用几支箭射爆所有气球”：按终点排序，贪心挑选。
  • “最少需要几间会议室 / 几个服务台 / 几辆车”“同一时刻最多有几个区间同时进行”：按起点排序 + 最小堆，或者把开始、结束拆成事件来扫。

按起点排序，还是按终点排序？

这是区间题最关键的一个选择，先给结论，后面每道题会具体解释为什么：

排序方式排完之后得到的性质适合的题
按起点从左往右扫时，后面的区间起点不会更小。所以一个区间如果和“已经扫过的部分”重叠，只可能和最后一段重叠，用不着回头看更早的。合并区间、插入区间、会议室 II 这类要把区间“拼起来”或“排进时间表”的题
按终点先看到的区间结束得早，给后面留下的空间最多。无重叠区间、最多参加几个活动、射气球这类“挑出尽量多互不重叠的区间”的题

题 1：合并区间（LeetCode 56）

题意。给一组区间，把所有有重叠的合成一个，返回合并后的结果。例如 [[1, 3], [2, 6], [8, 10], [15, 18]]：[1, 3] 和 [2, 6] 重叠，合成 [1, 6]；其余两段和谁都不重叠，原样保留。答案是 [[1, 6], [8, 10], [15, 18]]。

暴力做法为什么慢。最直接的想法是：两两检查，发现重叠就合并成一个，再从头检查，直到没有任何两个重叠为止。每一轮要比较 O(n2) 对，最多合并 n 次，总共 O(n3)。慢的原因是区间顺序是乱的，和某个区间重叠的伙伴可能在列表的任何位置，只好全部比一遍。

关键观察。如果先按起点从小到大排序，那么和某个区间重叠的区间一定紧挨着它，不会隔着一个不相干的区间出现。所以从左往右扫的时候，当前区间只需要和结果里的最后一段比较。

具体做法。

def merge_intervals(intervals):
    merged_intervals = []
    for start, end in sorted(intervals):            # 按起点排序
        if merged_intervals and start <= merged_intervals[-1][1]:
            # 起点没超过最后一段的终点：重叠，把最后一段拉长
            merged_intervals[-1][1] = max(merged_intervals[-1][1], end)
        else:
            # 接不上：开新的一段
            merged_intervals.append([start, end])
    return merged_intervals

merge_intervals([[1, 3], [2, 6], [8, 10]])          # [[1, 6], [8, 10]]

注意更新终点时要取 max，不能直接写成 end。反例：[1, 10] 后面来了 [2, 3]，它整个被包在里面，如果直接把终点改成 3，就把 [1, 10] 改短了。

为什么是对的。假设扫到区间 X 时，它的起点大于最后一段的终点 current_end。因为已经排过序，X 后面所有区间的起点都 >= X 的起点，也就都 > current_end，所以最后一段以后再也不会和任何区间重叠，可以放心地“封口”，开新的一段。反过来，如果 X 的起点 <= current_end，又因为 X 的起点 >= 最后一段的起点（排过序），X 一定和最后一段重叠，合并它是必须的。

复杂度。排序 O(n log n)，扫描 O(n)，总共 O(n log n)；结果列表占 O(n) 空间。

动手玩

先点合并区间：第 1 帧是乱序的原始输入，第 2 帧排好序，之后每一步看当前区间（红色）的起点和红线（结果里最后一段的终点）谁大。最下面一行是 merged_intervals，红框是最后一段。题 4 讲完后再回来点会议室 II，看最小堆怎么告诉我们哪间会议室空出来了。

题 2：插入区间（LeetCode 57）

题意。给一组已经按起点排好序、互不重叠的区间，再给一个新区间 new_interval，把它插进去，有重叠就合并，结果仍然有序且不重叠。例如区间是 [[1, 2], [3, 5], [6, 7], [8, 10], [12, 16]]，新区间 [4, 8]：它和 [3, 5]、[6, 7]、[8, 10] 都重叠，这四个合成 [3, 10]，答案是 [[1, 2], [3, 10], [12, 16]]。

暴力做法为什么慢（其实也不算太慢）。把新区间追加到末尾，然后直接调用题 1 的合并区间，结果是对的，但要重新排序，O(n log n)。输入本来就是有序的，重新排序浪费了这个条件。

关键观察。原来的区间互不重叠又有序，相对于新区间，它们一定按顺序分成三段：完全在新区间左边的、和新区间重叠的、完全在新区间右边的。三段各自连成一片，不会交错出现。

具体做法。用一个下标 i 从左往右走，分三个循环：

def insert_interval(intervals, new_interval):
    new_start, new_end = new_interval
    merged_intervals = []
    index = 0
    # 第一段：终点比新区间的起点还小，完全在左边，原样保留
    while index < len(intervals) and intervals[index][1] < new_start:
        merged_intervals.append(intervals[index])
        index += 1
    # 第二段：起点不超过新区间的终点，说明重叠，并进新区间
    while index < len(intervals) and intervals[index][0] <= new_end:
        new_start = min(new_start, intervals[index][0])
        new_end = max(new_end, intervals[index][1])
        index += 1
    merged_intervals.append([new_start, new_end])
    # 第三段：剩下的都在右边，原样保留
    merged_intervals.extend(intervals[index:])
    return merged_intervals

为什么是对的。第一个循环停下时，intervals[i] 的终点 >= new_start，它不在新区间左边。第二个循环里的条件“起点 <= new_end”，加上刚才的“终点 >= new_start”，正好就是开头讲的重叠条件。第二个循环停下时，intervals[i] 的起点 > new_end，后面的起点更大，所以剩下的全都在右边，不会再和合并好的新区间重叠。注意第二个循环里 new_end 会变大，每次比较用的都是合并后最新的 new_end。

复杂度。每个区间只被看一次，时间 O(n)；结果占 O(n) 空间。

题 3：无重叠区间（LeetCode 435）

题意。给一组区间，最少删掉几个，能让剩下的两两不重叠？这道题里端点相接不算重叠。例如 [[1, 2], [2, 3], [3, 4], [1, 3]]：删掉 [1, 3] 后，剩下三个首尾相接，互不重叠，答案是 1。

暴力做法为什么慢。枚举“删哪些”，每个区间删或不删，一共 2n 种，每种还要检查是否重叠，n = 30 时就已经算不完了。

关键观察。“最少删几个”等于“总数减去最多能留几个”。而“最多留下几个互不重叠的区间”，正是第 18 课讲过的活动选择：一天里想参加尽量多的活动，每次挑最早结束的那个。

具体做法。按终点排序，用 current_end 记录上一个留下的区间在哪里结束：

def min_removals_to_avoid_overlap(intervals):
    kept_count = 0
    current_end = float("-inf")
    for start, end in sorted(intervals, key=lambda interval: interval[1]):   # 按终点排序
        if start >= current_end:      # 端点相接不算重叠，所以用 >=
            kept_count += 1           # 留下它
            current_end = end
        # 否则它和上一个留下的重叠，删掉它，current_end 不变
    return len(intervals) - kept_count

为什么按终点排序是对的。在所有区间里，结束最早的那个（叫它 X）一定可以出现在某个最优答案里。理由是：随便拿一个最优答案，把其中结束最早的那个区间换成 X。X 结束得不比它晚，所以不会和答案里后面的区间冲突，换完区间个数不变，仍然是最优的。确定留下 X 之后，所有和 X 重叠的区间都只能删掉，剩下的问题和原问题形状一样，继续用同样的理由挑下一个。

为什么按起点排序不行。反例 [[1, 100], [2, 3], [4, 5]]：按起点排，第一个看到的 [1, 100] 很长，留下它会把后面两个都挤掉，只能留 1 个；按终点排，先留 [2, 3] 和 [4, 5]，留 2 个，删 1 个才是对的。

复杂度。排序 O(n log n)，扫描 O(n)；除了排序，只用了几个变量。

题 4：会议室 II（LeetCode 253）

题意。给一组会议的开始和结束时间，最少要几间会议室，才能让每场会议都有地方开？一场会议结束的同一时刻，另一场可以接着用这间会议室。例如 [[0, 30], [5, 10], [15, 20]]：[0, 30] 从头占到尾，要一间；[5, 10] 和 [15, 20] 时间不冲突，可以先后用另一间。答案是 2。

暴力做法为什么慢。答案其实就是“同一时刻最多有几场会议在开”。暴力做法是对每一个可能的时间点，数一数有几场会议覆盖它。时间点有很多个（每场会议的开始时间都要检查），每个点要数 n 场会议，O(n2)。

关键观察。按开始时间的顺序一场一场安排。新来一场会议时，我们只关心一件事：现在在用的会议室里，最早空出来的那间，是不是已经空了？“随时取出最小值”正是第 12 课的最小堆擅长的。

具体做法。

import heapq


def min_meeting_rooms(meetings):
    room_free_times = []            # 最小堆：每间在用的会议室什么时候空出来
    max_rooms = 0
    for start, end in sorted(meetings):              # 按开始时间排序
        if room_free_times and room_free_times[0] <= start:
            heapq.heappop(room_free_times)           # 最早空出来的那间已经空了，让给这场会议
        heapq.heappush(room_free_times, end)         # 这场会议占用一间，到 end 才空
        max_rooms = max(max_rooms, len(room_free_times))
    return max_rooms

为什么是对的。堆里的元素个数始终等于“当前时刻正在使用的会议室数”。新会议到来时，如果连最早空出来的那间都还没空，其他的更不可能空，只能新开一间；如果它已经空了，就让新会议用它，不浪费会议室。所以堆的最大大小就是同一时刻最多需要的会议室数。上面的动画里可以看到，D 接着用了 B 腾出来的会议室 2，E 接着用了 A 腾出来的会议室 1。

另一种写法：拆成事件。把所有开始时间排成一列 start_times，所有结束时间排成一列 end_times，用两个下标同时往后走，就像两个有序列表的归并。遇到开始，rooms_in_use 加一；遇到结束，减一；时间相同时先处理结束（因为结束和开始可以共用会议室）。过程中 rooms_in_use 的最大值就是答案。

复杂度。排序 O(n log n)，每场会议最多进堆、出堆各一次，每次 O(log n)，总共 O(n log n)；堆占 O(n) 空间。

复杂度汇总

题排序方式时间额外空间
合并区间按起点O(n log n)O(n)
插入区间输入已有序，不用排O(n)O(n)
无重叠区间按终点O(n log n)O(1)
会议室 II按起点 + 最小堆O(n log n)O(n)

最容易错的四个地方

  • 端点相接的处理写反。合并区间里 [1, 3] 和 [3, 5] 要合并，判断用 start <= 最后一段的终点；无重叠区间和会议室里相接不算冲突，判断用 start >= current_end 和 堆顶 <= start。
  • 合并时终点直接赋值，没取 max。被完全包住的区间（[1, 10] 里的 [2, 3]）会把结果改短。
  • 无重叠区间按起点排序。一个很长的区间排在最前面，会把后面很多短区间挤掉，得到的不是最优。
  • 原地修改了输入。直接 intervals.sort() 或者把输入里的区间对象放进结果再改它的终点，调用者手里的数据也跟着变了。用 sorted(...)，往结果里放新列表 [start, end]。

自测

1. 合并区间为什么只需要和结果里的最后一段比较，不用和更早的段比较？ 因为按起点排过序，结果里更早的段在“封口”时，已经确认后面所有区间的起点都大于它的终点。所以当前区间不可能和它们重叠，只可能和最后一段重叠。
2. 射气球（LeetCode 452）：气球是区间 [x_start, x_end]，在 x 处射一箭，能射爆所有覆盖 x 的气球。最少几支箭？和无重叠区间有什么关系？ 按终点排序，第一支箭射在第一个气球的终点上，能把所有起点 <= 这个位置的气球一起射爆；遇到起点 > 这个位置的气球，就要再射一支，射在它的终点。箭数就等于“最多能挑出几个互不重叠的气球”，和 435 题留下的个数一样。区别是这道题端点相接的气球可以被同一支箭射爆，所以算重叠，判断条件要用 >，不是 >=。
3. 会议室 II 里，为什么时间相同时要“先处理结束，再处理开始”？ 一场会议在 10 点结束、另一场在 10 点开始，同一间会议室可以接着用。如果先处理开始，rooms_in_use 会先加一，算出一个比实际多一间的峰值。
