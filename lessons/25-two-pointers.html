第 25 课 · 双指针

双指针 = 用两个下标同时在数组上走，每一步都根据当前情况排除掉一批不可能的答案。原本要两层循环 O(n²) 才能枚举完的“一对位置”，变成两个下标各走一遍，O(n)。

开始前要会：Python —— 解包与交换、推导式、切片、lambda 与 sorted vs sort、dict.fromkeys、类型标注（X | None）、try/except；前面的课 —— 第 8 课 · 归并排序（“合并两份有序数据”的思路）、第 12 课 · 堆（实战表里的 heapq.merge）。

实战里怎么写：先看真实代码里的双指针

业务代码里很少有人写“对撞指针找两数之和”，但双指针的想法天天在用，只是常常藏在标准库里：

场景用什么代价
合并两份已经排好序的数据（两台服务器的日志、两页排好序的结果）标准库 heapq.merge(a, b)（第 12 课的 heapq，那里见过它），内部就是每份数据一个指针O(n + m)，边读边合并，不用全部读进内存
两份排好序的数据要对齐：对账，找两边都有的、只有一边有的手写同向双指针O(n + m)，额外空间 O(1)
按条件删元素、保持顺序列表推导式 [x for x in items if keep(x)]O(n)，多一份列表的内存
保持顺序地去重list(dict.fromkeys(items))O(n)
数据大到不能复制一份，必须原地删快慢指针，最后 del items[slow:]O(n)，额外空间 O(1)
import heapq

merged_logs = list(heapq.merge(server_a_logs, server_b_logs))   # 两份各自按时间排好序的 (时间戳, 内容)

def reconcile(ledger_ids: list[int], bank_ids: list[int]):
    """对账：两份流水号都从小到大排好序。哪边小，说明它在另一边找不到，记下来往前走。"""
    matched, ledger_only, bank_only = [], [], []
    ledger_index = bank_index = 0
    while ledger_index < len(ledger_ids) and bank_index < len(bank_ids):
        ledger_id, bank_id = ledger_ids[ledger_index], bank_ids[bank_index]
        if ledger_id == bank_id:
            matched.append(ledger_id)
            ledger_index += 1
            bank_index += 1
        elif ledger_id < bank_id:
            ledger_only.append(ledger_id)
            ledger_index += 1
        else:
            bank_only.append(bank_id)
            bank_index += 1
    ledger_only.extend(ledger_ids[ledger_index:])   # 一边走完了，另一边剩下的都对不上
    bank_only.extend(bank_ids[bank_index:])
    return matched, ledger_only, bank_only

两种走法

双指针不是一种具体算法，而是一类写法。按两个下标怎么走，分成两种：

名字怎么走典型用途
对撞指针left 从最左边出发往右走，right 从最右边出发往左走，两者相遇就结束在有序数组里找一对满足条件的数；从两头往中间比较（回文、盛水）
快慢指针slow 和 fast 从同一头出发、同方向走，fast 每步都走，slow 满足条件才走原地整理数组（删元素、移零、去重）；链表找中点、判断有没有环

两种走法的共同点是：每个下标只往一个方向走，从不回头。两个下标加起来最多走 n 步，所以总时间是 O(n)。难点不在写代码，而在于说清楚“为什么这一步可以放心地移动这个指针，不会错过答案”。下面每道题都会把这个理由讲出来。

怎么认出这类题

  • 题目说数组已经有序（或者你可以先排序），要找两个数 / 三个数满足某个和、差、积。→ 对撞指针。
  • 要从两端往中间比较：回文串、反转数组、两根柱子之间的面积。→ 对撞指针。
  • 要求原地修改数组、O(1) 额外空间，比如“删除某些元素”“把某类元素挪到末尾”“去掉重复项”。→ 快慢指针。
  • 链表题里要找中间节点、倒数第 k 个节点、判断有没有环。→ 快慢指针（fast 每次走两步或先走 k 步）。
  • 暴力解法是“两层循环枚举所有的 (i, j) 对”，而你觉得很多对其实不用看。→ 先想想能不能用双指针砍掉一层循环。

第 1 题：两数之和 II（对撞指针）

题意：数组 numbers 已经从小到大排好序，找两个不同位置的数，使它们的和等于 target，返回这两个下标。题目保证恰好有一个答案。

例子：numbers = [2, 7, 11, 15]，target = 9。2 + 7 = 9，所以返回 [0, 1]。

暴力做法为什么慢：两层循环，外层选第一个数，内层选第二个数，把所有的对都试一遍。n 个数有 n(n-1)/2 对，时间 O(n²)。它完全没利用“数组有序”这个条件。

关键观察：拿最小的数和最大的数相加，看看和 target 比是大了还是小了。

  • 如果 numbers[left] + numbers[right] < target：numbers[right] 已经是剩下的数里最大的了，numbers[left] 和它相加都不够，和剩下的任何一个数相加只会更小。所以 numbers[left] 不可能出现在答案里，可以扔掉，left 右移一格。
  • 如果和大于 target：反过来，numbers[right] 和剩下最小的数相加都太大，它也不可能出现在答案里，right 左移一格。
  • 如果正好等于：找到了。

每比较一次，就有一个数被确定“不可能是答案”，从候选范围里删掉。候选范围始终是 left 到 right 这一段。

target = 9： 271115 2 + 15 = 17 > 9，15 和谁配都太大，right 左移
　　　　　　 271115 2 + 11 = 13 > 9，right 左移
　　　　　　 271115 2 + 7 = 9，找到 [0, 1]
left, right = 0, len(numbers) - 1
while left < right:
    pair_sum = numbers[left] + numbers[right]
    if pair_sum == target:
        return [left, right]
    if pair_sum < target:
        left += 1      # numbers[left] 和剩下最大的数相加都不够，扔掉它
    else:
        right -= 1     # numbers[right] 和剩下最小的数相加都太大，扔掉它

为什么是对的：上面每次扔掉的数，都已经证明了它和候选范围里的任何数都凑不出 target。答案那两个数永远不会被扔掉，而候选范围每步缩小一格，最后一定会让 left 和 right 正好停在答案上。

复杂度：left 和 right 加起来最多走 n 步，时间 O(n)；只用了两个变量，额外空间 O(1)。

第 2 题：盛最多水的容器（对撞指针）

题意：heights[i] 是第 i 根竖线的高度，相邻竖线间距为 1。选两根竖线，和 x 轴一起组成一个容器。水面不能高过较矮的那一根，所以容器能装的水 = min(heights[left], heights[right]) × (right - left)。求最多能装多少水。

例子：heights = [1, 8, 6, 2, 5, 4, 8, 3, 7]。选下标 1（高 8）和下标 8（高 7）：高度取较矮的 7，宽度 8 - 1 = 7，面积 49，这是最大值。

暴力做法为什么慢：枚举所有的两根竖线组合，每对算一次面积，O(n²)。

关键观察：先拿最左和最右两根算面积，此时宽度最大。接下来要移动其中一根，宽度一定会减 1。问题是移动哪一根。

  • 假设左边那根更矮。它现在的搭档是最右边那根，两者距离已经是它能拥有的最大距离。
  • 如果它换一个更靠里的搭档：宽度变小；高度取两者中较矮的，最多也就是它自己的高度，不可能变大。宽度变小、高度不变大，面积一定不会超过刚才算过的那个。
  • 所以这根矮竖线“这辈子最好的成绩已经算过了”，可以放心扔掉，left 右移。
  • 反过来，如果扔掉高的那一根，矮的那根留下来，以后的面积仍然被它限制，而且可能错过答案。所以永远移动较矮的那一根。两根一样高时移动哪一根都可以。
left, right = 0, len(heights) - 1
best_area = 0
while left < right:
    water_height = min(heights[left], heights[right])
    best_area = max(best_area, water_height * (right - left))
    if heights[left] < heights[right]:
        left += 1      # 左边矮：它和最远的搭档已经算过了，扔掉
    else:
        right -= 1     # 右边矮（或一样高）：扔掉右边

为什么是对的：每扔掉一根竖线，都已经证明它和还没算过的任何一根组合都不可能比已经算过的面积更大。所以最大面积那一对在被扔掉之前，一定已经被算过一次。

复杂度：时间 O(n)，额外空间 O(1)。下面的动画里可以一步步看这个过程。

第 3 题：三数之和（排序 + 对撞指针）

题意：给一个整数数组（没有排序），找出所有和为 0 的三元组，三个数要来自三个不同位置。每个三元组从小到大写，结果里不能有重复的三元组。

例子：[-1, 0, 1, 2, -1, -4] 返回 [[-1, -1, 2], [-1, 0, 1]]。注意数组里有两个 -1，[-1, 0, 1] 可以用第一个 -1 也可以用第二个，但结果里只能出现一次。

暴力做法为什么慢：三层循环 O(n³)，而且还要另外处理重复的三元组（比如把每个结果排序后放进集合）。

关键观察：如果先固定第一个数 numbers[first_index]，剩下的问题就是“在它右边找两个数，和等于 -numbers[first_index]”，这正是第 1 题。第 1 题要求有序，所以一开始先把整个数组排序，排序只花 O(n log n)，比后面的 O(n²) 小。

怎么用上双指针：

  1. 排序：[-4, -1, -1, 0, 1, 2]。
  2. first_index 从左往右走。每个位置上，left = first_index + 1，right = 最后一个下标，用第 1 题的方法找所有和为 -numbers[first_index] 的对。和第 1 题不同的是，找到一对之后不能停，要两边都往里收一格，继续找下一对。
  3. 去重（这是最容易错的地方）：
    • 固定的第一个数如果和上一轮固定的一样（例如第二个 -1），它能找到的三元组上一轮都找过了，直接跳过。
    • 找到一组答案后，left 要一直右移，跳过所有和刚才相同的值；right 同理一直左移。否则同一组值会被记录两次。
numbers.sort()
triplets = []
for first_index in range(len(numbers) - 2):
    if first_index > 0 and numbers[first_index] == numbers[first_index - 1]:
        continue                                   # 第一个数和上一轮相同，跳过
    left, right = first_index + 1, len(numbers) - 1
    while left < right:
        total = numbers[first_index] + numbers[left] + numbers[right]
        if total < 0:
            left += 1
        elif total > 0:
            right -= 1
        else:
            triplets.append([numbers[first_index], numbers[left], numbers[right]])
            while left < right and numbers[left] == numbers[left + 1]:
                left += 1                          # 跳过相同的第二个数
            while left < right and numbers[right] == numbers[right - 1]:
                right -= 1                         # 跳过相同的第三个数
            left += 1
            right -= 1

为什么是对的：任何一个答案三元组，排序后它的最小数一定出现在某个 first_index 上（重复值只取第一次出现的位置），剩下两个数在它右边，会被第 1 题的对撞指针找到。去重规则保证同一组值只在“第一次遇到”时记录一次。

复杂度：外层 n 次，每次对撞指针 O(n)，时间 O(n²)；除了结果列表和排序，额外空间 O(1)。

第 4 题：移动零（快慢指针）

题意：原地修改数组，把所有 0 挪到末尾，非零数保持原来的先后顺序。不能复制出一个新数组。

例子：[0, 1, 0, 3, 12] 变成 [1, 3, 12, 0, 0]。

暴力做法为什么慢：每遇到一个 0，就把它后面所有元素往前挪一格、把 0 放到最后。挪一次 O(n)，最多挪 n 次，O(n²)。

关键观察：其实只需要知道“下一个非零数应该放在哪儿”。用 slow 记住这个位置，用 fast 从头到尾扫描。

  • fast 遇到 0：什么也不做，fast 继续走。
  • fast 遇到非零数：把它和 slow 位置的数交换，然后 slow 右移一格。

整个过程中始终保持一个不变量：下标 [0, slow) 里都是非零数，并且保持原来的顺序；下标 [slow, fast) 里都是 0。fast 走到末尾时，非零数全在前面、0 全在后面，就做完了。

slow = 0
for fast in range(len(numbers)):
    if numbers[fast] != 0:
        numbers[slow], numbers[fast] = numbers[fast], numbers[slow]
        slow += 1

为什么是对的：交换时，slow 位置要么就是 fast 自己（前面还没出现过 0），要么是一个 0（根据不变量）。所以交换只是把一个非零数挪到前面、把一个 0 挪到后面，不会打乱非零数的先后顺序。

复杂度：fast 走一遍，时间 O(n)，额外空间 O(1)。同样的模板改一下判断条件，就能做“移除元素”“删除有序数组中的重复项”。

动手玩

三个按钮各演示一道题。建议先看 盛最多水：橙色的竖线是 left 和 right，蓝色是当前这对竖线能装的水，注意每一步被扔掉的都是较矮的那根。然后看 两数之和 II 和 移动零，用“上一步 / 下一步”慢慢对照下面的说明。灰掉的格子表示已经被排除。

最容易错的地方

  • 对撞指针的循环条件写成 left <= right：两个指针指到同一个位置时，会把同一个数用两次。找“两个不同位置”时要写 left < right。
  • 盛水题移动了较高的那一根。这样可能把答案扔掉，前面已经解释过为什么只能移动较矮的。
  • 三数之和只在固定第一个数时去重，找到答案后忘了让 left、right 跳过相同的值，结果里出现重复三元组。
  • 三数之和忘了先排序。对撞指针依赖“左边小、右边大”，数组无序时整个推理都不成立。
  • 移动零写成“遇到 0 就 remove 再 append”：list.remove 本身是 O(n)，总共变成 O(n²)。

自测

1. 两数之和 II 为什么要求数组有序？无序时用什么？ 对撞指针的每一步推理都依赖有序：和太小就说明要更大的数，而更大的数一定在右边。无序时这个推理不成立。第 27 课会讲一个不要求有序的哈希表做法：一边走一边把见过的数存进 dict，O(n) 时间、O(n) 空间，这里先不展开。
2. 盛水题里两根竖线一样高，移动哪一根？会不会错过答案？ 移动哪一根都可以。设两根都高 h，它们的面积是 h × 宽度。只留下其中任何一根、换一个更靠里的搭档，高度最多还是 h，宽度变小，面积不会更大。所以两根都已经“用完了”，扔掉哪一根都不会错过答案。
3. 快慢指针在链表上怎么找中间节点？ slow 每次走一步，fast 每次走两步。fast 走到末尾时，slow 正好走了一半，停在中间节点。判断有没有环也用这一对：有环的话，fast 迟早会从后面追上 slow。
