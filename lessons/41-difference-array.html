第 41 课 · 差分数组

差分数组 = 只记“相邻两个数差了多少”。给一整段数同时加上同一个值，在差分数组里只要改两格，O(1)；所有修改做完，再做一遍前缀和（第 27 课）就还原出最终数组。差分和前缀和是一对逆操作。

开始前要会：Python —— itertools.accumulate、enumerate、zip、解包（for first, last, seats in bookings）、类与 __init__、__len__、raise IndexError、defaultdict、date 与 timedelta；前面的课 —— 第 27 课 · 前缀和（本课处处用到，尤其是“多一格”的写法）、第 34 课 · 区间问题（会议室 II 用堆做过一次，本课换一种做法）。

类比：公交车的上下车记录

想知道公交车开到每一站时车上有几个人，司机不用每站数一遍人头，只要记“这一站上了几个、下了几个”。从起点开始把这些变化量一路加起来，就得到每一站车上的人数。

“每站的变化量”就是差分，“一路加起来”就是前缀和。一个乘客从第 2 站坐到第 5 站，在记录里只占两笔：第 2 站 +1，第 6 站（他已经下车）-1，中间那几站的记录一个字都不用改。这就是本课的全部想法。

实战里怎么写：先看真实代码里的差分

差分适合“先攒一大批区间修改，最后才要结果”的场景。标准库没有专门的差分工具，但还原那一步就是 accumulate：

场景做法代价
酒店每晚住了几间房、每天在线人数每张订单在差分数组上改两格，最后 accumulate 还原每单 O(1)，还原 O(天数)
时间戳很大很稀疏（秒级时间、坐标）差分存进 dict：change_at[start] += 1、change_at[end] -= 1，按键排序后累加（也叫扫描线）O(m log m)，m 是区间个数
批量调价、批量加分每条规则改两格，最后一次还原每条 O(1)，还原 O(n)
from itertools import accumulate

def apply_price_rules(prices: list[int], rules: list[tuple[int, int, int]]) -> list[int]:
    """rules 里每项是 (第一个商品下标, 最后一个商品下标, 调价金额)，两端都包含。"""
    difference = [0] * (len(prices) + 1)          # 多一格，下面解释为什么
    for first, last, change in rules:
        difference[first] += change               # 从 first 开始，每个都多了 change
        difference[last + 1] -= change            # 到 last 为止，后面的再减回去
    return [price + adjustment for price, adjustment in zip(prices, accumulate(difference))]

apply_price_rules([3, 1, 4, 1, 5, 9, 2, 6], [(2, 5, 2), (4, 7, 3)])
# [3, 1, 6, 3, 10, 14, 5, 9]

完整可运行的版本在 examples/difference_array_in_practice.py（uv run examples/difference_array_in_practice.py），里面还有酒店入住和“要几间会议室”的 dict 写法。zip(prices, accumulate(difference)) 会在较短的 prices 走完时停下，所以多出来的那一格不会被用到。下面的练习里不许用 accumulate，要自己写循环，把“改两格为什么就够了”想清楚。

差分数组的定义

本课和下一课（第 42 课 · 树状数组）都用同一个数组当例子：numbers = [3, 1, 4, 1, 5, 9, 2, 6]，长度 n = 8。

它的差分数组 difference 比它多一格，长度 n + 1：

  • difference[0] = numbers[0]：可以想成第一个数前面还有一个看不见的 0，差就是它本身。
  • difference[i] = numbers[i] - numbers[i - 1]（1 ≤ i < n）：第 i 个数比前一个多了多少。
  • difference[n] = 0：多出来的这一格一开始是 0，作用后面讲。
下标012345678 numbers31415926 difference3-23-344-740

例如 difference[2] = numbers[2] - numbers[1] = 4 - 1 = 3，difference[6] = 2 - 9 = -7。

差分和前缀和互为逆操作

反过来，把 difference 从头加到第 i 格，中间的项两两抵消：

difference[0] + difference[1] + ... + difference[i]
= numbers[0] + (numbers[1] - numbers[0]) + ... + (numbers[i] - numbers[i - 1])
= numbers[i]

所以对差分数组做前缀和，就还原出原数组；对原数组求差分，又能回到差分数组。这样一对“做完一个、再做另一个就回到原样”的操作，叫做互为逆操作，就像乘 2 和除以 2。

和第 27 课对照着看：第 27 课的 prefix_sum 开头多放了一个 0，prefix_sum[i] 是前 i 个数的和，不含 numbers[i]。这里的还原公式是“加到第 i 格，含 difference[i]”，所以写循环时是边加边输出，不需要开头的 0：

running_total = 0
for index in range(n):
    running_total += difference[index]
    result.append(running_total)       # running_total 就是 numbers[index]

区间整体加：只改两格

现在要把下标 2 到 5（两端都包含）这一段整体加 2，也就是每个数都加 2。直接改原数组要改 4 个数，一段长 n 就要 O(n)。在差分数组里只改两格：

difference[left] += delta          # difference[2] += 2
difference[right + 1] -= delta     # difference[6] -= 2
下标012345678 difference3-25-344-940 还原316371126

为什么改两格就够了：还原时第 i 个数等于 difference[0..i] 的和。

  • i < 2：加的范围里没有 difference[2] 和 difference[6]，结果不变。
  • 2 ≤ i ≤ 5：加的范围里有 difference[2]（多了 2），没有 difference[6]，结果多 2。
  • i ≥ 6：两格都在范围里，+2 和 -2 抵消，结果不变。

再把下标 4 到 7 整体加 3：difference[4] += 3，difference[8] -= 3。这次 right + 1 = 8 = n，正好落在多出来的那一格上。这就是多一格的作用：不管 right 是不是最后一个下标，都能写同一行 difference[right + 1] -= delta，不用特判。还原时只算前 n 格，最后一格永远不会被读到。两次修改之后还原，得到 [3, 1, 6, 3, 10, 14, 5, 9]，和上面实战代码的输出一样。

差分什么时候不好用：它要求“改完再查”。如果改一次就要马上查某个数，每次都得 O(n) 还原一遍，就失去意义了。改和查交替进行的情况，下一课用树状数组解决。

动手玩

两个按钮。区间加与还原：先把 numbers 变成差分数组，再做上面的两次区间加（绿色格子 +delta，红色格子 -delta），最后一格格做前缀和还原，看结果和直接改原数组一样。拼车演示下面的题 2：每一单乘客改两格，再从位置 0 开始一格格累加出车上的人数，第一次超过容量就标红并返回 False，和题 2 的代码一样。

题 1：航班预订统计（LeetCode 1109）

题意：航班编号 1 到 n。bookings[i] = [first, last, seats] 表示第 first 到第 last 个航班（两端都包含）每个都订了 seats 个座位。返回每个航班的总预订数。

例子：bookings = [[1, 2, 10], [2, 3, 20], [2, 5, 25]]，n = 5，返回 [10, 55, 45, 25, 25]。第 2 个航班被三张订单都覆盖：10 + 20 + 25 = 55。

暴力做法为什么慢：每张订单把 first 到 last 逐个加一遍，一张 O(n)，m 张订单 O(m · n)。n 和 m 都是 2 万时，就是 4 亿次加法。

关键观察：所有订单都加完才要结果，正是差分的场景。每张订单在差分数组上改两格，最后还原一次。唯一要注意的是编号从 1 开始，换成下标要减 1：

def corp_flight_bookings(bookings, flight_count):
    difference = [0] * (flight_count + 1)
    for first, last, seats in bookings:
        difference[first - 1] += seats      # 编号 first 是下标 first - 1
        difference[last] -= seats           # 编号 last 是下标 last - 1，再 + 1 就是 last
    answer = []
    running_total = 0
    for index in range(flight_count):
        running_total += difference[index]
        answer.append(running_total)
    return answer

复杂度：时间 O(n + m)，额外空间 O(n)。

题 2：拼车（LeetCode 1094）

题意：车只往一个方向开。trips[i] = [passengers, start, end] 表示 passengers 个人在位置 start 上车、在位置 end 下车。车最多坐 capacity 人。问能不能接完所有乘客。

例子：trips = [[2, 1, 5], [3, 3, 7]]。位置 1～4 车上有第一批 2 人，位置 3～6 有第二批 3 人，位置 3 和 4 两批都在，共 5 人。capacity = 4 时返回 False，capacity = 5 时返回 True。

关键观察：在 end 下车的人到 end 时已经不占座，所以一单乘客占的是位置 start 到 end - 1，也就是“下标 start 到 end - 1 整体加 passengers”。全部加完还原，看每个位置的人数有没有超过 capacity。这正是开头公交车的类比。

def car_pooling(trips, capacity):
    difference = [0] * 1002                 # 位置 0～1000，再多一格
    for passengers, start, end in trips:
        difference[start] += passengers     # 上车
        difference[end] -= passengers       # 下车：end - 1 是最后一个占座的位置，再 + 1 就是 end
    on_board = 0
    for change in difference:
        on_board += change
        if on_board > capacity:
            return False
    return True

为什么下车写在 end 而不是 end + 1：区间是 start 到 end - 1，“right + 1”就是 end。这一步写错，会把恰好在同一个位置一下一上的两拨人算成同时在车上。

复杂度：时间 O(m + 位置的最大值)，额外空间 O(位置的最大值)。如果位置可以大到 109，开不了这么长的数组，就像实战里那样把差分存进 dict、按位置排序后累加，时间 O(m log m)。

二维差分（简述）

同样的想法可以搬到矩阵上：要把一块子矩形（第 top～bottom 行、第 left～right 列）整体加 delta，在 (行数 + 1) × (列数 + 1) 的二维差分数组上改四个角：

difference[top][left]               += delta
difference[top][right + 1]          -= delta
difference[bottom + 1][left]        -= delta
difference[bottom + 1][right + 1]   += delta    # 前两行把右下角多减了一次，加回来

还原时做一遍第 27 课提过的二维前缀和：每一格等于“它自己的差分 + 上面一格 + 左边一格 - 左上角一格”（左上角那一块被加了两次，要减掉一次）。练习里的 add_to_submatrices 是选做题，对应 LeetCode 2536。

复杂度汇总

操作直接改原数组差分数组
建差分数组—O(n)
区间整体加一次O(区间长度)，最坏 O(n)O(1)
m 次区间加之后拿到整个数组O(m · n)O(m + n)
改完马上查一个数O(1)O(n)，要先还原（交替进行就用第 42 课的树状数组）
二维子矩形加 m 次再还原O(m · 行数 · 列数)O(m + 行数 · 列数)

怎么认出这类题

  • “对很多个区间各加一个数，最后问每个位置的值”：差分 + 一次还原。
  • “每个时刻 / 位置被几个区间覆盖”“同一时刻最多几个”“车上最多几人”：每个区间是 +1 / -1 两格，还原后取最大值。
  • 坐标很大但区间不多：差分存进 dict，按坐标排序再累加（扫描线）。
  • 二维矩阵上反复给子矩形加数，最后看整个矩阵：二维差分。
  • 改和查交替出现：差分单独不够，要差分 + 树状数组（第 42 课）。

LeetCode 1854 · 人口最多的年份

题意：logs[i] = [birth, death] 是第 i 个人的出生和死亡年份。年份 x 的人口是那一年活着的人数：第 i 个人计入 x 年的人口，当且仅当 x 在闭区间 [birth, death − 1] 内，死亡当年不计入。返回人口最多的年份；有多个时返回最早的那一年。

例子：输入 logs = [[1950, 1961], [1960, 1971], [1970, 1981]]，输出 1960。1960 年前两人都活着，1970 年后两人都活着，人口都是 2；1961 年第一个人已经死亡不计入，取最早的 1960。

LeetCode 2536 · 子矩阵元素加 1

题意：n × n 矩阵 mat 初始全为 0。对每个查询 [row1, col1, row2, col2]，把左上角 (row1, col1)、右下角 (row2, col2) 的子矩阵（含边界）中每个元素加 1。返回执行完所有查询后的矩阵。

例子：输入 n = 3, queries = [[1, 1, 2, 2], [0, 0, 1, 1]]，输出 [[1, 1, 0], [1, 2, 1], [0, 1, 1]]。格子 (1, 1) 同时在两个子矩阵里，所以是 2。

数据范围：1 ≤ n ≤ 500，1 ≤ queries.length ≤ 104。

最容易错的地方

  • 差分数组没有多一格：right 是最后一个下标时，difference[right + 1] 越界报错。要么多开一格，要么特判，多开一格最省事。
  • 编号从 1 开始（题 1）：下标是编号减 1，right + 1 换算后正好是 last，容易多减或少减一个 1。动手前先用一个小例子算一遍。
  • 区间是左闭右开（题 2，[start, end)）：减回去的那格是 end，不是 end + 1。
  • 还原时加错范围：还原是“加到第 i 格，含第 i 格”。和第 27 课前缀和“前 i 个，不含第 i 个”差一位，写混了整体错开一格。
  • 边改边查：差分只适合“改完再查”。每次查都还原一遍，总复杂度又回到 O(m · n)。

测试里的主线例子就是上面的 [3, 1, 4, 1, 5, 9, 2, 6]，会检查 difference 每一格的值，可以对照上面两张图排错。

自测

1. 对 numbers 做一次差分、再做一次前缀和，会得到什么？反过来先做前缀和、再做差分呢？ 两种顺序都回到 numbers 本身，因为差分和前缀和互为逆操作。先前缀和再差分：相邻两个前缀和相减，剩下的正好是中间那一个数。
2. 一共有 m 次区间加、q 次“查某个下标的当前值”，而且两种操作穿插出现。只用差分数组，最坏复杂度是多少？ 每次查询都要从头加到那个下标，最坏 O(n)，总共 O(m + q · n)。如果查询很多，这和暴力差不多。第 42 课把差分数组放进树状数组，加和查都变成 O(log n)。
3. 拼车如果改成“end 那一站下车的人还占着座位”（区间变成两端都包含），代码要改哪里？ 减回去的那一格从 end 改成 end + 1，也就是 difference[end + 1] -= passengers。数组长度要能放下下标 end + 1：end 最大是 1000，下标 1001，上面开的 1002 格正好够，不用再加长。
