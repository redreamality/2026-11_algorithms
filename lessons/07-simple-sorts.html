第 7 课 · 简单排序（选择、插入）与稳定性

两种最朴素的排序：选择排序每轮挑出最小的放到前面；插入排序像理牌，把新牌插进左边已经排好的那一手里。都是 O(n²)。

问题直觉 核心定义与不变量 通用操作模板 题目与动画 应用场景 易错点与练习

开始前要会：Python —— lambda、key=、sorted 与 sort、排序稳定、itemgetter、@dataclass、多重赋值交换、range 与 enumerate、f-string 的 !r；前面的课 —— 第 0 课 · 复杂度（O(n²)、O(n log n)）。

问题直觉：如何把“乱序”变成“有序”

两种算法都维护一段已经排好的前缀：选择排序每轮从剩余部分找最小值，插入排序把下一个值插回前缀。先固定这条“已排前缀”视角，再看每一步为何不会破坏已有结果。

核心定义与不变量

选择排序的不变量是：开始第 start 轮时，items[:start] 已经按顺序排好，而且其中每个值都不大于未排序区。插入排序的不变量是：处理到 index 时，items[:index] 已经有序。

选择排序：每轮选一个最小的

左边是排好的，右边是没排的。每轮在右边找出最小的，和右边第一个交换，排好的部分就多一个。

12｜ 543 ← 右边最小是 3，和 5 交换 
def selection_sort(items):
    for start in range(len(items)):
        smallest = start
        for candidate in range(start + 1, len(items)):
            if items[candidate] < items[smallest]:
                smallest = candidate
        items[start], items[smallest] = items[smallest], items[start]

插入排序：像理手里的牌

左边已经有序。拿起下一个数，只要它左边的比它大，就把左边的往右挪一格，最后把它放进空出来的位置。

245 ⟵3 5、4 都比 3 大，往右挪；2 不比 3 大，停，3 放在 2 后面 
def insertion_sort(items):
    for index in range(1, len(items)):
        item = items[index]
        position = index - 1
        while position >= 0 and items[position] > item:   # 用 >，相等就停
            items[position + 1] = items[position]
            position -= 1
        items[position + 1] = item

通用操作模板：先维护已排前缀

选择排序的模板是“扫描未排序区 → 记录最小值位置 → 一次交换”；插入排序的模板是“保存当前值 → 把更大的值右移 → 放回空位”。相等元素是否跨过彼此，决定了稳定性。

复杂度与选择

选择排序插入排序
最好（已经有序）O(n²)，照样每轮找最小O(n)，每个数看一眼就停
最坏（完全倒序）O(n²)O(n²)
交换 / 挪动次数最多 n−1 次交换最坏 O(n²) 次挪动
额外空间O(1)O(1)
稳定否是

插入排序对近乎有序的数据特别快：每个数只需往左挪几步。所以小数组或“基本排好”的数组，实际中常用它（Python 的 Timsort 里就有它）。

稳定性：相等的元素别换位置

按分数给学生排序，小红和小刚都是 90 分，原来小红在前。稳定的排序保证排完后小红还在小刚前面。先按姓名排、再按分数稳定地排，就能得到“分数相同时按姓名”的结果。

2a2b1 → 选择排序：1 和 2a 交换 → 12b2a

选择排序的“远距离交换”会把 2a 甩到 2b 后面，所以不稳定。插入排序只在左边严格更大时才挪，相等的永远不越过彼此，所以稳定。

应用场景：标准库排序与稳定多字段排序

业务代码里没人手写排序。内置的 Timsort 稳定、O(n log n)、近乎有序时接近 O(n)。要学的是怎么用好它：

场景用什么代价
要一个新列表，原数据不动sorted(items, key=..., reverse=...)O(n log n)，额外 O(n)
就地排，省内存items.sort(...)，返回 NoneO(n log n)
按字段排key=lambda ticket: ticket.priority，或 key=operator.itemgetter("priority")（见预备课）key 每个元素只算一次
多字段、方向不同利用稳定性分两趟排；或数字取负号拼元组两趟就是 2 × O(n log n)
from operator import itemgetter

# 工单：优先级从高到低，同优先级按创建日期从早到晚
ordered = sorted(tickets, key=lambda ticket: ticket.created)   # 先按次要字段
ordered.sort(key=lambda ticket: ticket.priority, reverse=True) # 再按主要字段；稳定，日期顺序被保留

# 一趟写完也行：元组按字段依次比，数字字段取负号就反过来了
ordered = sorted(tickets, key=lambda ticket: (-ticket.priority, ticket.created))

sorted(file_names, key=str.casefold)    # 不区分大小写

题目与动画

先选 选择排序 点“排序”，再切到 插入排序 用同一组数比一比比较次数。默认数组里有两个 3（标了 a、b），留意排完后谁在前。再点 近乎有序，看插入排序有多快。

易错点与练习

  • 插入排序的条件写成 >=：结果还是对的，但不稳定了。
  • 插入排序挪完后，item 放在 position + 1，不是 position。
  • 有 key 时，比较的是 key，但挪动和交换的是元素本身。和 list.sort 一样，key 每个元素只算一次：先算好一个 keys 列表，挪元素时 key 跟着一起挪。
  • reverse=True 不能“先正着排再整个反转”：那样相等元素的次序也反了，不再稳定。正确做法是把比较方向反过来。

练习

补全 dsa/simple_sorts.py。接口和 list.sort 一样：原地排序、返回 None、只接受关键字参数 key= 和 reverse=。建议顺序：先写不带参数的 selection_sort → insertion_sort，再加 key，最后加 reverse（保持稳定）。

自测

1. 数组已经有序，两种排序各要比较多少次？ 选择排序还是 n(n−1)/2 次，因为它不知道“已经有序”；插入排序只要 n−1 次，每个数和左边比一次就停。
2. 什么时候选择排序反而更合适？ “写入”很贵的时候（比如写闪存）：它最多只交换 n−1 次，插入排序可能挪动 O(n²) 次。
3. 只有一种排序键时，稳定性还有用吗？ 元素就是数字本身时看不出区别；元素是记录（学生、订单）时就有用：可以先按次要字段排，再按主要字段稳定地排。
