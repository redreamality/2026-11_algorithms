第 10 课 · 二叉树与递归遍历

二叉树就是每个节点最多有两个孩子的链表。处理一棵树 = 处理根 + 处理左子树 + 处理右子树，所以几乎所有树的代码都是递归。

问题直觉 核心定义与不变量 通用操作模板 题目与动画 应用场景 易错点与练习

开始前要会：Python —— 生成器（yield）、yield from、@dataclass 与 isinstance、类型标注（X | None、引号前向引用）；前面的课 —— 第 5 课 · 递归与分治、第 3 课 · 队列（层序要用 deque）

问题直觉：把“处理一棵树”拆成三个动作

树没有数组那样的顺序下标，但每个节点都把问题分成“自己、左子树、右子树”。只要先约定访问根的时机，四种遍历就只是同一个递归模板的不同插入点。

通用操作模板：四种遍历与递归出口

四种遍历

前、中、后说的是根排在第几个，左永远在右前面：

遍历顺序上面这棵树
前序根 → 左 → 右1 2 4 5 3 6
中序左 → 根 → 右4 2 5 1 3 6
后序左 → 右 → 根4 5 2 6 3 1
层序一层一层，从左到右1 2 3 4 5 6

应用场景：配置、源代码与目录树

业务代码里几乎没人自己定义 TreeNode，但树形数据天天碰到，处理它们用的正是本课的递归遍历：

场景用什么代价
JSON / 配置的嵌套结构自己写递归生成器（dict、list 是有孩子的节点）O(n)，递归深度 = 嵌套层数
分析源代码标准库 ast：ast.walk 是层序，ast.NodeVisitor 是前序O(n)
目录树os.walk、pathlib.Path.rglobO(文件数)
def flatten(config, prefix=""):
    """把嵌套配置拍平成 ("database.port", 5432) 这样的路径。前序遍历。"""
    if isinstance(config, dict):
        children = config.items()
    elif isinstance(config, list):
        children = enumerate(config)
    else:
        yield prefix, config            # 叶子
        return
    for key, child in children:
        yield from flatten(child, f"{prefix}.{key}" if prefix else str(key))

dict(flatten({"database": {"host": "localhost", "port": 5432}, "debug": False}))
# {'database.host': 'localhost', 'database.port': 5432, 'debug': False}

完整可运行的版本在 examples/binary_tree_in_practice.py（uv run examples/binary_tree_in_practice.py），还演示了用 ast 列出“每个函数调用了谁”。注意它用的是 yield：遍历写成生成器，调用方可以 list() 全拿，也可以找到想要的就 break。

def preorder(root):
    if root is None:          # 空树：什么都不产出
        return
    yield root.val            # 根
    yield from preorder(root.left)
    yield from preorder(root.right)

list(preorder(root))          # [1, 2, 4, 5, 3, 6]

中序、后序只是把 yield root.val 挪个位置。yield from 的意思是“把子树产出的值原样转交出去”，比 [root.val] + preorder(...) + ... 每层都新建 list 省得多。

层序不用递归，用第 3 课的队列：出队一个，就把它的孩子入队。实际中常常要按层分组（比如“每一级有谁”），技巧是每轮先记下队列长度，只出队这么多个：

from collections import deque

def level_order(root):
    if root is None:
        return
    queue = deque([root])
    while queue:
        level = []
        for _ in range(len(queue)):        # 这一轮只处理当前这一层
            node = queue.popleft()
            level.append(node.val)
            if node.left is not None:
                queue.append(node.left)
            if node.right is not None:
                queue.append(node.right)
        yield level

list(level_order(root))       # [[1], [2, 3], [4, 5, 6]]

高度和节点数：同一个套路

def height(root):
    if root is None:
        return 0
    return 1 + max(height(root.left), height(root.right))

先写“空树返回什么”，再假设左右子树已经算好，想想怎么拼出答案。节点数就是 1 + 左 + 右。

操作时间额外空间
前 / 中 / 后序、高度、节点数O(n)O(h)，调用栈深度 = 树高
层序O(n)O(w)，w 是最宽一层的节点数

题目与动画

依次点四种遍历，用“上一步 / 下一步”看访问顺序。橙色是正在访问的节点，绿色是已经输出的；递归遍历下面会显示调用栈，层序显示队列。

易错点与练习

  • 忘了写空树的出口，递归一路走到 None.left 就报错。
  • 高度的定义：本课约定空树是 0、只有根是 1（有的书从 -1 数起）。
  • build_from_list 里，None 位置不会有孩子，后面的值要跳过它分给下一个真实节点。
  • 递归生成器里调用子树要写 yield from preorder(root.left)。只写 preorder(root.left) 会创建一个生成器然后丢掉，子树一个值都不会产出。

练习

补全 dsa/binary_tree.py。TreeNode 是 dataclass，两棵树结构和值都一样时 == 为 True，测试靠它比较。除了遍历，还要写两种序列化：层序列表（LeetCode 的写法，build_from_list / to_list）和可以直接 json.dumps 的嵌套 dict（to_dict / from_dict），都要能来回转换。json.dumps(对象) 把嵌套 dict/list 变成 JSON 字符串，json.loads(字符串) 再解析回来——这里只用它验证转换结果是能存盘、能走网络的普通数据。

建议顺序：preorder → inorder → postorder → count_nodes → height → level_order → to_dict / from_dict → build_from_list → to_list。

自测

1. 递归遍历额外占用多少空间？ 调用栈最深等于树高 h。平衡的树是 O(log n)，退化成一条链时是 O(n)。
2. 只给前序遍历的结果，能还原出树吗？ 不能，比如 [1, 2] 可能是 2 在左，也可能在右。给前序 + 中序（且值不重复）就可以。
3. 删除一棵树时（比如释放内存），该用哪种遍历？ 后序：先处理完两个孩子，再处理自己，不会出现“先删了父亲，孩子找不到”的问题。
