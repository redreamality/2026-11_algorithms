第 44 课 · 状压 DP

当 DP 的状态里要记住“哪些东西已经用过”，而东西只有十几个时，就把这个集合压缩成一个整数（位掩码），整数直接当数组下标。这就是状态压缩 DP，简称状压 DP。

阅读路线

阅读路线：先理解本课要解决的问题和核心模板，再看题目如何逐步套用；应用场景用于说明这个方法在真实代码里的位置，最后再做练习和自测。

开始前要会：Python —— math.inf、推导式（二维表）、itertools.permutations、functools.cache；前面的课 —— 第 39 课 · 位运算技巧（位掩码、bit_count）、第 21 课 · 回溯（枚举排列）、第 19 课 · DP（一）记忆化、第 37 课 · 一维 DP（四步法）。

本课一条主线：一个配送站，先给 3 个骑手分 3 单（题 1，热身），再给 1 个骑手规划跑 4 个点的路线（题 2，旅行商问题）。两题的状态里都有一个“已经处理过的集合”。

先定义几个词

  • 位掩码（第 39 课）：一个整数 mask，它的第 k 位是 1，表示第 k 个元素在集合里。n 个元素的所有子集，正好对应 0 到 2n − 1 这 2n 个整数。
  • 全集：所有元素都在，(1 << n) - 1，二进制是 n 个 1。
  • 状态压缩：把“一个集合”这种不好当下标的状态，压缩成一个整数，于是 DP 表可以写成普通的列表 best[mask] 或 shortest[mask][last]。

本课反复用到的四个操作（第 39 课的小招式）：

想做什么写法例子（mask = 0b1011）
第 k 个在不在集合里(mask >> k) & 1k = 2：0，不在
把第 k 个加进集合mask | (1 << k)k = 2：0b1111
把第 k 个从集合去掉（它原来在）mask ^ (1 << k)k = 1：0b1001
集合里有几个mask.bit_count()3

还有一个关键性质：往集合里加元素，整数一定变大；去掉元素，整数一定变小（多了一个 1，少了一个 1）。所以只要 mask 从小到大循环，用到的“少一个元素的集合”一定已经算好。这就是状压 DP 的遍历顺序。

应用场景：先看 n 有多大

n用什么为什么
≤ 8itertools.permutations 枚举所有顺序8! = 40320，最不容易写错
10～16状压 DP，functools.cache 写递归，参数里带一个 visited_mask状态数 2n × n，几十万到一百万
更大分配问题用匈牙利算法（scipy.optimize.linear_sum_assignment，O(n³)）；路线问题用启发式求近似解（Google OR-Tools）2n 太大，精确的状压也算不动（这两个库本课程不装）
import math
from functools import cache

def shortest_route_length(distance):              # 从 0 出发，每点去一次，回到 0
    count = len(distance)
    everything = (1 << count) - 1

    @cache
    def rest_of_trip(visited_mask, here):         # 去过 visited_mask、现在在 here，剩下最少还要走多远
        if visited_mask == everything:
            return distance[here][0]
        best = math.inf
        for next_place in range(count):
            if not (visited_mask >> next_place) & 1:
                best = min(best, distance[here][next_place] + rest_of_trip(visited_mask | (1 << next_place), next_place))
        return best

    return rest_of_trip(1, 0)                     # 1 = 0b1：只去过配送站

shortest_route_length([[0, 2, 9, 10], [2, 0, 6, 4], [9, 6, 0, 3], [10, 4, 3, 0]])    # 18

题 1：分配任务（热身）

题意：n 个骑手、n 个订单，cost[worker][task] 是骑手 worker 送订单 task 的花费。每个骑手正好送一单、每单正好一人送，总花费最少是多少？

例子：3 个骑手、3 单。

cost单 0单 1单 2
骑手 0927
骑手 1643
骑手 2581

最优是加粗的三格：2 + 6 + 1 = 9。贪心为什么不对：按顺序让每个骑手挑剩下最便宜的，骑手 0 挑单 1（2），骑手 1 挑单 2（3），骑手 2 只剩单 0（5），总共 10。骑手 1 抢走了骑手 2 最便宜的那单。

暴力做法为什么慢：每种分法就是订单的一个排列，一共 n! 种。n = 16 时约 2 × 1013 种，跑不完。

关键观察：让骑手按编号顺序接单：骑手 0 先挑，然后骑手 1……那么“已经分出去的订单集合”就能说明一切：

  • 集合里有几单，就说明前几个骑手已经安排好了（mask.bit_count() 个）。
  • 后面的骑手怎么分，只取决于还剩哪些单，跟前面谁拿了哪单的具体对应无关。

暴力枚举会把“骑手 0 拿单 1、骑手 1 拿单 0”和“骑手 0 拿单 0、骑手 1 拿单 1”当成两条路分别往下走，但它们走到的是同一个状态“单 0、单 1 已分出去”，只需要保留花费更少的那条。状态从 n! 个排列缩成了 2n 个集合。

套四步法：

  1. 状态：best[assigned_mask] = 订单集合 assigned_mask 已经分给前 assigned_mask.bit_count() 个骑手时的最少花费。
  2. 转移：最后安排的是骑手 worker = assigned_mask.bit_count() - 1，他送的是集合里的某一单 task。去掉这一单，就是安排他之前的状态： 
    best[assigned_mask] = min(best[assigned_mask ^ (1 << task)] + cost[worker][task]
                          for task in range(n) if (assigned_mask >> task) & 1)
  3. 初始值：best[0] = 0，一单都没分，不花钱。
  4. 遍历顺序：assigned_mask 从 1 到 2n − 1 从小到大。答案在 best[(1 << n) - 1]。

复杂度：2n 个状态，每个状态试 n 单，O(2n × n) 时间，O(2n) 空间。n = 20 约 2000 万次，Python 几秒。

题 2：旅行商问题（TSP，本课主线）

题意：骑手从 0 号点（配送站）出发，每个点正好去一次，最后回到配送站。distance[a][b] 是从 a 到 b 的距离。最短要走多远？

例子：4 个点，0 = 配送站、1 = 东门、2 = 图书馆、3 = 南门。

distance0123
002910
12064
29603
310430

最短路线 0 → 1 → 3 → 2 → 0，长度 2 + 4 + 3 + 9 = 18（反方向走一样长）。

暴力做法为什么慢：除了起点，剩下 n − 1 个点的每种顺序都是一条路线，一共 (n − 1)! 条。n = 15 时约 8.7 × 1010 条。

关键观察：走到半路时，接下来最少还要走多远，只取决于两件事：已经去过哪些点、现在停在哪。至于是按什么顺序去的，后面根本不关心。比如“0 → 1 → 3”和“0 → 3 → 1”去过的集合都是 {0, 1, 3}，但一个停在 3、一个停在 1，所以停在哪也要记。于是状态是“集合 + 当前点”，一共 2n × n 个。

套四步法：

  1. 状态：shortest[visited_mask][last] = 从 0 出发，正好走过 visited_mask 里的点，现在停在 last，最短走了多远。visited_mask 一定包含 0 和 last，不满足的格子没有意义（保持 math.inf）。
  2. 转移：停在 last 之前的那一站叫 previous，它在“去掉 last 的集合”里： 
    previous_mask = visited_mask ^ (1 << last)
shortest[visited_mask][last] = min(shortest[previous_mask][previous] + distance[previous][last]
                                   for previous in range(n) if (previous_mask >> previous) & 1)
  3. 初始值：shortest[1][0] = 0。1 就是 0b0001，只去过配送站，停在配送站，走了 0。
  4. 遍历顺序：visited_mask 从小到大（previous_mask 比它少一个 1，一定更小）。所有点都走过以后还要回站，答案是 min(shortest[全集][last] + distance[last][0])。
import math

def shortest_round_trip(distance):
    n = len(distance)
    if n <= 1:
        return 0
    shortest = [[math.inf] * n for _ in range(1 << n)]
    shortest[1][0] = 0
    for visited_mask in range(1, 1 << n):
        if not visited_mask & 1:                     # 不含配送站的集合没有意义
            continue
        for last in range(1, n):
            if not (visited_mask >> last) & 1:
                continue
            previous_mask = visited_mask ^ (1 << last)
            for previous in range(n):
                if (previous_mask >> previous) & 1:
                    candidate = shortest[previous_mask][previous] + distance[previous][last]
                    shortest[visited_mask][last] = min(shortest[visited_mask][last], candidate)
    everything = (1 << n) - 1
    return min(shortest[everything][last] + distance[last][0] for last in range(1, n))

为什么对：任何一条合法路线，走到某一步时都处在某个状态 (visited_mask, last)，而且它前面那一段一定能换成到达这个状态的最短走法（换了以后后面照样能走，总长只会更短）。所以每个状态只记最短值不会丢掉最优路线。

O(2n × n²) 什么时候能用

TSP 有 2n × n 个状态，每个状态试 n 个 previous，所以 O(2n × n²) 时间、O(2n × n) 空间。笔试看到数据范围就该反应过来：

n2n × n²(n − 1)!（暴力）Python 实测（上面这段代码）
10约 10 万36 万0.01 秒
12约 59 万4000 万0.03 秒
15约 740 万8.7 × 10100.3 秒
16约 1700 万1.3 × 10120.8 秒
20约 4.2 亿1.2 × 1017按增长速度估算要半分钟左右，笔试必超时

（实测比 2n × n² 这个数快，是因为不含配送站、不含 last 的状态都被 continue 跳过了。）经验规则：题目给 n ≤ 15 或 16，又要“每个都用一次”“访问所有点”，基本就是状压 DP；只要 O(2n × n) 的（像题 1），n 可以到 20。n 到 30 时 230 已经超过 10 亿，状压就不行了。另外空间也要算：n = 20 时 2n × n 是两千万格，一个 Python 列表的格子要 8 字节，表本身就要一百多 MB。

怎么认出这类题

  • n 很小（≤ 20，常见 ≤ 15 或 16），这是最强的信号。一般的 DP 题 n 都是几百几千。
  • 题目要求“每个都正好用一次”“访问所有点”“把 n 个东西分配给 n 个人”。
  • 写回溯（第 21 课）时发现：不同的走法会走到“用过的东西一样、当前位置一样”的局面，后面的事完全相同。这就是可以合并的重复状态。
  • 状态要记“哪些用过了”：用 set 当状态既慢又不能当列表下标，换成位掩码。

LeetCode 1879 · 两个数组最小的异或值之和

题意：两个长度都是 n 的整数数组 nums1、nums2，异或值之和定义为 (nums1[0] XOR nums2[0]) + (nums1[1] XOR nums2[1]) + … + (nums1[n − 1] XOR nums2[n − 1])。可以任意重新排列 nums2，返回重新排列后异或值之和的最小值。它就是 正文题 1 的分配问题。

例子：输入 nums1 = [1, 2]，nums2 = [2, 3]，输出 2。把 nums2 排成 [3, 2]，得到 (1 XOR 3) + (2 XOR 2) = 2 + 0 = 2。

数据范围：n ≤ 14，0 ≤ nums1[i]、nums2[i] ≤ 107。

LeetCode 526 · 优美的排列

题意：用 1 到 n 这 n 个整数组成一个排列 perm（下标从 1 开始）。如果对每个位置 i（1 ≤ i ≤ n），perm[i] 能被 i 整除或 i 能被 perm[i] 整除，就称它是优美的排列。返回优美的排列的数量。

例子：输入 n = 2，输出 2。[1, 2] 和 [2, 1] 都满足：位置 1 上的数总能被 1 整除；[2, 1] 的位置 2 上是 1，2 能被 1 整除。

数据范围：n ≤ 15。

LeetCode 847 · 访问所有节点的最短路径

题意：n 个节点（编号 0 到 n − 1）的无向连通图，graph[i] 是与节点 i 相邻的节点列表。返回访问所有节点的最短路径长度（经过的边数）。可以从任意节点出发、在任意节点结束，可以重复访问节点、重复走边。

例子：输入 graph = [[1, 2, 3], [0], [0], [0]]，即边 0–1、0–2、0–3（节点 0 在中间），输出 4，一条最短路径是 1 → 0 → 2 → 0 → 3。

数据范围：n ≤ 12。

LeetCode 943 · 最短超级串

题意：给定字符串数组 words，返回一个最短的字符串，使 words 里的每个字符串都是它的子串。有多个最短答案时返回任意一个。保证 words 里没有一个字符串是另一个的子串。

例子：输入 words = ["alex", "loves", "leetcode"]，输出 "alexlovesleetcode"。这三个词任意两个首尾都不重叠，所以按任何顺序直接拼接都是 17 个字母，都是正确答案。

数据范围：words 最多 12 个，每个长度 ≤ 20，只含小写字母且互不相同。

LeetCode 698 · 划分为 k 个相等的子集

题意：给定整数数组 nums 和正整数 k，判断能否把 nums 分成 k 个非空子集，使每个子集的元素和都相等。返回 true 或 false。

例子：输入 nums = [4, 3, 2, 3, 5, 2, 1]，k = 4，输出 true。总和 20，每组和为 5：(5)、(1, 4)、(2, 3)、(2, 3)。

LeetCode 1125 · 最小的必要团队

题意：req_skills 是项目需要的技能列表，people[i] 是第 i 个人掌握的技能列表。如果一组人里，每项需要的技能都至少有一人掌握，就称这组人是必要团队。返回人数最少的必要团队，用人员编号的列表表示，顺序任意；有多个答案时返回任意一个。保证答案存在。

例子：输入 req_skills = ["java", "nodejs", "reactjs"]，people = [["java"], ["nodejs"], ["nodejs", "reactjs"]]，输出 [0, 2]。0 号会 java，2 号会 nodejs 和 reactjs，两人就够；只用一人覆盖不全。

数据范围：req_skills 最多 16 项，people 最多 60 人。

最容易错的地方

  • 运算符优先级：1 << n - 1 是 1 << (n - 1)，不是 (1 << n) - 1。全集一定写成 (1 << n) - 1。判断用 (mask >> k) & 1，养成加括号的习惯（第 39 课）。
  • 用异或“加入”元素：mask ^ (1 << k) 在第 k 位已经是 1 时会把它去掉。加入用 |，确定在集合里时才用 ^ 去掉。
  • TSP 忘了回起点：shortest[全集][last] 只走到了 last，答案还要加 distance[last][0]。题目说“不用回来”时才不加。
  • 初始值：TSP 是 shortest[1][0] = 0，不是 shortest[0][0]，起点本身也在集合里。
  • n = 1：只有配送站，range(1, n) 是空的，min() 会报错，要单独返回 0。

自测

1. 为什么 mask 从小到大循环，就能保证转移用到的状态已经算好？ 转移用的是“去掉一个元素的集合” mask ^ (1 << k)，它比 mask 少一个二进制的 1，作为整数一定更小。从小到大循环时，更小的整数在之前就处理过了。
2. TSP 的状态为什么要同时记集合和当前点，只记集合不行吗？ 不行。下一步走到哪个点，距离取决于现在停在哪。去过 {0, 1, 3} 停在 1 和停在 3，接下来去 2 的距离分别是 6 和 3，后面的最优走法也不同，不能合成一个状态。
3. 题目给 n ≤ 50，要求每个点访问一次，还能用状压 DP 吗？ 不能。250 约 1015，状态都存不下。这时要找题目的其他结构（比如图是一棵树、点在一条线上），或者题目只要近似解。看到 n ≤ 15～20 才考虑状压。
