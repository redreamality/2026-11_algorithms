第 21 课 · 回溯

回溯 = 试一步，不行就退回来换一条路。像走迷宫：每个岔口挑一条走，走到死胡同就退回上一个岔口。

实战里怎么写：先看 itertools 够不够

只是“把所有排列 / 组合列出来”，标准库 itertools 已经写好了，而且都是惰性生成器：要几个算几个。

场景用什么代价
几个步骤的所有顺序、值班轮换itertools.permutationsn! 个
从候选人里挑 k 个组队itertools.combinationsC(n, k) 个
CI 测试矩阵、所有配置组合itertools.product各维度大小相乘
约束多、规模大：排班、数独、选课自己写回溯生成器，边放边检查最坏指数级，靠剪枝提速

完整可运行的版本在 examples/backtracking_in_practice.py（uv run examples/backtracking_in_practice.py）。itertools 管不了“边生成边检查约束”，这时就要自己写回溯。下面看它的结构。

三步模板：选择 → 递归 → 撤销

写成生成器，每找到一个解就 yield 出去，用法就和 itertools 一样了：

def permutations(items):
    used = [False] * len(items)
    path = []

    def walk():
        if len(path) == len(items):          # 结束条件：放满了
            yield tuple(path)                # 交出副本！之后 path 还会被撤销改掉
            return
        for index, item in enumerate(items):
            if used[index]:
                continue
            used[index] = True
            path.append(item)                # ① 选择
            yield from walk()                # ② 递归，把下层找到的解原样往上交
            path.pop()                       # ③ 撤销，恢复原样再试下一个
            used[index] = False

    yield from walk()

next(permutations(list(range(20))))          # 马上返回；20! 个排列不会全算出来

“撤销”是回溯的灵魂：从递归回来时，状态必须和进去前一模一样，下一个选项才能在干净的状态上试。

决策树：子集 [1, 2, 3]

每一层对一个数做二选一：要，或不要。叶子就是答案，一共 23 = 8 个。

第 1 层（1）：要 1不要 1
第 2 层（2）：要 2不要 2……每个节点都再分两叉
叶子：[1,2,3][1,2][1,3][1][2,3][2][3][]

回溯就是深度优先地走一遍这棵树：一路走到叶子，再退回最近的岔口换另一边。

四道经典题

题每层在选什么答案个数 / 时间
全排列还没用过的数里挑一个（用 used 记录）n! 个，O(n · n!)
子集当前这个数要不要2n 个，O(n · 2n)
组合总和从 start 往后挑一个数（可重复选）看数据，靠剪枝提速
N 皇后这一行的皇后放第几列最坏 O(n!)，剪枝后快得多

剪枝：早点发现走不通

决策树往往大得吓人，回溯快不快全看能剪掉多少枝。在“选择”之前先判断，注定失败就别往下走：

  • N 皇后：这一格和已放的皇后同列或同斜线，直接跳过。用集合记录占用的列、r - c、r + c，判断是 O(1)。
  • 组合总和：候选数排好序，当前数已经大于剩下的 target，后面更大的也不用试，break。

动手玩

建议依次试试：n = 4 点 找第一个解，用“上一步 / 下一步”慢慢看：红色 × 是冲突被剪掉的格子，橙色是和它冲突的皇后；再点 找全部解，看找到一个解之后它怎么继续回溯；最后把 n 改成 5，对比尝试次数。

最容易错的三个地方

  • 直接 yield path：交出去的是同一个列表的引用，调用方一保存，撤销完它们全变成空列表。要 yield tuple(path)。
  • 递归调用写成 walk() 而不是 yield from walk()：生成器函数被调用时什么都不执行，下层的解全丢了。
  • 忘了撤销，或者撤销得不完整（N 皇后三个集合都要删）。
  • 组合总和出现 [2, 3] 和 [3, 2]：没用 start 限制“只往后选”。

补全 dsa/backtracking.py。每个函数都是生成器，逐个 yield tuple；permutations 的顺序要和 itertools.permutations 完全一样，n_queens 产出每个解的摆法（第 row 行放在第几列），数个数用 sum(1 for _ in n_queens(8))。建议顺序：subsets → permutations → combination_sum → n_queens →（选做）solve_sudoku。

自测

1. 回溯和普通递归有什么区别？ 回溯就是递归，只是多了“撤销”：所有分支共用同一份 path 和状态，从子调用回来时要把改动恢复原样。
2. 全排列为什么需要 used，而子集不需要？ 全排列每层可以挑任何没用过的数，所以要记录谁用过了；子集每层只决定“下标 i 这个数”要不要，按下标往后走，天然不会重复用。
3. 回溯和动态规划都在“穷举”，什么时候用哪个？ 要列出所有方案用回溯；只要方案个数或最优值，且子问题会重复出现，用 DP 更快。
