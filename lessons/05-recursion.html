第 5 课 · 递归与分治

递归就是函数调用自己。只要两样东西：一个能直接回答的最小问题，和把大问题缩小一点再交给自己。

先理解核心对象模板与不变量应用场景练习与自测

开始前要会：Python —— yield from、生成器（yield）、@functools.cache、isinstance、类型标注（Iterator）、异常（raise ValueError）、生成器表达式、f-string 的 !r；前面的课 —— 第 0 课 · 复杂度（O(...) 记号）。

先理解：大问题如何交给更小的问题

递归适合“里面还有同样结构”的问题：先处理当前层，再把更小的一层交给同一个函数，最后把结果接回来。

应用场景：递归用在“递归形状”的数据上

业务代码里没人手写阶乘和幂，math.factorial、pow 都现成。真正要自己写递归的，是数据本身一层套一层的时候：

场景用什么代价
遍历目录树标准库 Path.rglob / os.walk，不用自己递归O(文件数)
嵌套 JSON、组织架构、评论楼中楼自己写一个几行的递归函数O(节点数)，栈深 = 嵌套层数
同一个子问题被反复算@functools.cache 记忆化（见预备课；原理第 19 课细讲，这里先用）指数级降到“子问题个数”
数据可能极深（用户上传的 JSON）改用显式栈 stack = [...] + while不受约 1000 层的递归上限限制
from functools import cache
from pathlib import Path

def find_values(document, wanted_key):
    """在任意嵌套的 JSON 里收集某个键的所有值，例如所有 "email"。"""
    found = []
    if isinstance(document, dict):
        for key, child in document.items():
            if key == wanted_key:
                found.append(child)
            found.extend(find_values(child, wanted_key))   # 往深处交给自己
    elif isinstance(document, list):
        for child in document:
            found.extend(find_values(child, wanted_key))
    return found                                            # 基线：其他值什么都不找

total_bytes = sum(path.stat().st_size for path in Path("logs").rglob("*") if path.is_file())

@cache
def ways_to_climb(steps):            # 每次走 1 或 2 级，有几种走法
    if steps <= 1:
        return 1
    return ways_to_climb(steps - 1) + ways_to_climb(steps - 2)

完整可运行的版本在 examples/recursion_in_practice.py（uv run examples/recursion_in_practice.py）。下面看递归本身是怎么工作的。

核心对象：基线与缩小后的问题

模板与不变量：两个要素

两个要素

def factorial(number):
    if number < 0:
        raise ValueError("number must be >= 0")   # 和 math.factorial(-1) 一样
    if number <= 1:                             # ① 基线条件：小到能直接回答
        return 1
    return number * factorial(number - 1)       # ② 缩小问题：相信 factorial(number-1) 能算对

类比：排队时想知道自己排第几，问前面的人“你排第几？”，他再问他前面的……问到第一个人（基线），答案再一路传回来。

写递归时不要在脑子里展开每一层。只要确认：基线对，而且“假设小一号的问题已经算对，我这一层能拼出答案”，整个函数就是对的。

调用栈：每一层都在等

每调用一次函数，就往调用栈上压一层，记住它的参数和“算到哪了”。算 factorial(3) 时最深的那一刻：

factorial(1)← 栈顶：基线，返回 1
factorial(2)等 factorial(1)
factorial(3)等 factorial(2)

然后从栈顶开始一层层返回、弹出。栈有多深，就占多少内存：factorial(n) 的空间是 O(n)。Python 默认只允许约 1000 层，再深就抛 RecursionError。

动手玩

先用 n = 4 点 factorial(n)，看栈怎么先长高再变矮；再点 fib(n)，看 fib(2)、fib(1) 被反复算了好几遍，调用次数远多于栈的深度。

分治：一刀切成两半

分治 = 把问题分成几个同样的小问题，分别治好，再合起来。它是递归最常见的用法，后面的二分查找、归并排序、快速排序都是这个套路。

快速幂：算 x8 不用乘 7 次，先算一半再平方：

x⁸←平方x⁴←平方x²←平方x¹ n 是奇数时再多乘一个 x

汉诺塔：要把 n 个盘子从 A 搬到 C，就先把上面 n-1 个搬到 B，再把最大的搬到 C，最后把 n-1 个从 B 搬到 C。中间那两步“搬 n-1 个”交给递归，不用自己想。

复杂度

函数时间栈深度
factorial(n)O(n)O(n)
power(base, exponent) 快速幂O(log n)O(log n)
flatten、flatten_json、directory_sizeO(节点总数)O(嵌套层数)
朴素 fib(n)约 O(2n)O(n)
hanoi(n)O(2n)，共 2n-1 步O(n)

最容易错的三个地方

  • 忘了基线，或者问题没有真的变小：无限递归，最后 RecursionError。
  • 快速幂里写成 power(base, exponent // 2) * power(base, exponent // 2)：同一半算了两次，又退回 O(n)。先存进变量再平方。
  • 递归里改了传进来的数据（比如对 JSON 做 pop）：调用者的数据被你弄坏了。要返回新结果，不要改输入。
  • 生成器递归时写成 flatten(child) 而不是 yield from flatten(child)：只是建了一个生成器对象，里面的值一个都没产出。

练习与自测

练习

补全 dsa/recursion.py：“往深处走”一律用递归，同一层的兄弟可以用 for 挨个处理。建议顺序：factorial → power → flatten（用 yield from）→ flatten_json（把嵌套订单摊平成表格的一行）→ directory_size（用 Path.iterdir()，不许用 rglob）。

自测

1. 列表求和写成 items[0] + total(items[1:])，有什么代价？ 每次切片都复制一份列表，总共 O(n²)，而且 1000 个元素就撞上递归上限。这种“线性”的数据直接用 sum(items) 或循环；递归留给树形、嵌套的数据。
2. 朴素 fib(n) 为什么这么慢？怎么救？ 同一个 fib(k) 被重复算了指数多次。把算过的结果存起来（记忆化），每个 k 只算一次，就变成 O(n)。实战里在函数上加一行 @functools.cache 就行，第 19 课细讲。
3. 递归一定比循环慢吗？ 复杂度一样时，递归多了函数调用的开销，常数大一点，还受栈深度限制。但树、分治这类问题用递归写清楚得多。
