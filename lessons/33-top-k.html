第 33 课 · 堆与 Top K

“最大的 K 个”“第 K 大”“出现最多的 K 个”这类问题，核心技巧是：用一个只装 K 个元素的堆当“候选名单”，新元素来了只和名单里最差的那个（堆顶）比较。找最大的 K 个要用小顶堆，方向和直觉相反。

开始前要会：Python —— Counter 与 most_common、lambda 与 key=、@dataclass、*args（实战里的 heapq.merge(*logs)）、生成器、类型标注（引号前向引用）；前面的课 —— 第 12 课 · 堆与优先队列（heapq 的用法）、第 29 课 · 链表高频技巧（哑节点，题三用）。

这一课默认你已经学过第 12 课（堆与优先队列）。第 12 课手写过堆，这一课直接用 Python 标准库 heapq：

写法作用时间
heapq.heappush(heap, item)放进一个元素O(log n)
heapq.heappop(heap)弹出并返回最小的元素O(log n)
heap[0]看一眼最小的元素，不弹出O(1)
heapq.heapify(items)把一个列表原地变成堆O(n)

heapq 只有最小堆（小顶堆）。要用最大堆时，放进去的是相反数 -num，取出来再取反：最小的相反数，对应的就是最大的原数。堆里也可以放元组，例如 (出现次数, 数)，元组按第一项比较，第一项相等再比第二项。

实战里怎么写：标准库已经包好了

业务代码里很少自己维护“大小为 k 的堆”。下面这些标准库函数内部用的就是本课的技巧，直接调用即可：

场景用什么代价
出现次数最多的 k 个（热门接口、高频词）collections.Counter(...).most_common(k)统计 O(n)，取前 k 个 O(m log k)
按某个字段最大 / 最小的 k 个（最慢的请求、最便宜的商品）heapq.nlargest(k, items, key=...) / heapq.nsmallestO(n log k)，可以直接吃生成器，不用全部装进内存
几份各自有序的日志 / 分片合并成一条有序流heapq.merge(*iterables, key=...)O(N log k)，懒惰地一条一条产出
k 接近 n，或者本来就要全部排好序sorted(items, key=...)[:k]O(n log n)，此时反而更快更清楚
import heapq
from collections import Counter

# 两台服务器的访问日志，各自按时间排好序：合并成一条时间线，不需要拼起来再整体排序
timeline = list(heapq.merge(server_a_log, server_b_log, key=lambda request: request.timestamp))

# 访问次数最多的 2 个接口：[('/api/orders', 4), ('/api/users', 2)]
busiest_paths = Counter(request.path for request in timeline).most_common(2)

# 最慢的 3 个请求，从慢到快
slowest_requests = heapq.nlargest(3, timeline, key=lambda request: request.latency_ms)

完整可运行的版本在 examples/top_k_in_practice.py（uv run examples/top_k_in_practice.py）。数据流中位数标准库没有现成的：statistics.median 每次都要整体排序；要在不断加入数据的同时随时查询，还是要用本课题四的双堆。下面的练习就是把这些函数背后的堆自己写一遍。

怎么认出这类题

  • 题目里有“第 K 大 / 第 K 小”“前 K 个”“最大的 K 个”“最接近的 K 个”“出现频率最高的 K 个”：大小为 K 的堆。
  • 有“合并 K 个有序的……”：把每一路的当前最小值放进堆，每次取出全局最小的那个。
  • 有“数据流”“动态地不断加入”，同时要随时回答“目前的最大 / 最小 / 中位数”：堆，中位数用两个堆。
  • 暴力做法是“全部排序再取前 K 个”，而 K 远小于 n：可以用堆把 O(n log n) 降到 O(n log k)。

题一：数组中的第 K 个最大元素（LeetCode 215）

题意：返回数组从大到小数的第 k 个数，重复的数分别计数。例如 [3, 2, 1, 5, 6, 4]，k = 2：从大到小是 6, 5, 4, 3, 2, 1，第 2 个是 5。

暴力做法：排序后取 nums[len(nums) - k]，时间 O(n log n)。它是对的，但做了很多没必要的事：我们只关心最大的 k 个，其余 n − k 个数之间谁大谁小根本不重要。

关键观察：只要一直维护“目前见过的最大的 k 个数”这份名单，扫完整个数组后，名单里最小的那个就是第 k 大。

为什么用小顶堆：新来一个数时，要决定它能不能进名单。它要挤掉的是名单里最小的那个，所以我们需要随时拿到名单里的最小值——这正是小顶堆的堆顶。用大顶堆的话，堆顶是名单里最大的数，对“谁该被淘汰”没有帮助。

做法：名单叫 min_heap_of_k_largest。每来一个数 num：先 heappush 进去；如果堆里超过了 k 个，就 heappop 一次，弹出这 k + 1 个里最小的。扫完后返回 min_heap_of_k_largest[0]。

为什么对：每一步之后，堆里都恰好是“目前见过的数里最大的 k 个”（不足 k 个时就是全部）：新数进来后，k + 1 个候选里最小的那个不可能属于最大的 k 个，弹出它就对了。

复杂度：每个数最多一次 push、一次 pop，每次 O(log k)，总时间 O(n log k)；堆只占 O(k) 空间。k 很小时，比排序快得多，而且数据可以一边读一边处理，不需要全部装进内存。

补充：这题还有一种平均 O(n) 的“快速选择”做法，就是第 9 课快速排序的分区，只递归进答案所在的那一边。面试里两种都常见，堆的写法更不容易出错。

题二：前 K 个高频元素（LeetCode 347）

题意：返回出现次数最多的 k 个数，顺序随意。例如 [1, 1, 1, 2, 2, 3]，k = 2：1 出现 3 次，2 出现 2 次，3 出现 1 次，答案是 [1, 2]。

暴力做法：统计次数后，按次数把所有不同的数排序，取前 k 个。设不同的数有 m 个，时间 O(n + m log m)。

关键观察：统计完次数之后，问题就变成了“在 m 个（数, 次数）里找次数最大的 k 个”，和题一是同一个问题，只是比较的是次数。

做法：① 用字典 count_of_number 统计每个数出现几次；② 遍历字典，把 (次数, 数) 放进大小为 k 的小顶堆，超过 k 个就弹出次数最少的；③ 堆里剩下的 k 个元组，取出其中的数就是答案。把次数放在元组的第一项，堆才会按次数比较。

复杂度：统计 O(n)，堆的部分 O(m log k)，总共 O(n log k) 以内；字典占 O(m) 空间。

补充：还有一种 O(n) 的“桶”做法：次数最多是 n，开 n + 1 个桶，第 c 个桶放出现了 c 次的数，从最大的桶往回收集 k 个。

题三：合并 K 个升序链表（LeetCode 23）

题意：给 k 个各自升序的链表，合并成一个升序链表。例如 1→4→5、1→3→4、2→6 合并成 1→1→2→3→4→4→5→6。设所有链表一共有 N 个节点。

暴力做法：把所有值收集起来排序再建链表，O(N log N)。或者像第 8 课归并排序那样，拿第一个链表依次和后面每个链表两两合并：结果链表越来越长，每次合并都要把它从头走一遍，最坏 O(N · k)。

关键观察：结果链表的下一个节点，一定是某个链表的当前头节点（每个链表自己是升序的，头节点就是它剩下部分的最小值）。所以只需要在这 k 个头节点里找最小的——这正是堆擅长的：最多 k 个元素，反复取最小值。

做法：先把每个非空链表的头节点放进小顶堆。然后反复：弹出值最小的节点，接到结果链表的末尾；如果它后面还有节点，把那个节点放进堆，补上这个链表的位置。堆空了就合并完了。结果链表用一个哑节点 dummy_head 开头，省得单独处理“第一个节点”。

一个 Python 的坑：堆里不能直接放 (节点值, 节点)。两个节点值相等时，元组会接着比较第二项，而 ListNode 之间没有定义大小，会报 TypeError。解决办法是在中间加一个链表编号：(节点值, 链表编号, 节点)。值相等时比较编号，编号互不相同，就永远不会比较到节点本身。

复杂度：每个节点进出堆各一次，堆里最多 k 个元素，总时间 O(N log k)，额外空间 O(k)。

题四：数据流的中位数（LeetCode 295）——本课重点

题意：数一个一个地到来，要随时回答“目前所有数的中位数”。中位数是排好序后正中间的数；个数为偶数时，取中间两个数的平均值。例如依次加入 5、15、1：加入 5 后中位数是 5；加入 15 后是 (5 + 15) / 2 = 10；加入 1 后排好序是 1, 5, 15，中位数是 5。

暴力做法为什么慢：每次查询都把所有数排序，一次 O(n log n)。改进一点：维护一个有序列表，每来一个数用二分找到位置插进去。找位置是 O(log n)，但在 Python 列表中间插入要把后面的元素整体往后挪，是 O(n)。

关键观察：中位数只关心“正中间”的一两个数，不需要整体有序。把所有数分成较小的一半和较大的一半，那么中位数只和两个数有关：较小一半里的最大值，和较大一半里的最小值。“随时拿到最大值 / 最小值”正是堆做的事。

两个堆：

  • max_heap_of_smaller_half：放较小的一半，是大顶堆（heapq 里存相反数），堆顶是这一半的最大值。
  • min_heap_of_larger_half：放较大的一半，是小顶堆，堆顶是这一半的最小值。

任何时候都要保持两个条件：

  1. 有序：较小一半里的每个数都 ≤ 较大一半里的每个数。（只要比较两个堆顶就能确认。）
  2. 平衡：较小一半的个数等于较大一半，或者正好多 1 个。

有了这两个条件，中位数就很简单：总数是奇数时，较小一半多 1 个，它的堆顶就是正中间的数；总数是偶数时，两边一样多，中位数是两个堆顶的平均值。都是 O(1)。

加入一个数 num 的三步：

  1. 先把 num 放进较小的一半。
  2. 把较小一半的最大值弹出来，放进较大的一半。
    为什么：num 可能比较大一半里的某些数还大，直接留在较小一半会破坏“有序”。这一步送走的，是“原来的较小一半加上 num”里最大的数，所以留下的数都 ≤ 它。留下的数也都 ≤ 原来较大一半的每个数：原来较小一半的数本来就满足；如果 num 被留下了，说明 num ≤ 被送走的那个原有的数，而那个数 ≤ 较大一半的每个数。所以有序条件重新成立。
  3. 如果这时较大的一半比较小的一半多了，把较大一半的最小值弹出来，放回较小的一半。
    为什么：第 2 步总是往较大一半送一个数，可能让它变多，破坏“平衡”。送回去的是较大一半的最小值，它 ≥ 较小一半的所有数，放到较小一半里成为新的最大值，有序条件不受影响。

三步里每次 push / pop 都是 O(log n)，所以加入一个数是 O(log n)，查询中位数 O(1)。下面的动画一步步演示这三步。

复杂度汇总

题堆里放什么堆的大小时间
第 K 大目前最大的 k 个数（小顶堆）kO(n log k)
前 K 个高频(次数, 数)，次数最多的 k 个（小顶堆）kO(n log k)
合并 K 个链表(值, 链表编号, 节点)，每个链表的当前头kO(N log k)，N 是节点总数
数据流中位数较小一半（大顶堆）+ 较大一半（小顶堆）各约 n / 2加入 O(log n)，查询 O(1)

最容易错的地方

  • 堆的方向反了：找最大的 k 个用小顶堆（堆顶是名单里最容易被淘汰的那个）；找最小的 k 个用大顶堆。
  • 先 push 再判断大小：先放进去，超过 k 个再弹出。如果先拿新数和堆顶比较再决定要不要放，也可以，但要处理“堆还不满 k 个”的情况，更容易漏。
  • 最大堆忘了取反：放进去是 -num，取出来、看堆顶时都要再取反一次。
  • 堆里放了不能比较的对象：合并链表时元组中间要加编号。
  • 中位数是整数还是小数：偶数个时要除以 2，用 / 不要用 //，否则 (5 + 4) // 2 得到 4 而不是 4.5。

LeetCode 703 · 数据流中的第 K 大元素

题意：设计一个类，找出数据流中第 k 大的元素（是排序后的第 k 大，不是第 k 个不同的元素）。实现 KthLargest 类：

  • KthLargest(k, nums)：用整数 k 和初始整数数组 nums 初始化对象。
  • add(val)：把 val 加入数据流，返回当前数据流中第 k 大的元素。

LeetCode 973 · 最接近原点的 K 个点

题意：给定数组 points，其中 points[i] = [xi, yi] 是平面上的一个点，再给定整数 k，返回离原点 (0, 0) 最近的 k 个点。距离是欧几里得距离。答案可以按任意顺序返回，并且保证答案唯一（与顺序无关）。

例子：输入 points = [[1, 3], [-2, 2]]，k = 1，输出 [[-2, 2]]。两个点到原点距离的平方分别是 10 和 8，8 更小。

数据范围：1 ≤ k ≤ points.length ≤ 104，-104 ≤ xi, yi ≤ 104，坐标可以是负数。

LeetCode 692 · 前K个高频单词

题意：给定单词列表 words 和整数 k，返回出现次数前 k 多的单词。返回的列表按出现次数从高到低排序；出现次数相同的单词按字典序从小到大排序。进阶要求时间复杂度 O(n log k)。

例子：输入 words = ["i", "love", "leetcode", "i", "love", "coding"]，k = 2，输出 ["i", "love"]。"i" 和 "love" 都出现 2 次，是最多的两个；次数相同，按字典序 "i" 排在前面。

数据范围：1 ≤ words.length ≤ 500，每个单词长度 1～10，只含小写字母；k 在 [1, 不同单词的个数] 之间。

LeetCode 378 · 有序矩阵中第 K 小的元素

题意：给定 n × n 矩阵 matrix，每一行和每一列都按升序排列，返回矩阵中第 k 小的元素（排序后的第 k 小，不是第 k 个不同的元素）。要求内存复杂度优于 O(n2)。

例子：输入 matrix = [[1, 5, 9], [10, 11, 13], [12, 13, 15]]，k = 8，输出 13。全部元素从小到大是 1、5、9、10、11、12、13、13、15，第 8 个是 13。

数据范围：1 ≤ n ≤ 300，-109 ≤ matrix[i][j] ≤ 109，1 ≤ k ≤ n2。

LeetCode 373 · 查找和最小的 K 对数字

题意：给定两个按非递减顺序排列的整数数组 nums1、nums2 和整数 k。一个数对 (u, v) 由 nums1 中的一个元素 u 和 nums2 中的一个元素 v 组成。返回和最小的 k 个数对。

例子：输入 nums1 = [1, 7, 11]，nums2 = [2, 4, 6]，k = 3，输出 [[1, 2], [1, 4], [1, 6]]。和最小的三个数对的和是 3、5、7；其余数对的和至少是 7 + 2 = 9。

数据范围：1 ≤ nums1.length, nums2.length ≤ 105，-109 ≤ 元素 ≤ 109，1 ≤ k ≤ 104，k ≤ nums1.length × nums2.length；数对总数可达 1010，不能全部列出。

LeetCode 480 · 滑动窗口中位数

题意：实现函数 medianSlidingWindow(nums, k)：一个大小为 k 的窗口从数组 nums 的最左端滑到最右端，每次右移一位，返回每个窗口中元素的中位数组成的数组（k 为偶数时中位数是中间两个数的平均值）。与真实值误差在 10-5 以内的答案都算正确。

例子：输入 nums = [1, 3, -1, -3, 5, 3, 6, 7]，k = 3，输出 [1, -1, -1, 3, 5, 6]。例如第一个窗口 [1, 3, -1] 排序后是 -1、1、3，中位数是 1；第二个窗口 [3, -1, -3] 的中位数是 -1。

数据范围：1 ≤ k ≤ nums.length ≤ 105，-231 ≤ nums[i] ≤ 231 − 1。

1. 找最大的 k 个数，为什么用小顶堆而不是大顶堆？ 堆里装的是“目前最大的 k 个”这份名单。新数来了，要和名单里最小的那个比，决定谁被淘汰。小顶堆的堆顶正好是名单里最小的，O(1) 就能看到，O(log k) 就能淘汰。大顶堆的堆顶是名单里最大的，对淘汰没有帮助。
2. 数据流中位数里，为什么加入一个数时要先放进较小一半，再把它的最大值挪到较大一半，而不是直接判断该放哪边？ 直接判断也可以：和较小一半的堆顶比，小于等于就放左边，否则放右边，然后再平衡个数。“先放左边再挪一个过去”的写法不需要分情况，也不用担心堆是空的，三步固定执行，不容易写错。代价只是多做一两次 O(log n) 的堆操作。
3. 合并 K 个链表时，如果改成“依次两两合并”，为什么会慢？有没有不用堆、同样 O(N log k) 的办法？ 依次两两合并时，结果链表越来越长，每合并一次都要把它从头走一遍，最坏 O(N · k)。不用堆的办法是分治：像归并排序一样，先两两配对合并（第 1 和第 2、第 3 和第 4……），再把结果两两合并，一共 log k 轮，每轮所有节点各走一次，也是 O(N log k)。
