第 23 课 · 选修 · KMP 字符串匹配

在文本里找模式串。暴力法一失配就退回去从头比；KMP 记住“刚才已经对上了哪些字符”，失配时文本指针不回头，模式按一张前缀表直接往右跳。

实战里怎么写：直接用 str 和 re

日常代码里没人手写 KMP。Python 的字符串方法和 re 已经够用：

场景用什么代价
有没有pattern in text通常接近 O(n)
第一次出现在哪text.find（找不到 -1）/ text.index（找不到抛 ValueError）同上
出现几次（不重叠）text.countO(n)
所有位置、忽略大小写、一类字符串re.finditer；要重叠的位置用前瞻 (?=...)简单模式约 O(n)
同时找很多关键词拼成一个正则 "|".join(map(re.escape, keywords))扫一遍文本
import re

log = "INFO start\nERROR db timeout\nINFO retry\nERROR db timeout\n"
"ERROR" in log                        # True
log.find("FATAL")                     # -1
log.count("ERROR")                    # 2
[log.count("\n", 0, match.start()) + 1 for match in re.finditer("ERROR", log)]   # 所在行号 [2, 4]
[match.start() for match in re.finditer("(?=ATA)", "ATATATA")]                   # 重叠位置 [0, 2, 4]

完整可运行的版本在 examples/kmp_in_practice.py（uv run examples/kmp_in_practice.py）。CPython 的 str.find 用的是 Boyer-Moore 一类的算法加启发式，平均比 KMP 还快。学 KMP 是为了两件事：最坏情况 O(n + m) 有保证，以及“前缀表”这个思路（很多字符串题都要用到）。

暴力匹配：失配就从头

把模式放在每个起点上，逐个字符比，一不等就右移一格、从模式开头再来：

文本ABABABC
模式ABABC

前 4 个刚比完都相等，暴力法却把它们全扔掉，下一轮又从头比。最坏要 O(n·m)。

前缀表：开头和结尾有多少一样

π[k] = 模式前 k+1 个字符里，开头和结尾相同的最长长度（不能是整段本身）。以 ABABC 为例：

前缀开头 = 结尾π
A（只有一个字符，不算）0
AB没有0
ABAABA1
ABABABAB2
ABABC没有0

KMP 怎么用它跳

上面在 C 处失配时，已经对上的是 ABAB，而 π[3] = 2：它的结尾 AB 正好等于开头 AB。所以把模式右移，让开头的 AB 对准文本里刚比过的 AB，从模式第 2 位接着比，文本指针 i 原地不动：

def find_all(text, pattern):
    """按从小到大产出所有匹配的起点（允许重叠）。"""
    table = prefix_function(pattern)       # 就是上面的 π
    matched = 0                            # 下面的 j：模式已经对上了几个字符
    for position, character in enumerate(text):     # 下面的 i：只往前走
        while matched > 0 and character != pattern[matched]:
            matched = table[matched - 1]   # 失配：查表，模式往右跳
        if character == pattern[matched]:
            matched += 1
        if matched == len(pattern):        # 整个对上了
            yield position - matched + 1
            matched = table[matched - 1]   # 接着找下一个（可能重叠）

def find(text, pattern):
    return next(find_all(text, pattern), -1)   # 和 str.find 一样，找到第一个就停

（这段省略了空模式的处理，见 dsa/kmp.py 顶部的约定。下文和动画里的 i、j 分别对应 position 和 matched。）

算前缀表本身也是同一个套路：拿模式自己和自己匹配。

方法时间额外空间
暴力匹配最坏 O(n·m)O(1)
KMPO(n + m)O(m)，存前缀表

为什么是 O(n + m)：i 从不回退，j 每次往回跳的总量不会超过它往前走的总量。

动手玩

先点 暴力匹配，再点 KMP，看比较次数差多少。KMP 失配那一帧会把用到的 π 格子标亮。也可以试试文本 AAAAAAAAB、模式 AAAB，这是暴力法的最坏情况。

最容易错的地方

  • π[k] 说的是长度，也正好是失配后 j 的新值：j = pi[j - 1]，注意是 j − 1。
  • 失配后要用 while 一直跳，跳到相等或 j = 0 为止，只跳一次不够。
  • 找到一处后别把 j 清零，要 j = pi[j - 1]，否则会漏掉重叠的匹配（"aaaa" 里找 "aa" 应得 [0, 1, 2]）。

练习

补全 dsa/kmp.py。接口和标准库对齐：find ≈ str.find、index ≈ str.index、count ≈ str.count，find_all 是产出所有（可重叠）位置的生成器。测试会拿它们和标准库逐个对比，空模式等边界也照标准库的约定。

建议顺序：naive_find_all → prefix_function → find_all → find → index → count。

uv run dsa/kmp.py               # 在日志里定位错误的端到端例子，逐条打印期望和实际
uv run pytest tests/test_kmp.py

自测

1. AABAAAB 的前缀表是什么？ [0, 1, 0, 1, 2, 2, 3]。比如最后一位：整串开头 AAB 等于结尾 AAB，长 3。
2. KMP 里文本指针为什么可以不回退？ 失配前对上的那段字符我们已经知道是什么（就是模式的前 j 个），前缀表事先算好了“这段的结尾里，哪一截还能当新的开头”，不用再回去看文本。
3. 什么时候暴力法就够用了？ 日常文本里失配往往第一两个字符就发生，暴力法接近 O(n)。Python 的 str.find 用的也不是 KMP。KMP 的价值在于最坏情况有保证，以及前缀表这个思路。
