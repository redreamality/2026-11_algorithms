第 24 课 · 选修 · 平衡树思路（AVL 旋转）

AVL 树就是一棵会自己扶正的二叉搜索树：每插入一个值，沿路往回看，哪里歪了就转一下，树高始终是 O(log n)。

开始前要会：Python —— 继承 MutableMapping（update / items 都是白送的）、@classmethod、生成器（__iter__ 用 yield 中序产出、next(iter(orders))）、X | None 与引号前向引用、sortedcontainers 用法（实战当黑盒）；前面的课 —— 第 11 课 · 二叉搜索树（本课直接在它上面改：退化问题、递归插入改父指针、删除的三种情况都来自那里）、第 5 课 · 递归与分治、第 6 课 · bisect（实战里的对比方案）。

先定义 平衡不变量 旋转母模板 逐题比较 应用场景 看动画 练习与自测

先定义：保持 BST 顺序，同时控制树高

AVL 仍然是一棵二叉搜索树：左子树所有键更小，右子树所有键更大。新增的不变量是每个节点左右子树的高度差不能超过 1；插入后只修复从插入点回到根的路径。

实战里怎么写：sortedcontainers

Python 标准库没有平衡树，业务代码里也没人手写 AVL。需要“边改边保持有序”时：

场景用什么代价
只是偶尔要有序结果dict / list，用时 sorted()每次 O(n log n)
数据基本不变，只查询排好序的 list + bisect查 O(log n)，插入 O(n)
边改边要有序、按排名或范围取sortedcontainers 的 SortedList / SortedDict增删查约 O(log n)
from sortedcontainers import SortedList

ranking = SortedList()                      # 存 (-分数, 玩家)：分高的在前，同分按名字
ranking.add((-90, "alice"))
ranking.add((-75, "bob"))
ranking.remove((-75, "bob"))                # 改分 = 删旧的 + 加新的，都是 O(log n)
ranking.add((-95, "bob"))
ranking.index((-95, "bob")) + 1             # bob 第几名：1
ranking[:3]                                 # 前三名

完整可运行的版本在 examples/avl_in_practice.py（uv run examples/avl_in_practice.py）。下面讲的 AVL 是这类“有序容器”最经典的实现思路：它解决的正是第 11 课 BST 最大的毛病。

问题：BST 会退化成链表

1↘2↘3↘4按顺序插入，树高 = n，查找 O(n)

第 11 课见过：有序插入时 BST 只往一边长。平衡树的目标就是：不管按什么顺序插入，h 都保持在 O(log n)。

平衡因子：左高 − 右高

bf = height(node.left) - height(node.right)

AVL 只要求每个节点的 bf 是 -1、0、1 之一。插入后从新节点往根走，遇到第一个 bf 变成 +2 或 -2 的节点，就在那里旋转。每个节点记着自己的 height，算 bf 是 O(1)。

旋转母模板：换个节点当根，中序不变

右旋（左边太高）：左孩子 x 升上来当根，原来的根 y 降到 x 的右边，x 原来的右子树 B 挂到 y 的左边。

y左 x(A, B)，右 C ⟹ 右旋 ⟹ x左 A，右 y(B, C) 
def update_height(node):
    node.height = 1 + max(height(node.left), height(node.right))

def rotate_right(top):                  # 图里的 y
    new_top = top.left                  # 图里的 x
    top.left = new_top.right            # B 换个爹
    new_top.right = top
    update_height(top)                  # 先更新 y（它现在在下面）
    update_height(new_top)              # 再更新 x
    return new_top                      # 新的子树根

左旋完全对称。旋转只改了几根指针，O(1)，而且 A < x < B < y < C 的大小关系没变。

四种情况：只比较失衡方向和插入方向

失衡节点新值插在怎么转
bf = +2左孩子的左边（LL）对它右旋一次
bf = -2右孩子的右边（RR）对它左旋一次
bf = +2左孩子的右边（LR）先对左孩子左旋，变成 LL，再右旋
bf = -2右孩子的左边（RL）先对右孩子右旋，变成 RR，再左旋

判断方法：看失衡节点“偏重那一侧的孩子”的 bf。和自己同号是一条直线（一次旋转），异号是拐了个弯（两次旋转）。写成代码就是一个 rebalance，插入时回来的路上每个节点都调用一次：

def rebalance(node):
    update_height(node)
    balance_factor = height(node.left) - height(node.right)
    if balance_factor > 1:                               # 左边太高
        if height(node.left.left) < height(node.left.right):
            node.left = rotate_left(node.left)           # LR：先把弯拉直
        return rotate_right(node)
    if balance_factor < -1:                              # 右边太高
        if height(node.right.right) < height(node.right.left):
            node.right = rotate_right(node.right)        # RL
        return rotate_left(node)
    return node

def _insert(self, node, key, value):
    if node is None:
        self._size += 1
        return AVLNode(key, value)
    if key == node.key:
        node.value = value                               # 已有的键只改值
        return node
    if key < node.key:
        node.left = self._insert(node.left, key, value)  # 父亲的指针在这里改过去
    else:
        node.right = self._insert(node.right, key, value)
    return rebalance(node)

应用场景：什么时候用现成的有序容器

上面的 sortedcontainers 示例给出实际选择：偶尔排序用 sorted()，静态数据查询用排序列表加 bisect，需要边修改边保持有序时才考虑有序容器或平衡树。

动手玩

先点 插入 1, 2, 3，看 1 的 bf 变成 -2 后怎么左旋；再点 插入 3, 1, 2，看 LR 情况的两次旋转。最后点 插入 1～7，和第 11 课退化成链表的样子比一比。每个节点上方的小数字是它的 bf。

最容易错的三个地方

  • 旋转后先更新下面那个节点的高度，再更新上面的，顺序反了高度就错。
  • 旋转返回新的子树根，父亲的指针要改过去（用递归 node.left = self._insert(node.left, v) 最省事）。
  • LR / RL 只转一次是不够的：转完还是歪的，只是歪到了另一边。

其它平衡树（了解即可）

红黑树用“红黑颜色”代替精确高度，平衡得松一些，但插入删除时旋转更少，Java 的 TreeMap、C++ 的 std::map 都用它。Python 标准库没有平衡树；第三方的 sortedcontainers 走另一条路：把数据切成很多段有序的小 list，靠二分查找定位，实践中往往比平衡树还快。

自测

1. 插入一个值，最多要旋转几次？ 一次（单旋或双旋）。路上可能有好几个祖先同时失衡，但只要在最低的那个失衡节点转一次，那棵子树的高度就回到插入前，再往上自然都平衡了。
2. 为什么旋转后中序遍历不变？ 旋转前后都满足 A < x < B < y < C，只是谁当根变了，从左到右的顺序一样。
3. 依次插入 1～7，AVL 树长什么样？ 一棵满二叉树：根 4，第二层 2、6，第三层 1、3、5、7，高度 3。
