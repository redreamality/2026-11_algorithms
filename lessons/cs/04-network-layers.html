第 4 课 · 网络分层与 IP

把一份数据从一台电脑送到世界另一头的某个进程，是一件很复杂的事。网络把它拆成五层，每层只管一件事：发送时每层加一个首部，接收时每层拆一个。其中网络层的 IP 地址负责「送到哪台主机」，传输层的端口负责「交给哪个进程」。

开始前要会：第 1 课的进程与 PID（服务器上同时跑着好几个进程，每个有自己的编号），以及进程间通信里那句预告：跨机器通信靠套接字。网络部分从这一课开始，不需要第 2、3 课。

前三课一直待在网店的服务器里面。这一课走出服务器：一位顾客在家里的电脑上打开浏览器，输入 shop.example.com。这条请求要经过顾客家里的路由器、运营商的路由器，最后送到网店服务器上那个叫 shop-server 的进程手里。它一路上是怎么找到方向的？全课就跟着这一条请求走。

本课的路线：网络里有哪些设备 → 为什么分层 → 三种分层模型 → 封装与解封装 → 端口：交给哪个进程 → IPv4 地址 → 子网掩码与计算 → 子网划分 → 分类地址与私有地址 → MAC 与 ARP → 逐跳转发 → ICMP 与 ping → DNS → NAT 与 IPv6 → 动画：一次请求走完全程 → 题单怎么考。

1. 网络里的设备、地址和协议

先认识几个名词，后面一直会用到：

主机：连在网络上、运行应用程序的计算机。顾客的电脑是主机，网店服务器也是主机。
链路：把两个相邻设备连起来的那段通道，例如一根网线、一段光纤、一段 Wi-Fi 无线信号。
局域网：一个家里、一间办公室或一个机房里的小范围网络。同一个局域网里的设备可以直接互相发数据。
交换机：把同一个局域网里的多台设备连在一起，收到数据后转给局域网里正确的那台设备。家用路由器里通常就内置了一个小交换机。
路由器：连接不同网络的设备。它收到发往别的网络的数据，替数据选一条路，转发给下一个路由器。互联网就是由无数个局域网用路由器连成的「网络的网络」。

每台设备要被找到，就得有地址。本课用到两种地址，这里先给出直观的含义，后面分别细讲：

网卡与 MAC 地址：网卡是设备上负责收发网络信号的硬件。每块网卡出厂时刻着一个 48 位的编号，叫 MAC 地址，写成 6 组十六进制数，例如 00:1A:2B:00:00:23。它在同一个局域网里用来认出某台设备（第 10 节）。
IP 地址：给网络上每台主机分配的 32 位地址，写成 192.168.1.23 这种形式。它在整个互联网范围内用来找到某台主机（第 6 节）。路由器连着几个网络，每个连接口（接口）各有一个 IP 地址和一个 MAC 地址。

全课用同一组设备和地址。为了省地方，图里的 MAC 地址只写最后一段，例如「MAC :23」就是 00:1A:2B:00:00:23。

这么多设备要配合，就得事先说好规矩：

协议：通信双方事先约定好的数据格式和处理规则。例如浏览器和网店服务器之间说的是 HTTP 协议：请求要写成什么样、回复要写成什么样，都由它规定。双方遵守同一个协议，才能互相看懂。

2. 为什么要分层

把请求从顾客电脑送到 shop-server 进程，要解决好几个互不相同的问题：

  1. 浏览器想对网店说什么？（「请把首页发给我」）
  2. 到了服务器上，交给哪个进程？（服务器上同时跑着好几个进程）
  3. 跨过好几个网络，怎么找到网店服务器这台主机？
  4. 在一根网线上，怎么把数据送到线对面那台设备？
  5. 0 和 1 怎么变成电信号、光信号或无线电信号？

如果写一个大程序把五件事一起包了，换一种网线就得重写整个程序。网络的做法是分层：一个问题交给一层，每层只用下面一层提供的服务，只为上面一层提供服务。于是换成 Wi-Fi 时只要换最下面两层，浏览器完全不用改。这五个问题正好对应五层模型，从上往下是：

应用层：应用程序（进程）之间要交换什么内容。例如 HTTP 规定浏览器怎么向网店要网页。
传输层：把数据交给对方主机上的哪个进程。靠端口号区分进程（第 5 节）。这一层的协议是 TCP 和 UDP，第 5 课专门讲。
网络层：把数据从源主机跨过很多个网络送到目的主机。靠 IP 地址指明目的地，路由器在这一层选路。
数据链路层（简称链路层）：在一条链路上，把数据从一台设备送到直接相连的下一台设备。靠 MAC 地址指明线对面是谁。
物理层：把 0 和 1 变成线路上的信号发出去，在另一端再还原成 0 和 1。

并不是每台设备都要实现全部五层。路由器只需要知道「下一步往哪送」，用到网络层就够了；交换机只在局域网内转发，用到链路层就够了：

3. 三种分层模型和各层一览

五层模型是教材为了讲课方便用的。考试还会问另外两种：国际标准化组织提出的 OSI 七层模型（理论上很完整，但没有真正普及），和互联网实际在用的 TCP/IP 四层模型。它们的对应关系是：

OSI 多出来的两层：表示层管数据的格式转换、加密和压缩，会话层管通信双方会话的建立、维持和结束。在 TCP/IP 里这些事都由应用程序自己做，所以并进了应用层。

每一层发出去的那份数据有自己的名字，叫这一层的数据单位（正式名称是协议数据单元，PDU）。这张表是考试的重点，最好能背下来：

层负责什么数据单位代表协议代表设备
应用层进程之间交换什么内容报文HTTP、HTTPS、DNS、FTP、SMTP、SSH（主机上的应用程序）
传输层交给哪个进程（端口）报文段（TCP），用户数据报（UDP）TCP、UDP（主机的内核）
网络层跨网络送到哪台主机（IP 地址）、选路分组，也叫 IP 数据报IP、ICMP、ARP路由器
数据链路层在一条链路上送到相邻设备（MAC 地址）帧以太网、Wi-Fi（802.11）、PPP交换机、网桥
物理层比特和信号互相转换比特（网线、光纤、无线电的各种标准）集线器、中继器

两个容易混的点：ARP（第 10 节）在多数教材里归网络层，但它只在一个局域网里用；ICMP（第 12 节）也是网络层协议，ping 就靠它。集线器只会把收到的信号原样转发到所有口，不认识任何地址，所以是物理层设备；交换机认识 MAC 地址，所以是链路层设备。

4. 封装与解封装

分了层，各层之间怎么交接？靠在数据前面贴「标签」：

首部：每一层在上一层交来的数据前面加的一段控制信息，写着这一层需要的东西，例如传输层首部里写端口号，网络层首部里写源 IP 地址和目的 IP 地址。链路层除了首部，还会在末尾加一个尾部，用来检查传输中有没有出错。
封装：发送方从上往下，每过一层就加一层首部。解封装：接收方从下往上，每过一层就拆掉一层首部，读出里面写给本层的信息。

注意一个关键性质：每一层只读、只改写自己那一层的首部，不去看里面装的东西。例如路由器拆到网络层，读的是 IP 首部，根本不关心里面是 HTTP 还是别的。正因为这样，各层才能独立替换。

后面第 11 节会看到：路由器在转发时，会拆掉旧的 MAC 首部、换上新的，但 IP 首部原样保留。这是本课最重要的结论之一，先在这里留个印象。

5. 端口：交给主机上的哪个进程

IP 地址只能把数据送到主机。可是网店服务器上同时跑着好几个进程（第 1 课说过，每个进程有自己的 PID）：处理网页的 shop-server、供管理员远程登录的 sshd、数据库 mysqld……数据到了服务器，该交给谁？

端口：传输层用来区分同一台主机上不同进程的编号，是一个 16 位的整数，范围 0～65535。传输层首部里写着源端口和目的端口。
监听：服务器进程启动时告诉内核「发到某个端口的数据都交给我」。例如 shop-server（PID 1024）监听 443 端口。

反过来，顾客的浏览器也是一个进程，它发请求时，内核会临时给它分配一个没人用的端口当源端口，本课取 50000。服务器回复时把目的端口写成 50000，回复就能找回浏览器。

「IP 地址 + 端口」就能精确定位到网上的某一个进程。第 1 课预告过的套接字（socket），就是操作系统给进程的一个通信端点：进程创建一个套接字，把它绑定到某个 IP 地址和端口上，然后通过它收发数据。本课的这次通信，两端的套接字是 192.168.1.23:50000 和 198.51.100.80:443。

0～1023 叫熟知端口，留给常用服务。下面这些要记住：

6. IPv4 地址：网络号 + 主机号

现在回到网络层，看 IP 地址到底长什么样。目前用得最广的是第 4 版，叫 IPv4（第 6 版见第 14 节）。

IPv4 地址：32 位二进制数。为了好读，每 8 位一段分成 4 段，每段写成十进制（0～255），中间用点隔开，叫点分十进制。
网络号与主机号：IP 地址的前若干位是网络号，表示这台主机在哪个网络里；剩下的位是主机号，表示是这个网络里的哪一台。网络号相同的主机在同一个网络（子网）里，可以通过链路层直接互发；网络号不同，就必须经过路由器。

就像「某某路 12 号」：路名是网络号，门牌号是主机号。邮局送信先按路名找到那条路，再按门牌号找到那一户。路由器也只看网络号来选路，这样路由器不用记住每一台主机，只要记住每个网络往哪走。

问题是：32 位里前多少位算网络号？这要靠下一节的子网掩码来说明。

7. 子网掩码与 CIDR：算网络地址、广播地址、主机数

子网掩码：一个和 IP 地址一样长的 32 位数，前面连续若干个 1，后面全是 0。1 所在的位是网络号，0 所在的位是主机号。也写成点分十进制，例如 255.255.255.0。
CIDR 记法（无分类域间路由）：在 IP 地址后面写「/数字」，数字是掩码里 1 的个数，叫前缀长度。192.168.1.23/24 就是掩码前 24 位为 1，即 255.255.255.0。

有了掩码，就能算出关于这个网络的三样东西。它们都基于一个运算：

按位与（AND）：两个二进制数逐位比较，两位都是 1 结果才是 1，否则是 0。IP 地址和掩码按位与，主机位被 0 「抹掉」，只剩网络号。
网络地址：主机位全 0 的地址，代表这个网络本身，不能分给主机。广播地址：主机位全 1 的地址，发到这里的数据会送给本网络的所有主机，也不能分给主机。

所以主机位有 n 位时，一共有 2n 个地址，去掉网络地址和广播地址这两个：

可用主机数 = 2^n − 2      （n = 32 − 前缀长度）

顾客家里 /24，n = 8，可用 28 − 2 = 254 个：.1 给了路由器内网口，.23 给了顾客电脑。

掩码不是 8 的整数倍时

/24 的边界正好落在两段之间，一眼就能看出来。考试更爱考边界落在某一段中间的情况。还是用网店服务器 198.51.100.80，假设前缀是 /26（第 8 节会看到这个 /26 是怎么来的）：

  1. 写掩码：26 个 1 = 前三段 24 个 1，第 4 段再 2 个 1：11000000 = 128 + 64 = 192。掩码是 255.255.255.192。
  2. 只算第 4 段（前三段掩码全 1，按位与后原样保留 198.51.100）。80 的二进制是 01010000。
  3. 按位与：01010000 AND 11000000 = 01000000 = 64。网络地址 198.51.100.64。
  4. 主机位全 1：第 4 段的后 6 位改成 1，01111111 = 127。广播地址 198.51.100.127。
  5. 主机数：n = 32 − 26 = 6，26 − 2 = 62，即 .65 ～ .126。

口算的捷径：第 4 段的「块大小」= 256 − 192 = 64，网络地址只能是 0、64、128、192 中的一个。80 落在 64～127 这一块里，所以网络地址是 .64，广播地址是这一块的最后一个 .127。

用掩码判断「在不在同一个网络」

顾客电脑要发数据给 198.51.100.80，第一件事就是用自己的掩码判断对方和自己是不是在同一个网络：

  • 自己：192.168.1.23 AND 255.255.255.0 = 192.168.1.0
  • 对方：198.51.100.80 AND 255.255.255.0 = 198.51.100.0

两个网络地址不同，说明服务器不在本网络，不能直接发，要先交给路由器。如果目的地址是家里的另一台设备，例如 192.168.1.50，算出来也是 192.168.1.0，就可以直接发。第 10 节会接着讲「直接发」和「交给路由器」各怎么做。

动手算

输入任意 IP 地址和前缀长度，点「计算」，看它一步步转成二进制、按位与。默认是顾客电脑的地址；试试 198.51.100.80 / 26，和上面的手算对一对。

8. 子网划分

假设网店以后扩张，机房里 198.51.100.0/24 这一段地址要分给四个部门（办公、网站服务器、数据库、备用），每个部门一个独立的网络，互不干扰。这就是子网划分：从主机位里「借」几位出来当子网号，把一个大网络切成几个小网络。

子网：一个大网络切分后得到的每个小网络。借了几位，前缀就变长几位，掩码里就多几个 1。

题目：把 198.51.100.0/24 划成 4 个大小相同的子网，写出每个子网的网络地址、可用地址范围、广播地址。

  1. 借几位：要 4 个子网，借 k 位能分出 2k 个子网，2k ≥ 4，取 k = 2。
  2. 新前缀和掩码：24 + 2 = /26。第 4 段掩码是 11000000 = 192，即 255.255.255.192。
  3. 每个子网多大：主机位剩 8 − 2 = 6 位，每个子网 26 = 64 个地址，可用 64 − 2 = 62 个。
  4. 列出子网：第 4 段从 0 开始，每次加 64：0、64、128、192。每个子网的广播地址 = 下一个子网的网络地址 − 1。
子网网络地址可用地址范围广播地址可用主机数
1 办公198.51.100.0.1 ～ .62198.51.100.6362
2 网站服务器198.51.100.64.65 ～ .126198.51.100.12762
3 数据库198.51.100.128.129 ～ .190198.51.100.19162
4 备用198.51.100.192.193 ～ .254198.51.100.25562

划分以后的代价：原来一个 /24 能用 254 个地址，现在 4 × 62 = 248 个，少了 6 个。因为每个子网都要单独占掉一个网络地址和一个广播地址。

考试还有两种问法，思路一样，只是条件换了：

  • 「至少划出 6 个子网」：2k ≥ 6，k = 3（22 = 4 不够），前缀 /27，每个子网主机位 5 位，可用 25 − 2 = 30 个。子网个数只能是 2 的幂，所以实际得到 8 个。
  • 「每个子网至少容纳 50 台主机」：反过来先定主机位 n，2n − 2 ≥ 50，n = 6（n = 5 只有 30 个），前缀 32 − 6 = /26，于是一个 /24 能分出 22 = 4 个这样的子网。

本课其他地方仍按 198.51.100.0/24 讲（服务器前缀 /24），这一节只是一道练习。

192.168.0.0/16192.168.0.0 ～ 192.168.255.255C 类

顾客电脑的 192.168.1.23 就是私有地址。那它发出去的请求，回复怎么回得来？靠家用路由器做地址转换，第 14 节讲。本课用的 203.0.113.x 和 198.51.100.x 是专门留给文档举例用的公网地址段，代表「互联网上真实可达的地址」。

还有两个特殊地址：0.0.0.0 表示「本机，地址还不确定」（例如刚开机还没分到地址时）；255.255.255.255 是受限广播，发给本局域网的所有主机，路由器不会把它转发出去。

10. MAC 地址与 ARP：在局域网里找到下一台设备

回到顾客电脑。第 7 节它已经算出服务器不在本网络，要先交给路由器。交给哪个路由器？

默认网关：主机发往别的网络的数据，一律先交给的那个路由器接口。顾客电脑的默认网关是家用路由器的内网口 192.168.1.1。电脑联网时，家用路由器会自动告诉它「你的 IP 是 192.168.1.23，掩码 255.255.255.0，网关 192.168.1.1」（这个自动分配地址的协议叫 DHCP，了解即可）。

现在电脑知道下一站是 192.168.1.1。但链路层发帧，帧首部里要写的是对方的 MAC 地址，不是 IP 地址。为什么要两种地址？因为它们管的范围不同：

  • IP 地址是网络层的地址，表示最终要去的主机，一路上不变（第 11 节）。它是按网络分配的，同一网络的主机网络号相同，路由器才能按网络号选路。
  • MAC 地址是链路层的地址，表示这一段链路上的下一台设备，每过一段链路都换。它跟着网卡走，和设备在哪个网络无关，所以没法拿来跨网络选路。

从 IP 地址查出 MAC 地址，靠的是 ARP：

ARP（地址解析协议）：在同一个局域网里，根据 IP 地址查出对应的 MAC 地址。查到的结果存在本机的 ARP 缓存里，过一段时间（通常几分钟）没用就删掉。
单播：发给一台设备。广播：发给本局域网的所有设备，链路层的广播地址是 MAC 全 1，即 FF:FF:FF:FF:FF:FF。

要特别注意 ARP 问的是谁的 MAC：

  • 目的主机在同一网络（例如家里的手机 192.168.1.50）：直接 ARP 问目的主机的 MAC，帧直接发给它。
  • 目的主机不在同一网络（网店服务器）：ARP 问的是默认网关的 MAC。于是这一帧的目的 MAC 是路由器的 :01，而里面 IP 首部的目的地址仍然是服务器的 198.51.100.80。

ARP 的广播出不了局域网（路由器不转发广播），所以顾客电脑永远不可能直接查到网店服务器的 MAC，也不需要查。

11. 逐跳转发：MAC 每跳都换，IP 不变

帧到了家用路由器。路由器怎么决定往哪送？

路由表：路由器里的一张表，每一行写着「去往某个网络的分组，交给哪个下一跳（下一个路由器的 IP 地址），从哪个接口发出去」。如果目的网络就接在路由器自己的某个接口上，叫直连，直接发给目的主机即可。
默认路由：写成 0.0.0.0/0 的一行，前缀长度为 0，能匹配任何地址。表里其他行都对不上时，就走这一行。
最长前缀匹配：一个目的地址可能同时匹配好几行，路由器选前缀最长（掩码里 1 最多，也就是范围最小、最具体）的那一行。

家用路由器和运营商路由器的路由表（只列和本课有关的行）：

路由器目的网络下一跳出口
家用路由器192.168.1.0/24直连内网口
0.0.0.0/0（默认路由）203.0.113.1外网口
运营商路由器203.0.113.0/24直连接家庭一侧
198.51.100.0/24直连接机房一侧
0.0.0.0/0（默认路由）（其他运营商路由器）……

家用路由器收到目的地址 198.51.100.80：它不在 192.168.1.0/24 里，只能走默认路由，交给下一跳 203.0.113.1。运营商路由器收到同一个地址：它同时匹配 198.51.100.0/24（前缀 24）和 0.0.0.0/0（前缀 0），按最长前缀匹配选 /24，从接机房一侧直接发给服务器。

每个路由器做的事都一样，把这一过程叫逐跳转发（一跳 = 经过一段链路到下一台设备）：

  1. 收到帧，目的 MAC 是自己，拆掉 MAC 首部和尾部，拿出里面的分组。
  2. 读 IP 首部的目的地址，查路由表，得到下一跳和出口。
  3. 用 ARP 查出下一跳的 MAC，把分组装进一个新的帧：源 MAC = 自己出口的 MAC，目的 MAC = 下一跳的 MAC，从出口发出。

结论：转发过程中，源和目的 MAC 地址每一跳都变，源和目的 IP 地址不变（唯一的例外是做 NAT 的路由器会改写地址）。IP 首部里只有一个字段每跳都会变：

TTL（生存时间）：IP 首部里的一个计数，发送方设一个初值（常见 64 或 128），每经过一个路由器减 1，减到 0 时路由器丢弃这个分组。这样，万一路由表配错形成环路，分组也不会在网上无限兜圈。

如果中间还有交换机（比如网店机房里服务器先接一台交换机，再接到运营商路由器），交换机只看帧的目的 MAC，决定从哪个口转出去，不改帧的任何内容，所以上图不用为它加一行。这也是「交换机工作在链路层、路由器工作在网络层」的直接体现。

12. ICMP 与 ping：网络层的「回执」

分组在路上被丢了（TTL 减到 0、目的网络不可达……），发送方怎么知道？

ICMP（网际控制报文协议）：网络层用来报告差错和做简单查询的协议。ICMP 报文装在 IP 分组里发送。它不属于传输层，没有端口号。

最常用的两个工具都建立在 ICMP 上：

  • ping：向目标发 ICMP 回显请求，目标收到后回一个 ICMP 回显应答。能收到应答，说明网络层是通的，还能顺便量出往返时间。
  • traceroute（Windows 上叫 tracert）：故意把 TTL 依次设成 1、2、3……TTL = 1 的分组在第 1 个路由器就被丢弃，那个路由器回一个 ICMP 超时报文，于是就知道了第 1 跳是谁；TTL = 2 暴露第 2 跳……一路排出整条路径。
C:\> ping shop.example.com
正在 Ping shop.example.com [198.51.100.80] 具有 32 字节的数据:
来自 198.51.100.80 的回复: 字节=32 时间=12ms TTL=62

回复里的 TTL=62：服务器发出时设为 64，回来经过了运营商路由器和家用路由器两跳，64 − 2 = 62。注意 ping 只能说明网络层通，不能说明 443 端口上的 shop-server 在正常工作；很多服务器出于安全考虑也会直接不回应 ping。

13. DNS：从域名查到 IP 地址

前面一直假设浏览器已经知道 shop.example.com 的 IP。人记名字，网络层只认 IP 地址，中间的翻译就是 DNS：

域名：给主机起的、方便人记的名字，按层级从右往左写：shop.example.com 里，com 是顶级域，example.com 是网店注册的域名，shop 是它下面的一台主机。
DNS（域名系统）：把域名翻译成 IP 地址的应用层协议，由全世界分层部署的 DNS 服务器共同完成。默认使用 UDP 的 53 端口（UDP 不用先建立连接，一问一答，适合这种短查询，第 5 课讲）；回答太长时，或者 DNS 服务器之间同步整批记录时，改用 TCP 53。
  1. ① 顾客电脑问本地 DNS 服务器（一般是运营商提供的，地址也是联网时自动分配的）：shop.example.com 的 IP 是什么？
  2. ②③ 本地 DNS 服务器问根域名服务器，根说：我不知道，com 归顶级域服务器管，你去问它（并给出它的地址）。
  3. ④⑤ 问 com 顶级域服务器，回答：example.com 归它的权威服务器管，去问它。
  4. ⑥⑦ 问 example.com 的权威服务器，这台服务器由网店自己（或它的域名服务商）维护，它知道答案：198.51.100.80。
  5. ⑧ 本地 DNS 服务器把答案交给顾客电脑，并把结果缓存一段时间，下次有人再问就直接回答，不用再跑②～⑦。
递归查询：被问的一方负责查出最终答案再回复。迭代查询：被问的一方只告诉你「下一步去问谁」，由提问方自己接着问。通常主机到本地 DNS 服务器用递归，本地 DNS 服务器到其他 DNS 服务器用迭代。

实际上，在问本地 DNS 服务器之前，顾客电脑还会先查自己的缓存和 hosts 文件（一个手写的「域名 → IP」对照表），查到就不发 DNS 请求了。

14. NAT 与 IPv6

第 9 节留了一个问题：顾客电脑的 192.168.1.23 是私有地址，互联网上的路由器不认它，服务器的回复怎么送回来？

NAT（网络地址转换）：路由器把从内网发出的分组的源 IP 地址（通常连同源端口）改写成自己外网口的公网地址，并把这对对应关系记在 NAT 表里；回复回来时按表把目的地址改回去。连端口一起转换的叫 NAPT，家用路由器做的就是它，平时说的 NAT 一般就指它。

NAT 让一个家庭、一家公司只占一个公网地址，大大缓解了 IPv4 地址不够用的问题。代价是外面的主机没法主动连进内网（NAT 表里没有记录，回来的分组不知道该给谁），而且它破坏了「IP 地址一路不变」的分层原则。

根本的解决办法是换一个地址足够多的版本：

IPv6：新一代网际协议，地址长 128 位（IPv4 是 32 位），写成 8 组、每组 4 个十六进制数字，用冒号隔开，例如 2001:0db8:0000:0000:0000:0000:0000:0080。

IPv6 地址的两条简写规则：① 每组开头的 0 可以省略（0db8 → db8，0080 → 80）；② 连续若干组全 0 可以用 :: 代替，但整个地址里 只能用一次，否则不知道每个 :: 各代表几组。上面的地址简写成 2001:db8::80。环回地址是 ::1。

和 IPv4 相比，考试常问的区别：地址 128 位、多到基本不需要 NAT；首部固定 40 字节、字段更少，路由器处理更快；没有广播，改用多播；ARP 的工作由新的邻居发现协议承担。

自测

1. 某主机 IP 地址为 172.16.45.200，子网掩码为 255.255.240.0。它所在网络的网络地址、广播地址和可用主机数各是多少？ 掩码 240 = 11110000，边界落在第 3 段，前缀是 8 + 8 + 4 = /20。第 1、2 段原样保留 172.16，第 4 段掩码是 0，按位与后为 0。
第 3 段：45 = 00101101，AND 11110000 = 00100000 = 32。网络地址 172.16.32.0。
广播：第 3 段后 4 位改成 1，00101111 = 47，第 4 段全 1 = 255。广播地址 172.16.47.255。
主机位 n = 32 − 20 = 12，可用 212 − 2 = 4094 个。用块大小验证：256 − 240 = 16，第 3 段的网络边界是 0、16、32、48……45 落在 32～47 里。
2. 子网掩码为 255.255.255.192 的网络，最多能分配给多少台主机？ 192 = 11000000，前缀 /26，主机位 6 位。26 − 2 = 62。减 2 是因为主机位全 0 的网络地址和全 1 的广播地址不能分给主机。
3. 把 198.51.100.0/24 划分成至少 6 个子网，子网掩码应该是多少？每个子网最多多少台主机？ 22 = 4 < 6，23 = 8 ≥ 6，所以借 3 位，前缀 /27。第 4 段掩码 11100000 = 224，掩码 255.255.255.224。主机位剩 5 位，每个子网 25 − 2 = 30 台。实际得到 8 个子网：.0、.32、.64…….224。
4. 主机 A 为 192.168.1.23/25，主机 B 为 192.168.1.200/25。A 发给 B 的数据能直接在局域网里送到，还是要经过路由器？ 要经过路由器。/25 的第 4 段掩码是 10000000 = 128。A：23 AND 128 = 0，网络地址 192.168.1.0；B：200 = 11001000，AND 128 = 128，网络地址 192.168.1.128。网络地址不同，不在同一子网，A 会把数据交给自己的默认网关。
5. 下列哪个是私有 IP 地址？A. 172.32.1.1　B. 192.169.1.1　C. 10.20.30.40　D. 11.0.0.1 C。私有地址只有三段：10.0.0.0/8、172.16.0.0 ～ 172.31.255.255、192.168.0.0/16。A 的第二段 32 超出了 16～31；B 是 192.169，不是 192.168；D 是 11 开头，不是 10。
6. 一个 IP 分组从顾客电脑经过运营商路由器转发到网店服务器，下列哪一项在运营商路由器转发前后保持不变？A. 源 MAC 地址　B. 目的 MAC 地址　C. 目的 IP 地址　D. TTL C。路由器拆掉旧帧、按下一跳重新封装，源和目的 MAC 都换成新的；TTL 每过一个路由器减 1；IP 地址表示两端主机，转发时不改。
7. 关于 ARP，下列说法错误的是？A. 用于根据 IP 地址查 MAC 地址　B. ARP 请求以广播方式发送　C. 主机要和外网服务器通信时，用 ARP 直接查服务器的 MAC 地址　D. ARP 查到的结果会缓存一段时间 C 错。ARP 广播出不了局域网，主机发往外网时，查的是默认网关的 MAC，帧先交给网关路由器。
8. ping 命令使用的是哪个协议？它工作在哪一层？DNS 查询默认使用什么传输层协议和端口？ ping 用 ICMP 的回显请求和回显应答，ICMP 属于网络层，装在 IP 分组里，没有端口号。DNS 是应用层协议，查询默认用 UDP 53，因为一问一答很短，不必先建立连接；回答太长或服务器之间同步整批记录时改用 TCP 53。
