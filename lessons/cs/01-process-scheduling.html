第 1 课 · 进程与进程调度

一个 CPU 核同一时刻只能执行一个程序。操作系统让程序轮流上 CPU，轮得足够快，看起来就像在同时运行。「下一个轮到谁」由调度算法决定。

开始前要会：这是本系列第一课，不需要前置知识。只要知道「程序是一份写好的指令清单，CPU 一条条地执行它」就够了。

整个系列用同一个例子：一家小网店。这一课看网店的服务器：服务器上同时跑着「处理订单」「发确认邮件」「查库存」「生成日报」等好几个程序，而 CPU 只有一个核。它们是怎么轮流使用 CPU 的？

本课的路线：程序和进程 → 并发 → 进程的状态 → 切换进程的代价 → 创建进程（fork）→ 调度：挑下一个 → 用什么指标评价 → 各种调度算法 → 线程 → 进程间通信 → 题单怎么考。

1. 程序和进程

先认识几个名词，后面一直会用到：

程序：磁盘上的一个文件，里面是指令和数据，例如网店的 shop-server。它是死的，不运行就什么也不做。
进程：正在运行的程序。同一个程序运行两次，就是两个进程。每个进程有一个编号，叫 PID。
内核：操作系统里最核心的那部分程序，一直待在内存里，权限最高。管理进程、分配内存、操作硬件都由它来做。
寄存器：CPU 内部几个很小、很快的存储格，用来存正在计算的数。其中程序计数器（PC）记着「下一条要执行的指令在哪里」。

进程除了占一块内存（放代码、数据等，第 2 课细讲），内核还会给每个进程建一份档案，叫进程控制块（PCB），记录这个进程的一切：

记住一句话：PCB 是进程存在的唯一标志。内核只认 PCB：创建进程就是建一个 PCB，进程结束就是回收它的 PCB。

2. 并发：一个核怎么「同时」跑好几个进程

CPU 里真正执行指令的部件叫核。一个核同一时刻只能执行一条指令流。网店服务器只有一个核，却同时开着四个进程，办法是轮流：每个进程跑一小会儿（几毫秒），就换下一个。

  • 并发：一段时间内，多个进程都在推进（可以是轮流）。宏观上同时，微观上交替。
  • 并行：同一时刻，多个进程真的在同时执行。必须有多个核。

3. 进程的五种状态

先补一个名词：I/O（输入/输出），指读写磁盘、收发网络数据这类和外部设备打交道的操作。它比 CPU 计算慢成千上万倍。进程要读磁盘时，不能自己去操作硬件，要通过系统调用请内核代办，然后只能干等结果。

干等的时候还占着 CPU 就太浪费了，所以内核会把它挪开，换别人上。于是一个进程一生会在几种状态之间来回切换：

考试最爱问「哪种转换不存在」，看图上的箭头就能答：

  • 阻塞 → 运行：不存在。等的事办完了，也得先回就绪排队，再被调度选中。
  • 就绪 → 阻塞：不存在。要阻塞，得先在运行中发起 I/O 请求；一个没在运行的进程发不出请求。
  • 运行 → 阻塞是进程自己主动发起的（它要等 I/O）；运行 → 就绪是被动的（时间到了，被内核换下）。

5. 进程是怎么创建出来的：fork

在 Linux 里，新进程由已有的进程「复制」出来。系统调用 fork() 把当前进程几乎原样复制一份：代码、数据、打开的文件都一样，PID 不同。原来的叫父进程，复制出来的叫子进程。

最奇特的一点：fork() 调用一次，返回两次。父、子进程都从 fork() 的下一行接着往下跑，靠返回值区分自己是谁：

pid = fork();
if (pid == 0)  { /* 子进程拿到 0 */ }
else if (pid > 0) { /* 父进程拿到子进程的 PID */ }
else           { /* 返回 -1：创建失败 */ }

笔试题常用 C 语言出（Python 在 Linux 上的 os.fork() 规则完全一样）。看这段代码会打印几次 hi：

fork();
fork();
printf("hi\n");

规律：连续执行 n 次 fork()，最后有 2n 个进程，其中新创建的有 2n − 1 个。

6. 调度：从就绪队列里挑一个

处于就绪状态的进程排成一队，叫就绪队列。CPU 一空出来，内核里负责挑人的那段程序，也就是调度器，就从队列里选一个送上 CPU。怎么选，就是调度算法。

按「能不能把正在跑的进程中途换下来」，调度分两类：

  • 非抢占式：进程一旦上了 CPU，就一直跑到结束或自己去等 I/O，别人只能等。
  • 抢占式：内核可以中途把它换下来。靠的是时钟中断：硬件定时器每隔一小段时间打断一次 CPU（这种「硬件打断 CPU，让内核来处理」的机制叫中断），内核借这个机会决定要不要换人。

7. 怎么评价一个调度算法：周转时间和等待时间

笔试里的计算题全部围绕下面几个量。拿一个进程的一生来看：

量公式含义
周转时间完成时刻 − 到达时刻从交上任务到拿到结果，一共过了多久
等待时间周转时间 − 服务时间其中白白排队的时间（本课的进程不做 I/O）
带权周转时间周转时间 ÷ 服务时间≥ 1。越接近 1，说明越没被耽误
响应时间第一次上 CPU 的时刻 − 到达时刻交互程序最在乎：点了按钮多久有反应

8. 经典调度算法

先来先服务（FCFS）

谁先到谁先跑，非抢占。最简单，也最公平，但有一个大毛病：

按 FCFS 算一遍（完成时刻从甘特图上读）：

进程到达服务完成周转 = 完成 − 到达等待 = 周转 − 服务带权周转
P1077701
P22411952.25
P34112878
P454161172.75
平均8.754.753.5

P3 只要跑 1 个单位，却排了 7 个单位，带权周转高达 8。短进程排在长进程后面，被拖累，这叫护航效应。结论：FCFS 对长作业有利，对短作业不利。

短作业优先（SJF）

CPU 空出来时，从就绪队列里挑服务时间最短的，非抢占。看上面第二条甘特图：t = 7 时 P1 跑完，就绪队列里有 P2（4）、P3（1）、P4（4），选 P3；之后 P2、P4 一样长，按先到的来。

平均周转时间降到 8，平均等待时间降到 4。可以证明：所有进程同时到达时，SJF 的平均等待时间最短。代价有两个：

  • 要提前知道每个进程要跑多久，现实里只能估计。
  • 饥饿：如果短进程源源不断地来，长进程就永远轮不到。

最短剩余时间优先（SRTF）

SJF 的抢占版：每当有新进程到达，就比一比它的服务时间和当前进程的剩余时间，新来的更短就抢占。在这组数据上，平均等待时间进一步降到 3（下面动画里可以看到具体过程）。

高响应比优先（HRRN）

SJF 挑进程时只看服务时间，所以短进程不断到来时，长进程会饿死。HRRN 挑进程时多看一个因素：这个进程已经等了多久。规则：CPU 空出来时，给就绪队列里的每个进程算一个响应比，挑最高的；选中的进程一直跑到结束（非抢占）。

响应比 = (已等待时间 + 服务时间) ÷ 服务时间 = 1 + 已等待时间 ÷ 服务时间
已等待时间 = 当前时刻 − 到达时刻

这里的「已等待时间」是到当前时刻为止等了多久，不是第 7 节那个算到完成为止的等待时间。非抢占时，还在就绪队列里的进程从没上过 CPU，所以它就是「当前时刻 − 到达时刻」。

响应比的含义：分子「已等待 + 服务」，正是「如果现在就让它上 CPU，它的周转时间」；再除以服务时间，就是它的带权周转时间。所以，响应比就是「现在开跑的话，这个进程的带权周转时间」。HRRN 每次挑这个值最大的，也就是已经被耽误得最厉害的那个。

从「1 + 已等待时间 ÷ 服务时间」能读出两点：

  • 刚到达时已等待时间为 0，所有进程的响应比都是 1。之后每等 1 个单位，响应比增加 1 ÷ 服务时间：服务时间 1 的进程每单位增加 1，服务时间 4 的只增加 0.25。等得一样久时，服务时间短的响应比高，这一点和 SJF 一致。
  • 长进程的响应比增加得慢，但只要还在等，就一直增加，没有上限；每个新到的短进程却都要从 1 开始。所以长进程的响应比迟早会超过新到的短进程，不会饿死。

在本课的例子上走一遍（数据见第 7 节的表）。t = 0 时就绪队列里只有 P1，P1 跑 0–7。t = 7 时 P1 完成，P2、P3、P4 都已到达：

t = 7到达服务已等待 = 7 − 到达响应比
P2245(5 + 4) ÷ 4 = 2.25
P3413(3 + 1) ÷ 1 = 4　← 选
P4542(2 + 4) ÷ 4 = 1.5

P3 跑 7–8。t = 8 时重新算，P2、P4 都又多等了 1：

t = 8到达服务已等待 = 8 − 到达响应比
P2246(6 + 4) ÷ 4 = 2.5　← 选
P4543(3 + 4) ÷ 4 = 1.75

P2 跑 8–12，最后 P4 跑 12–16。顺序是 P1、P3、P2、P4，和 SJF 完全一样：这组数据里没有长进程被反复插队，看不出两者的差别。

两者的差别出现在饥饿场景里。换一组数据：A 在 0 到达，服务时间 2；长进程 L 在 1 到达，服务时间 4；短进程源源不断，每隔 2 个单位来一个，服务时间都是 2：S1 在 1 到达，S2 在 3 到达，S3 在 5 到达，依此类推。A 先跑 0–2。

CPU 空出来时SJF 的选择HRRN 算出的响应比HRRN 的选择
t = 2S1（2 < 4）L：1 + 1 ÷ 4 = 1.25；S1：1 + 1 ÷ 2 = 1.5S1，跑 2–4
t = 4S2（2 < 4）L：1 + 3 ÷ 4 = 1.75；S2：1 + 1 ÷ 2 = 1.5L，跑 4–8
t = 6、8、10……S3、S4、S5……

SJF 每次 CPU 空出来，队里都有一个服务时间 2 的新进程，L 永远轮不到。HRRN 里，L 在 t = 2 时比 S1 低，但它一直在等、响应比一直在涨，而 S2 是新来的、只等了 1；到 t = 4，L 就超过了 S2，上了 CPU。

优先级调度

每个进程有一个优先级，挑最高的。可以抢占，也可以不抢占。「数字小代表优先级高」还是反过来，每道题会自己约定，读题时要看清楚。它同样会让低优先级进程饥饿，常用解法是老化：等得越久，优先级慢慢调高。

时间片轮转（RR）

就绪队列按先来后到排队，每个进程最多连续跑一个时间片 q，用完还没跑完就回到队尾，抢占式。分时系统、交互系统都靠它，因为每个进程都能很快轮到一次，响应时间短。

q 怎么定是个权衡（这里用上第 4 节的上下文切换）：

  • q 太大：每个进程在一个时间片里就跑完了，退化成 FCFS。
  • q 太小：频繁切换，上下文切换的开销占比太高。

本课动画里有一个细节要注意：同一时刻既有新进程到达，又有进程用完时间片时，新到达的先入队。这是最常见的约定，但个别题目会另作说明。

多级反馈队列

把上面几种的优点拼起来，是很多真实系统的做法：

小结

算法抢占？优点毛病
FCFS否简单、公平短作业被长作业拖累（护航效应）

10. 线程：进程里的多条执行流

网店要同时服务很多顾客。每来一个顾客就开一个进程？太重了：进程之间的内存是互相隔离的，创建一个进程要复制一大堆东西，切换进程还要换掉整套内存信息。

于是有了线程：一个进程内部可以有好几条执行流，它们共用进程的资源，各自只保留「执行到哪了」需要的那一点东西。

进程线程
定位资源分配的基本单位CPU 调度的基本单位
内存各自独立，互不干扰同一进程的线程共享内存
创建、切换开销大小（同一进程内切换不用换内存信息）
一个出错不影响别的进程一个线程非法访问内存，整个进程一起崩

现代操作系统里，第 6～8 节说的「调度进程」实际调度的是线程，道理完全一样。共享内存很方便，但两个线程同时改同一个变量会出错，第 3 课专门讲怎么办。

11. 进程之间怎么通信

进程的内存互相隔离，要交换数据就得借助内核提供的通道。了解每种方式的特点即可：

方式特点
管道（pipe）一端写、一端读的字节流，单向。命令行里的 ls | grep shop 就是它。普通管道只能用于有亲缘关系的进程（例如 fork 出来的父子）
命名管道（FIFO）有文件名的管道，不相关的进程也能用
消息队列内核里的一个信箱，按「一条条消息」收发
共享内存让两个进程看到同一块内存（第 2 课讲怎么做到）。最快，因为数据不用经内核复制；但要自己加锁防止同时修改（第 3 课）
信号量一个计数器，用来协调先后顺序和互斥，本身不传数据（第 3 课）
信号通知某件事发生了，例如按 Ctrl+C 发的 SIGINT、kill -9 发的 SIGKILL
套接字（socket）唯一能跨机器通信的方式，网络部分（第 4～6 课）都建立在它之上

自测

1. A、B、C 三个进程都在 0 时刻到达，服务时间依次是 6、3、1。FCFS 和 SJF 的平均等待时间各是多少？ FCFS 按 A、B、C 顺序跑，等待时间是 0、6、9，平均 5。SJF 按 C、B、A 顺序跑，等待时间是 C 0、B 1、A 4，平均 5/3 ≈ 1.67。这正是「同时到达时 SJF 的平均等待时间最短」的例子。
2. 时间片轮转，q = 2。A 在 0 时刻到达，服务时间 3；B 在 1 时刻到达，服务时间 3。平均等待时间是多少？ 甘特图：A 0–2，B 2–4，A 4–5，B 5–6。t = 2 时 A 用完时间片回到队尾，排在早已到达的 B 后面。A 在 5 完成，周转 5，等待 2；B 在 6 完成，周转 5，等待 2。平均等待 2。
3. 下列哪种状态转换不可能发生？A. 运行→就绪　B. 就绪→运行　C. 阻塞→运行　D. 运行→阻塞 C。等待的事件完成后，进程只能先回到就绪状态，再等调度器选中它。
4. 下面的代码一共打印几行 -？
for (int i = 0; i < 2; i++) { fork(); printf("-\n"); }
 6 行。i = 0 时 fork 出 2 个进程，各打一行（2 行）；i = 1 时 2 个进程各自 fork 变成 4 个，各打一行（4 行）。
进阶：去掉 \n 会变成 8 个。因为 printf 先把字符放进进程内存里的缓冲区，遇到换行或程序结束才真正输出；fork 复制进程时，缓冲区里还没输出的 - 也被一起复制了。
5. 同一进程的多个线程之间，下面哪一项不共享？A. 堆　B. 全局变量　C. 栈　D. 打开的文件 C。栈记录每条执行流自己的函数调用，必须各有一份。
6. 某时刻 CPU 空闲，就绪队列里 A 已等待 6、服务时间 3，B 已等待 3、服务时间 1。按 HRRN 选谁？ A 的响应比 = (6 + 3) / 3 = 3，B 的响应比 = (3 + 1) / 1 = 4，选 B。
7. 时间片轮转的时间片为什么不能设得太小？ 每用完一个时间片就要上下文切换一次，切换本身不干活。时间片越小，切换次数越多，CPU 花在切换上的比例就越高。
